# 市场温度工具 · 总文档

> 个人投资者自用 · 市场温度 / 情绪 / 估值 / 行业拥挤度 / 资金面 聚合看板 + 微信日报
> 配套代码：`market_thermometer.py` · `valuation_jiucai.py` · `industry_crowding.py` · `notify_wechat.py` · `index.html`
> 本文档整合了所有历史分析、技术文档与韭圈儿 Pro 自建评估，是项目唯一说明入口。

---

## 一、项目概述

**目标**：聚合多个平台的市场温度/情绪/估值指标，给出比单一平台更立体的「市场温度」视角，并通过 Web 仪表盘 + 微信日报触达。

**设计原则**（贯穿全部实现）：
1. **不自造温度**：优先用官方/结构化接口，不重复造轮子。
2. **可插拔降级**：每个源是独立 fetcher，单源挂掉只标灰（`stale=true`），绝不阻塞整体。
3. **统一结构**：所有源归一化为 `{source, name, value, label, updated_at, stale, note}`，Web 与微信共用。
4. **脆弱源隔离**：稳定层（公开接口）与脆弱层（App 私有/登录态/逆向）分层，互不污染。
5. **自算层兜底**：对"别人不给/不给全"的维度（估值分位、行业拥挤度）用免费公开数据自算。

**当前形态**：本地 Python 脚本 → 输出统一 JSON → 写 `cache_latest.json` → HTML 仪表盘读取；微信推送（`notify_wechat.py`，PushPlus）已就绪待 token。

## 二、架构与数据流

```
┌──────────────────────────────────────────────────────────┐
│ 输出层：index.html 仪表盘  ·  notify_wechat.py 微信日报     │
└────────────────────────┬─────────────────────────────────┘
                          │ 统一 JSON {items:[...]}
┌────────────────────────┴─────────────────────────────────┐
│ 聚合层：market_thermometer.aggregate()                      │
│   · 并行/顺序拉取各 fetcher → 归一化 → 写 cache_latest.json  │
└────────────────────────┬─────────────────────────────────┘
                          │ 每个源独立 fetcher，单源失败只标灰
┌────────────────────────┴─────────────────────────────────┐
│ 适配层（fetcher）                                           │
│  稳定层：东财 / 集思录（公开接口）                           │
│  脆弱层：且慢(MCP) / 有知有行(SSR) / 韭圈儿(Playwright)      │
│  可选源：富来智投(token) / 行业拥挤度(自算)                  │
│  自算层：valuation_jiucai / industry_crowding               │
└────────────────────────┬─────────────────────────────────┘
                          │ HTTP / MCP / AKShare
┌────────────────────────┴─────────────────────────────────┐
│ 上游：东财 · 且慢 · 韭圈儿 · 集思录 · 有知有行 · legulegu    │
│        · baostock · Tushare · 央行/统计局(CPI/国债)         │
└──────────────────────────────────────────────────────────┘
```

**健壮性机制**：每个 fetcher `try/except` 包裹，异常 → 返回 `stale=true` 占位项；分母（全A 中位 PB）带本地缓存 + 东财实时兜底，`market_pb_series()` 永不抛异常；诊断日志走 stderr，保证 stdout JSON 纯净。

| 8 | **自算·行业拥挤度** | Tushare>baostock>legulegu | ⚠️ 工程闭环；需本机建历史才全行业 | 中 | 中 |

### 各源接入要点

- **东财成交额**：`push2.eastmoney.com`，上证`1.000001`+深证`0.399001`+北证`1.899050` 的 `f48` 求和得全市场成交（亿）。>12000亿=放量，<8000亿=缩量。零凭据零维护。
- **韭圈儿**：原接口返回 AES 密文（逆向脆弱），改为 Playwright 无头渲染 `app.jiucaishuo.com` 读已发布 DOM。每次聚合启动一次 Chromium（每日推送可接受）。恐贪收盘后更新，盘中取最近交易日值。
- **集思录**：`www.jisilu.cn/data/cbnew/cb_list_new/` 免登录。温度代理 `0.5×价格分位 + 0.5×溢价率分位`。未登录 `total=30`（有偏）；会员 cookie 可获全量。
- **且慢**：公开网页已下线，但官方 MCP `stargate.yingmi.com/mcp/sse` 的 `GetLatestQuotations` 可用（内置 key 或 `QIEMAN_API_KEY`）。轻量 MCP-SSE 客户端按 `\n\n` 切事件、拼接多 `data` 行。
- **有知有行**：`youzhiyouxing.cn/thermometer` 服务端渲染，数字直接进 HTML。含「债市温度」「各指数温度」字段（债市温度当前未抓取）。
- **富来智投（指数宝）**：电脑版 `etf.fulaizhitou.com` = 手机版 `tools.fulaizhitou.com`，同源同后端 `api.fulaizhitou.com`、同微信 OAuth。`fetch_fulai()` 只抓**增量**（避开与现有源重叠的温度/恐贪）：`index/money`→资金利率/货基收益、`markets/strong`→板块强弱（越低=轮动越弱）、`out/dlzc`→龙虎榜（路径/参数待确认，暂标灰）。**做成可选源**：不配 `FULAI_TOKEN` 就跳过，不影响主链路。已知成功码为整型 `10000`；`code:20000` 表示未登录、`10001 wrong` 表示路径/参数错误。
- **自算·股债利差**：`利差 = 1/PE − 10Y国债 + 0.3×CPI同比`，今日利差在 2005+ 历史的百分位 = 估值分位。免费数据：沪深300 PE(`stock_index_pe_lg`)、10Y 国债(`bond_zh_us_rate`，9302 行)、CPI(`macro_china_cpi`)。阈值 <30% 低估 / 30–70% 正常 / >70% 高估。复刻"韭菜投资学"思路（其原表为付费图片+OCR，不可结构化抓取，故自算）。
- **自算·行业拥挤度**：`拥挤度 = (行业PB / 全A中位PB) 在 2010-06 起历史的百分位`；倍数越低=相对 A 股越便宜（埋伏），越高=越热门（规避）。三路径自动选优：Tushare(`TUSHARE_TOKEN`)→申万一级 31 行业全覆盖；baostock→申万一级全行业（本机回补 `pbMRQ` 缓存）；legulegu→部分行业（免费但覆盖不均+限流）。分母健壮策略：legulegu 全历史 → 本地缓存 `cache/all_pb.csv` → 东财实时 PB → 全失败才标灰，永不抛异常。注意：统一用 PB 倍数做跨行业可比是简化（各行业"该用哪把尺子"属人工定性，不进自动温度表）。

## 五、统一输出结构（JSON 规范）

`market_thermometer.aggregate()` 返回：

```json
{
  "updated_at": "2026-07-21 15:16:02",
  "items": [
    {
      "source": "东财",
      "name": "全市场成交额(亿)",
      "value": 11842.3,
      "label": "温和",
      "updated_at": "2026-07-21 15:16:02",
      "stale": false,
      "note": "上证4540.1亿 深证6842.5亿 北证459.7亿"
    }
  ]
}
```

| 字段 | 类型 | 含义 |
|---|---|---|
| `source` | str | 数据源名 |
| `name` | str | 指标名（同 source 下唯一） |
| `value` | num\|null | 数值（0–100 类直接为分/度数；成交额单位亿；行业拥挤度=拥挤度%） |
| `label` | str | 文字标签（放量/缩量、极度恐惧…极度贪婪、冷/中/热、低估/正常/高估） |
| `updated_at` | str | 本条更新时间（每条独立，便于发现陈旧） |
| `stale` | bool | 是否不可用（`true`=标灰，前端不计入综合） |
| `note` | str | 口径/明细/异常说明 |

> `index.html` 的 `render(DATA)` 与本结构 1:1 对齐，把 `aggregate()` 的 JSON 注入 `DATA` 即可。

## 九、韭圈儿 Pro 功能自建评估（高价值项规划）

> 评估依据：韭圈儿会员权益页 `app.jiucaishuo.com/pagesF/vip/history_add_equity`、用户中心 `app.jiucaishuo.com/pages/user/index`（已抓取核实）。Pro = 韭圈儿 App 会员，核心价值在"提醒类/持仓穿透类/专业情绪面板类"。
> 仅做需求设计（不写实现代码）。情绪面板/行业恐贪的方法论见第十节。

### 9.1 可行性矩阵（核心）

判定：价值(高/中/低) × 数据可得性(易/中/难/无) × 能否自实现(可/受限/不可) × 难度(低/中/高) × 优先级(P0/P1/P2)。

| 功能 | 价值 | 能否自实现 | 难度 | 优先级 | 关键依赖 |
|---|---|---|---|---|---|
| 回撤提醒（基金/组合回撤越线） | 高 | 可 | 低 | **P0** | akshare 净值；需自选列表 |
| 策略提醒（恐贪/估值阈值触发） | 高 | 可 | 中 | **P0** | 复用恐贪+估值分位 |
| 组合诊断·穿透（行业/估值/恐贪/回撤/集中度） | 高 | 可(部分) | 中 | **P0** | **需用户持仓录入** |
| 基金持仓股票估值（持仓股历史分位） | 高 | 可 | 中 | **P0** | akshare 持仓+股票 PE/PB 分位；需持仓 |
| 行业恐贪策略 | 高 | 可 | 中 | P1 | 复用行业拥挤度 |
| 大小盘 / 成长价值强度 | 中 | 可 | 低 | P1 | 沪深300 vs 中证1000/2000、300成长 vs 300价值 |
| A股情绪面板（9大指标） | 高 | 可(部分) | 中 | P1 | 六子指标已有，补 3 项 |
| 高级基金筛选（回撤/行业占比/抱团率） | 中 | 可(部分) | 中 | P1 | 回撤/行业占比可算；抱团率需持仓汇总 |
| 指数相关性 / 净值下载 / 指数回测 / 恐贪历史叠加 | 中/低 | 可 | 低 | P1–P2 | 多指数净值算相关系数/akshare 导出 |
| 微盘拥挤度 / 相似基金 | 中 | 受限 | 中/高 | P2 | 口径难对齐 / 需大量基金净值库 |
| 全球情绪面板 / 公募行业配比 / 重仓择时胜率 / 定期报告巡检 | 中 | 不可(免费) | 高 | P2 | 各国市值GDP / 全市场持仓汇总 / 持仓变动历史 / PDF+NLP |
| 干货圈 / 课程折扣 | 低 | 不可 | — | — | 内容付费，无自建意义 |

**结论**：P0 四项（回撤提醒、策略提醒、组合诊断、基金持仓估值）全部可自建，是现有温度计能力的延伸；提醒/诊断类需先补**用户持仓录入**前置模块。

### 9.2 P0 高价值功能需求设计

**① 回撤提醒（P0）**
- 输入：自选基金/组合代码 + 阈值（如"当前回撤 > 15%"或"回撤创 N 日新高"）。
- 数据：`fund_open_fund_info_em` / `fund_etf_hist_em` 拿单位净值历史。
- 规则：当前回撤 = (区间净值高点 − 当前净值) / 区间高点；支持"最大回撤"与"创新高以来回撤"。
- 输出：超阈清单（代码、名称、回撤%、阈值、距高点天数）。
- 触发：每日收盘后 → PushPlus 推送（复用 `notify_wechat.py`）。

**② 策略提醒（P0）**
- 首批 4 类可自建策略：恐贪阈值(<10 买入 />90 卖出)、估值分位(<20% 低估 />80% 高估)、回撤(同①)、均线/乖离(二期)。
- 数据：复用恐贪指数、指数估值(`stock_index_pe_lg`)、回撤。
- 输出：命中策略清单 + 信号方向 + 当前值 + 阈值。

**③ 组合诊断·穿透（P0）**
- 输入：**用户持仓**（基金代码+仓位+成本，见 9.3）。
- 四维度：行业占比(映射申万一级，与全市场配比对比)、估值水位(映射持仓股票分位→加权)、情绪暴露(持仓行业恐贪/拥挤度)、风险(回撤/波动率/前十大集中度=抱团率近似/相关性)。
- 输出：一页式诊断报告 + 风险点提示（如"40% 仓位集中在高估行业"）。

**④ 基金持仓股票估值（P0）**
- 数据：`fund_portfolio_hold_em`(前十大持仓) + `stock_a_indicator`/`stock_zh_a_spot`(个股 PE/PB) + 自算历史分位。
- 规则：前十大各自算 PE/PB 历史分位 → 按持仓占比加权 → 基金整体持仓估值分位。
- 输出：估值水位(低估/中性/偏贵/极贵) + 个股分位明细。边界：前十大通常占 40–60%，标注"基于前十大，非全持仓"。

### 9.3 持仓录入前置模块（P0 前置）

- 格式：`holdings.csv` 字段 = `基金代码, 基金名称, 份额, 成本价, 当前市值(可选), 分组(组合/账本名)`。
- 录入：手工维护 CSV（一期）；后续可接代销平台导出（二期，受登录限制）。

## 十、情绪面板 / 行业恐贪方法论（韭圈儿原理）

### 10.1 恐惧贪婪指数 = 六大子指标合成

韭圈儿恐贪(0–100，越低越恐惧)由六个子指标合成：

| 子指标 | 含义 | 方向 | 免费可算？ |
|---|---|---|---|
| 50ETF 期权波动率(iVIX) | 期权市场对未来波动预期 | 波动↑=恐惧 | ✅ 需算 IV |
| 北向累计净额 | 外资态度 | 正偏离=看多 | ⚠️ 实时已停(2024-08 起)，历史可用 |
| 股价强度(创新高占比) | 市场强势 | 占比↑=贪婪 | ✅ 全A行情算 |
| 沪深300 期指升贴水 | 期货对后市看法 | 贴水=看空=恐惧 | ✅ 基差可算 |
| 避险天堂(股债回报差) | 近20日 沪深300回报−国债净价 | 差为负=恐惧 | ✅ 已有股债数据 |
| 杠杆水平(融资买入占比) | 场内借钱热情 | 占比↑=贪婪 | ✅ 融资融券可算 |

> 精确权重/归一化公式是韭圈儿专有资产，无法获知。目标不是 1:1 复刻，而是**免费数据近似复刻**（方向一致，可用于逆向择时），看板标注"近似"。北向实时停更，可用"主力资金净流入"代理并标注。

### 10.2 情绪面板 = 六子指标分项展示

不是新指标，而是把六子指标各自算成 0–100 的"恐/贪"分项并列，解释"综合恐贪 X 是因为期权波动率飙了还是融资杠杆起来了"。数据层与整体恐贪完全复用。

### 10.3 行业恐贪 = 同法套申万一级

各板块恐贪 = 基于当日**涨跌幅、资金流向、换手率、与宽基相关性**加权。即把"股价强度/资金/换手率/β联动"从全市场下沉到申万一级，输出 31 行业恐贪热力图（冷↔热），用于行业轮动/埋伏。韭圈儿 Pro 的"行业恐贪策略"已覆盖黄金/有色/白酒，我们可扩展全申万一级（复用 `industry_crowding.py` 思路）。
