## 2. 指标口径（权威表）

| 指标 | 公式 | 建议窗口 | 出处 |
|---|---|---|---|
| **夏普 Sharpe** | (年化收益 − rf) / 年化波动率 | ≥1 年 | 通用 |
| **卡玛 Calmar** | 年化收益 / \|最大回撤\| | ≥1 年 | 通用 |
| **UI 溃疡指数** | `√( 平均(DD_t²) )`，`DD_t` = 相对历史高点的回撤幅度(%) | ≥1 年 | 张翼轸 |
| **UPI** | 标准式 `(年化收益 − rf) / UI`；**作者使用的简化式 `年化收益 / UI`** | ≥1 年 | 张翼轸 |
| **波回比** | `年化收益率 /（收益波动率 × 最大回撤率）` | ≥1 年 | 莱言维语（自创） |
| **拟涨幅** | 近1月/近3月/近6月/近1年涨幅加权，权重可拖（近1年权重更高）；**用 K 值把不同频率统一到年频**修正跨周期可比性 | 多周期 | 肥常/金牛星空（自创） |
| **拟涨幅2** | 去重叠：`p1=r1`、`p2=(1+r2)/(1+r1)−1`、`p3=(1+r3)/(1+r2)−1`、`p4=(1+r4)/(1+r3)−1`；`(1+0.4p1)(1+0.3p2)(1+0.2p3)(1+0.1p4)−1` | 1 年 | 同上 |
| **胜率** | 上涨期占比（**粒度需定义**：日/周/月/年） | 随粒度 | 通用 |
| **滚动收益率** | 近1月 = **20 交易日**、近6月 = **120**、近一年 = **250** | — | 参考站口径 |

### 口径要点
- **UI 只算下行**：净值持续创新高时 `DD_t = 0`，UI 也为 0；只惩罚"从高点回落"的深度与持续时间。
- **UI 可读作"平均回撤幅度"**：UI = 18 意味着"相当长时间里账户常比前高低约 18%"。
- **UPI 的含义**：长期看，每承担 1 个百分点的"溃疡痛苦"能换多少年化收益；作者认为 >1 才算理想。
- **标准差（夏普分母）的批评**：σ 把曲线上每个点当等价，**不考虑先后顺序**，所以"1 个月暴跌 15% 立刻反弹"与"跌 10% 后盘整 23 个月才收复"可能同 σ，但后者体验更差。
- **最大回撤的批评**：被**最大那一次**支配，其余历次回撤被掩盖，且不计时间。

## 3. 作者的实证结论（选指标的关键情报，比公式更重要）

莱言维语取全市场「股票型 + 混合型（偏股/平衡/灵活/偏债）」五类，剔除指数基金与股票仓位 <60% 的产品、去重份额，**窗口 = 近 1 年**，对各指标前 20 名做横向对比：

| 排名依据 | 近1年平均收益 | 平均波动率 | 与其他指标前20的重叠度 |
|---|---|---|---|
| **UPI** | **230.21%** | **39.81%** | 与卡玛/夏普 **80%**；与天天基金"收益能力" **70%** |
| **拟涨幅** | **249.71%** | 44.58% | 与 UPI/收益/卡玛/夏普 = 70%/75%/75%/65% |
| **UI**（UI 均值 1.47） | 24.99% | 10.01% | — |
| **波回比** | **54.64%** | **14.28%**（UI 均值 1.8） | **与 UPI/拟涨幅/卡玛/夏普 全部 = 0** |

**三条硬结论**：
1. **UPI 存在"高收益绑架"**——分子端太强势，分母被拉成摆设，筛出来的 ≈ 直接按收益排序（与"收益能力"重叠 70%）。
2. **拟涨幅没有解决这个偏置**（收益 249.71%、波动 44.58%）。
3. **波回比是唯一正交的**——与前 20 完全不重叠；且在波动率只比 UI 组高 4% 的前提下收益翻倍。
4. **波回比有尾部爆炸**：债基/货基因分母（σ × MDD）趋 0 会算出极大值，**不能裸取 topN**，需叠加类型/仓位门槛。

## 7. 缺口清单（含两个隐藏坑）

1. **无风险利率 rf 缺失** —— 夏普/UPI 标准式必须。选项：常量配置 / akshare 取国债 / 小表存储。按 `decisions.md` D21 属配置级数据，**不应全量灌表**。
2. **回撤序列缺失** —— UI 需要逐日回撤而非单个最大值。沿用 `compute_max_drawdown` 的 peak 走法加一个纯函数即可，**按需算、不落库**。
3. **⚠️ 隐藏坑：我们没有「股票仓位」数据** —— `equity_position` 是死列（0% 填充、零读者），而回填它的 `fund_meta_job` 是逐只抓取的**限流炸弹**（#1403 / tech-debt §16.2 第 1 条 🔴）。而波回比/UI 的横向排序**必须**剔除债基/货基，否则债基会霸榜（分母趋 0）。
   → **建议用 `fund_type_id` / `fund_variety_id` 做「类型过滤」替代仓位数值**：既够用，又完全避开限流风险，且符合 D21。
4. **⚠️ 隐藏坑：净值跳变未处理** —— 参考站作者**自己承认**没处理大额赎回 / 份额折算造成的净值跳变（债基尤其严重，会出现 99.99% 由大额赎回导致的异常"收益"）。我们的 `acc_nav` 是「分红不再投近似复权」，**同样会被折算污染**。
   → 建议加**单日跳变检测**（|日收益| 超阈值即标 `basis=distorted` 并剔除该点），否则 UI / σ / 夏普全被脏点带偏。**这是我们能做得比参考源更好的地方。**
5. **口径元数据必须随值下发** —— §3.10 要求「存口径元数据，不只存数字」：UI/夏普/波回比必须带 `window` / `as_of` / `sample_size` / `basis`，否则同一列跨基金不可比。现有 `basis/as_of` 模式可直接沿用。
6. **样本分流** —— 成立不足（<250 点）、QDII 净值滞后、货基（无净值口径）要分别标 `basis=insufficient` / `money_fund`，**不要硬算**。

## 11. 边界（明确不做）

- **不做全库指标预计算**——3,419 只 × 多周期 × 多指标落库违反 D21；一律按需算。
