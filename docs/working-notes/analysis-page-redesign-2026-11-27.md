### 4.1 P2a 落地记录（2026-11-27）

- **不新画图，接三块既有面板**：`PositionStructurePanel` / `PenetrationPanel` /
  `StyleDistributionCard` 都**不传作用域 props = 家庭级**，与复盘页 XIRR、清仓周期的
  家庭合并口径一致；三块各自取数、各自降级，一块挂了不带走另两块。
- **`StyleDistributionCard` 从 `views/asset/panorama/components/` 上提到 `components/`**
  （连同 `styleDistributionModel.ts` 与单测）：跨页引用别人的私有目录，下一步一定是
  复制第二份。上提后 panorama 只改了一行 import。
- **与 panorama 的边界按「回答的是不是同一个问题」划**，不是按「有没有图」：
  大类构成（`category_distribution`）与账户/产品类型分组（`getPositionGroups`）仍归
  panorama，#2150 四条判据全绿；本页只放「钱压在哪些品种 / 哪些行业 / 什么风格」。
- **实测（真库，Edge headless，1440）**：结构区高 2449px（持仓结构 8 张卡 + Top5 条、
  穿透覆盖率 90.6% / 未穿透 9.4%、行业分布、风格分布），`pageerror` 0；
  整页由上版 19 268px 收到约 5 700px。1280 下指标卡转 2×2，无横向溢出。
- **代价**：结构区占整页 43%，是当前最长的一块。要压缩只有两条路——两列布局（1440
  单列宽 902px，两列各 430 会把 Top5 条与覆盖率卡挤坏）或默认折叠（站内无折叠区块先例）。
  本期都不做，等用户看到实物再定。

### 4.2 P2b 落地记录（2026-11-27，资金流动家庭级）

- **`scope=family` 显式才能进**：两个 id 都不传仍是 400。原因不是洁癖——「漏传参数就
  静默变成全家数据」比报错更坏（用户会以为自己筛过了）。`scope` 与 id 自洽校验也在
  后端（`scope=family&ledger_id=` 回 400）。
- **家庭级日序列不自己合并**：直接吃 `build_daily_pnl_series(ledger_id=None)`，与家庭级
  XIRR / 收益日历同源。组合级必须 Σ 成员（成员是显式选择的集合），家庭级照抄会多出
  「任一成员缺数据当天整体置缺」，与日历对不上。
- **顺带修掉一个存量 bug**：`build_layers` 默认 `include_cash_equivalents=False`（XIRR 的
  口径），资金流动误用了它 ⇒ `asset_type ∈ {cash, money_fund, reverse_repo}` 的流水被
  整条丢掉。真库实测「微众银行」25.8 万入金 / 14.4 万出金**全部消失**，账户页显示
  「还没有入金记录、净投入按 0」；家庭级更离谱（入金 104 元）。修正后该账户入金 25.85 万 /
  净投入 11.37 万 / 现金残差 +7.1 万（与其实际现金余额对得上）。
- **家庭级不推导现金残差**：残差的前提是「集合里每个账户的入金都记全了」。账户级能靠
  余额自证；家庭合并后同一份真库数据残差 −34.2 万 ⇒ 期末资产 −8.2 万。故家庭级
  `cash_residual / end_asset / total_return` 一律 `null`，卡面第 4 张改报**持仓市值**
  （与净值线末点同源），要看余额去账户页。
- **页面位置**：独立区块放在净值走势之后——曲线的台阶就是入金/出金，放下面才对得上
  「这天为什么抬了一截」。rail 变 7 项。
- **顺带修掉纵向节奏**：`.analysis-main` 此前没有 `gap`，区块间距实测 **0 / −1px**
  （只剩 SectionHeader 自带的 12px），七段挤成一片；补 `flex column + --space-section`
  后统一 48px（与同站其它资产页的 shell 同一条令牌）。结构区三块之间 24px（同一问题的
  三个切面），收进 `AnalysisStructureSection.vue`，页面因此回到 399 行。
- **实测（真库，Edge headless）**：1440/1280 两档 4 张卡与两张图正常、`pageerror` 0、
  `scope=family` 单次请求；家庭级 入金 258 898.60 / 出金 150 163.56 / 净投入 108 735.04 /
  持仓市值 566 749.51。⚠️ 与「收益概览」的当前市值 790 431 相差约 22 万（XIRR 与
  `pnl_calendar` 两个引擎的市值口径差），属既有问题，本 PR 不碰，记在这里待查。

## 5. 是否与「持仓分析」合并（评估）

**结论：应当合并，但以「口径切换器」为前提，且不能一步到位。**

两页现在按**实现**划分，不是按**用户任务**划分：

| 页面 | 实际内容 | 划分依据 |
|---|---|---|
| 投资复盘 `/analysis` | XIRR / 净值曲线 / 清仓周期 | 时间维度（#2150 决策） |
| 持仓分析 `/asset/position-analysis` | 口径切换 + 区间超额 + 日历 + 归因 + 持仓结构 + 穿透 | 「把已实现的分析端点聚到一个入口」（作者原话） |

用户打开「分析」时问的是三类问题：**我现在怎么样 / 我过去经历了什么 / 我的做法对不对**。
现状把"现在"和"过去"拆到两页，而"对不对"（超额）只在一页、"赚了多少"（XIRR）只在另一页——
用户无法预测信息在哪，只能两页来回翻。这是 endpoint-driven IA 的典型症状。

更强的证据来自第 9 条本身：一旦结构图画进复盘页，两页就有**三块重复**（结构 / 穿透 / 归因）。
**当两页开始重复，说明划分维度选错了**——重复不是第 9 条的副作用，是边界的证伪。

反方（必须承认的代价）：

- 复盘页现有 4 区块、持仓分析 6 区块，合并后 9–10 块，一屏装不下 → 需要分区懒加载 +
  目录 rail（已有 `usePageNav`），否则首屏接口从 2 个涨到 10 个；
- 口径切换器目前只在持仓分析，合并后要成为**整页**主控（净值曲线也要支持"只看某账户"），
  这会改动 `useNetWorthTrend` 与 XIRR 的入参；
- 两条路由都有外部书签（`/analysis` 是明写的锚点）→ 合并必须保留旧路径做重定向，
  不能删 URL。

迁移路径（建议）：

1. 先把复盘页补齐到"能和持仓分析对话"（P1 + P2），期间两页重复是有意的过渡态；
2. 再以 `/analysis` 为主页，把持仓分析的四块搬入并把口径切换器提到页头；
3. `/asset/position-analysis` 保留为重定向（带 `?scope=ledger&id=` 时落到对应锚点），
   侧边栏从 5 项减到 4 项。

不建议现在直接合并：合并的最大成本不在搬代码，而在「口径切换器要贯穿全页」和
「9 块内容的首屏取舍」，这两件事没有结论就动手，只会做出一个更长的页面。
