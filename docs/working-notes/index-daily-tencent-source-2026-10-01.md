# 指数日线第二路源（交易所宽基 → 腾讯直连）实证记录

> 日期：2026-10-01 ｜ 关联：#275 / #861 / #870 ｜ 决策：`docs/spec/decisions.md` D44
> 落点：`backend/app/services/sync/jobs/index_daily_job.py`、`backend/app/services/adapters/direct_feeds.py`

## 1. 起因（为什么要第二路源）

`index_daily` 原本只有**万得系**（韭圈儿 `.WI`，10 个目标），而绩效对比最常用的基准
——沪深300 / 中证500 / 创业板指——是**交易所指数**，在该表里**一行都没有**：
`services/market_service.py` 虽然能取到它们，却是每次向 akshare 现拉、**不落库**，
没有历史序列 ⇒ 跨年基准对比无从下手。

附带发现：本机调度**不含** `index_daily`（仅 CI / 手工 `grab.*` 触发），
实测数据停在 **2026-09-08**（截至 2026-10-01 已陈旧 23 天）。

## 3. 代码 ↔ 名称的交叉核对（**不可省的一步**）

腾讯**不返回指数名**，只有数字序列。若名称映射写错，会出现「代码对、名字错」的静默错配
（页面显示「沪深300」实际是中证500 的点位）——**这类错误没有任何自动报警**。
故用**新浪 hq 快照**逐只交叉核对 12/12 名称一致，并核对收盘值：

```
代码        预期名        新浪名          新浪现价     腾讯收
sh000300   沪深300       沪深300        4357.6155   4357.620   ← 逐值吻合
sh000001   上证指数       上证指数        3842.1946   3842.190
sz399006   创业板指       创业板指        3135.277    3135.280
sz399481   企债指数       企债指数         128.157     128.160
sh000012   上证国债指数     国债指数         230.9481    230.948
```

12/12 名称与数值均对上，无错配。

## 4. 实现要点

- **分流按后缀**（不靠查表）：`.WI` → 韭圈儿；`.SH` / `.SZ` → 腾讯。
- **口径新增 `raw`**：腾讯给的是**源侧真实收盘价**，与既有 `anchored`（有锚反推派生）、
  `normalized`（起点归一化 1000）三者并列。`IndexDaily.source` 同步扩为 `jiucaishuo` / `tencent`
  （此前 `_save_data` 把 source **写死**成 `jiucaishuo`，双源后会记错来源）。
- **增量口径**：首页**按 `start_date` 定界**。踩坑记录——首版沿用「固定跨 1400 天」，
  真机实测「近 12 月」变成**一次拉回 800 条≈3.2 年**，与韭圈儿侧的 12 月口径不一致，
  且每次白写数百行 upsert。已加用例钉住。
- **不依赖源侧返回顺序**：分页原用 `rows[0]` 当日「本页最旧日」，即默认源侧升序；
  用例暴露该假设后改为 `min(...)`，顺序变化不再静默退化成「原地打转」。

## 5. 诚实缺口（不明说就会被当成「已覆盖」）

- **中证全债 H11001 无公开行情通道**：腾讯 `sh11001` / `sz11001` 返回空、新浪同样返回空。
  它是债券基金的常用基准，但本次**不造假数据**、也不留「待补」的隐性假设，
  改用 **000012.SH 上证国债指数 + 399481.SZ 企债指数**两段近似覆盖。
- **`index_daily` 目前无读侧消费方**（全 `app/` 只有模型定义与写入侧）⇒ 本次是**补数据底座**，
  为 #861 绩效基准对比铺路，不会立刻改变任何页面。
- `docs/spec/data-refresh-inventory.md` 的刷新清单（停在 2026-09-11）**已整体过期**
  （基金名录 / 净值 / 行情均已恢复调度），本次**不单点修补**——需整表重新实测刷新，另行处理。
