# 组合体系殊途同归实施计划（2026-08-24）

> 关联：D20（`docs/spec/decisions.md`）、`docs/spec/data-model.md` §5.11（目标态设计，本批已重写）、#1081/#1082（已关闭的前置讨论）

## 1. 背景与问题

- 「投资组合」（账户级绑定，XIRR 口径）与「策略视图」（持仓级标签，展示口径）回答同一问题——「我的钱按目的分成几份、每份怎么样」，双轨并行造成概念混淆与认知税。
- 用户场景：支付宝内同时持有债券基金/固收+/权益基金，需分属不同策略组合；账户级绑定无法表达（同账户持仓被迫同组合）。
- 文档与代码存在系统性漂移（本日实证 4 处：AGENTS.md 数据域规则 1、AGENTS.md 分支规则、data-model §5.11 XIRR 口径、#973 勾选框滞后——前两者随本批修正）。

## 2. 目标态（定稿 D20，详见 decisions.md 与 data-model §5.11）

- 组合 = **持仓级**概念：组合成员为持仓（`positions.portfolio_id`，可空，空 = 继承账户「默认组合」）；废除旧约束「不拆分持仓」。
- **三层 XIRR 口径**：持仓（✅ `calculate_position_xirr`）/ 账户 Ledger（✅ performance 域）/ 组合（📦 二期切持仓归因，过渡期组合详情 XIRR 区块隐藏）。
- **策略标签保留**为「风格维度」（成长/价值/大盘），与组合「目的维度」正交；三期评估去留。
- **页面合一**：组合详情吸收策略视图的分组汇总能力。

## 3. 分期实施计划

### 一期：心智与数据统一（🚧 待实施）

**后端**：
- `positions.portfolio_id` 列（nullable FK → portfolios，ON DELETE SET NULL）+ 幂等迁移脚本（照 `migrate_family_id.py` 先例）
- 存量回填：`positions.portfolio_id = 所属账户的 portfolio_id`
- 组合聚合重写：`get_portfolio_holdings` 改按 `positions.portfolio_id` 直接归属（顺带修复按 `account_name` 字符串匹配的断链/串仓隐患）
- 组合详情 XIRR 区块：隐藏或标注「收益口径切换中」（旧账户归因口径不再适用于持仓级成员）
- API：持仓列表/详情携带 `portfolio_id`；持仓组合改派端点（PATCH）

**前端**：
- 组合详情页吸收策略视图的分组汇总能力（按组合分组：持仓只数/总市值/总盈亏卡片 + 明细表）
- 持仓列表加「组合」列 + 改派入口
- 账户编辑弹窗「投资组合」→「默认组合」（语义：新建持仓继承）
- 策略视图页一期保留只读，三期退役重定向

**文档**：data-model §5.11 目标态重写 ✅（本批）；AGENTS.md 分支/数据域修正 ✅（本批）

**验收**：pytest 单进程全绿 + vue-tsc 零错误 + 手工冒烟（组合分组正确、改派生效、存量回填正确、账户改名不再断链）

### 二期：收益口径（📦 待排期）

- 组合 XIRR 切持仓归因：`transactions.position_id → positions.portfolio_id` 联取现金流喂给 `xirr_engine`（引擎现成，改输入口径）
- 归因规则定稿：买入/卖出/分红归持仓；费用随交易；同组合内划转过滤；跨组合划转视为流出+流入
- 组合详情 XIRR 区块恢复展示（新口径），与持仓/账户 XIRR 三层并列

### 三期：概念收尾（📦 待排期）

- 策略标签去留评估（风格维度保留 or 并入组合体系）
- 账户级 `portfolio_id` 退役评估（视「默认组合」实际使用率）

## 4. 迁移与回滚

- **迁移**：幂等 ALTER 脚本只加列不删列；回填 UPDATE 以账户组合为源。
- **回滚**：revert 代码即可——旧读路径（`ledger.portfolio_id`）保留不动，回填数据对旧逻辑无影响；无需回滚数据库结构。

## 5. 概念精简评估（组合簇）

| 概念 | 判定 | 说明 |
|---|---|---|
| Portfolio | **保留，升级** | 持仓级核心概念，目标语义（purpose/target_*/benchmark）唯一载体 |
| StrategyTag / PositionStrategyTag | 保留（正交维度） | 「风格」回答持仓是什么类型，组合「目的」回答为什么而投；三期评估并入 |
| Allocation（五笔钱） | 保留 | 风险等级维度，与目的/风格正交 |
| 账户级组合绑定 | **降级为默认值机制** | 不再是独立心智概念，净概念数减少 |

> 更广的全库模型盘点（~40 表）登记为独立审计项（tech-debt 候选），不在本 feature 范围。

## 6. 页面方案（合一 vs 分开）

**推荐合一**：组合页 = 列表 + 详情（详情内按组合分组持仓 + 汇总卡片，吸收策略视图能力）；策略视图页一期保留只读、三期退役重定向。

理由：概念合一后页面必须合一，否则双入口延续概念税；策略视图的打标交互迁移至持仓明细（组合详情内）。
