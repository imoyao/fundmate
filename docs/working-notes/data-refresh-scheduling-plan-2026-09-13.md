### B. 探市页数据不在任何调度里

`GET /api/market/overview` → `MarketOverviewService.get_overview()`：

- 按需实时取数 + **两级缓存（LRU + 文件，TTL 30 分钟）**，**不落库**（v1 的「重启即冷」已修正，见 F5）；
- 一次请求串行拉 ~12~14 个资产的全历史序列（每个 0.5~4 秒）；
- 无落库 ⇒ **无历史留痕**（做不了「昨天 vs 今天」）、**数据源挂了只能显示占位**、**坏了也没人知道**（F6 正是这样活了很久）；
- 20 个资产里 6 个是**软占位**（海外 4 + 中证2000 + 比特币，`market-explorer.md` §2.2 二轮实测已确证无解）；**14 个可取中 2 个实际是陈旧数据**（F6）。

## 5. 探市页专项（最大一块）

### 5.1 现在怎么跑

```text
前端 GET /api/market/overview
      └─ MarketOverviewService.get_overview()
           └─ 逐资产 → akshare 全历史序列（两级缓存 TTL 30 分钟）
                 · stock_zh_index_daily          （上证 / 沪深300 / 中证500）
                 · stock_hk_index_daily_sina     （恒生 / 恒生科技）
                 · index_us_stock_sina           （标普500 / 纳斯达克）
                 · fund_etf_hist_sina('sh511010')（国债ETF）
                 · stock_us_daily('TLT')         （美债ETF）
                 · futures_main_sina             （沪金 / 沪银 / INE 原油）
                 · currency_boc_sina('美元')      （美元指数 / 离岸（替代））← 陈旧（F6）
                 · bond_zh_us_rate                （中 / 美 10Y 收益率）
```

### 5.2 三个候选方案（**推荐 B 最小版**）

| 方案 | 做法 | 评价 |
|------|------|------|
| A 只预热缓存 | 每日 08:00 调一次 `get_overview()` 让缓存热着 | 改动最小，但 TTL 30 分钟后照样回源；**无历史、损坏不可见**（F6 就是例子）→ **治标，不推荐** |
| **B 每日落库 + 前端读库**（**推荐**） | 每日 08:00 抓一次 → **复用 `market_multi_items` 落库**（F8：schema 够用，不新建表）→ 端点读库；实时取数降为「库空 / 数据过期」兜底 | **治本**：首屏毫秒级、跨进程稳定、有历史留痕、坏数据可见（`stale` + 审计） |
| C B + 盘中补充 | 再在 A股 / 港股收盘后各补一次 | 当日涨跌更准，但一天 3 次 × 12 请求且要处理「同一天两个值」口径 → **先不做** |

**B 方案落库设计（含 v1 未答的四个问题）**：

1. **分位所需历史从哪来？** → **不依赖本库**。每次取数时数据源返回全历史，分位当场现算（实测 12/14 资产 1492~8724 行，远超 500 日）。**因此只落算好的结果**（`change_pct` / `percentile` / `label` / `basis` / `window` / `trade_date` / `data_asof` / `caliber`），**不落收盘序列**（符合 `data-strategy.md`「不存多余数据」）。
2. **6 个软占位怎么落？** → **不入库**。它们是**结构性事实**（源不存在），不是每日数据，应由代码常量 `ASSET_CONFIG` 提供；落库只落真正取到的资产。**当日取数失败**是每日变化的 → 落 `stale=true` + 错误摘要，并**保留上一次成功值**供展示。
3. **保留期？** → **1 年**（与 `market_multi_items` / `market_composites` 既有注释「保留最近 1 年」一致；**与分位窗口无关**，见第 1 点）。约 20 行/天 × 250 交易日 ≈ 5,000 行/年，可忽略。
4. **口径一致性** → 落 `trade_date`（该资产所属交易日）+ `data_asof`（取数时刻），前端「各市场数据截止」文案沿用现有 `as_of_note`，**永不显示笼统的「今日」**。

## 6. 本机常驻可靠性评估（决定「本机扩到几项」的前提）

> 问题来源：本机是否长期开机？休眠 / 断网 / 重启后还准不准？

| 场景 | 当前行为 | 缺口 | 建议 |
|------|---------|------|------|
| **合盖过夜 / 休眠** | APScheduler 线程冻结；唤醒后若距触发时刻 < `misfire_grace_time`（**6 小时**）→ 立即补跑一次（`coalesce`）；超过则跳过 | **>6 小时的过夜休眠会整天不跑** | grace 6h → **24h**（覆盖「晚上休眠、早上开机」；代价是极端情形下凌晨补跑，可接受） |
| **断网** | 单 job 内部重试 3 次（2/4/8s 退避）；仍失败 → 记 `sync_logs` failed | **当天不再重试**，无跨天补偿 | 启动补跑判定从「今天已过点但无成功」**放宽为**「最近一次成功早于上一计划时刻」→ 隔天开机也能补 |
| **重启（白天）** | 启动后 180s 触发补跑，只补「当天已过触发时刻且无成功记录」的任务 | 补跑那次也失败就没了第二次 | 同上一行 |
| **长期不开机** | 全部跳过，下次开机补当天 | — | 可接受（数据源可回溯） |
| **并发双跑** | ✅ 单实例文件锁（内核释放，无 stale 锁） | — | 保持 |
| **失败无人知** | 只有日志（本地窗口一关就没了） | **无告警** | 见 §8-D9；本机至少要有「失败落盘 + 开机自检摘要」 |

**结论**：本机通道**适合「每日新鲜度」**（净值 / 行情 / 快照 / 温度 / 探市），**不适合**承担「错过一次就长期缺口」的重活（元数据回填、逐只类）——那些仍应交给手动 / CI / 服务器。**扩到 6~8 项可行，但需先做上面两处加固（grace + 跨天补跑）。**

## 9. 验收标准与回滚

### 9.1 探市落库（PR2）

| 项 | 验收标准 |
|----|---------|
| 首屏耗时 | 读库路径 **p95 < 300ms**（本地 SQLite；不含网络） |
| 冷启动 | 库空 / 数据过期时回退实时取数，**允许 30s 但必须有 loading 态**，不得白屏 |
| 数据新鲜度 | `data_asof` 每次 08:0x 更新；卡片展示「各市场数据截止」；任一资产 `trade_date` 落后该市场最近收盘日 >1 个交易日 → 标 `stale` |
| 降级 | 单资产失败 → 该行 `stale=true` + 展示上次成功值或 `—`；**整体端点永不 500** |
| 幂等 | 同日重复跑只 upsert 同批行（唯一键）；不产生重复 |
| 保留期 | 1 年滚动清理（复用 `TemperatureService.cleanup_old_data` 模式），清理失败不阻断 |
| 可观测 | `sync_logs` 出现 `market_snapshot` 记录；`pdm run invoke sched.status` 可见 |

### 9.2 回滚策略（通用原则：**新增路径 + 开关，不原地替换**）

| 改动 | 回滚方式 |
|------|---------|
| 探市读库 | 开关 `MARKET_OVERVIEW_SOURCE=live|db`，**合并时默认 `live`（行为不变）**，人工切 `db` 观察 3 天再改默认 → 出问题一条 env 回退 |
| 探市落库 job | `SCHEDULER_MARKET_ENABLED=false` 单独关 |
| `execution_plan` 分组 | 分组只是**新增入口** `run_group(name)`；`--job <name>` 单 job 逃生口**永久保留**；回滚=恢复旧列表 |
| 日历分组 | `calendar` 字段缺省 `none`（不跳过）→ 与旧行为兼容；回滚=置回全局布尔 |
| 可靠性加固（grace） | 纯配置项，改回 6h 即回滚 |
