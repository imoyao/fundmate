## 3. 三类结构性问题（先讲清，后面的表才好读）

### A. `run_all_jobs()` 的 `execution_plan` ≠ 全部 job

已注册 **25** 个 job（`orchestrator._register_jobs`），但 `run_all_jobs` 的计划里只有 **16** 个：

| 在计划内（16） | `stock_list` `fund_list` `fund_detail_enrich` `fund_type` `fund_scale` `fund_position` `fund_manager` `fund_company_backfill` `fund_nav` `price_history` `index_constituents` `index_catalog` `index_daily` `dividend_split` `advisor_portfolio` `asset_snapshot` |
|---|---|
| **在计划外（4）** | **`temperature`** · **`index_valuation`** · **`convertible_bond`** · **`amac_institution`** |

后果：`grab.all` / `pdm run sync --all` / CI 的 `pdm run scheduler` **都不刷新温度计**——只能靠 `pdm run invoke grab.temperature` 或 `--job temperature` 单独跑。这与「温度止步于 2026-08-02」是同一件事的两面。

> **待定**：这 4 个是「有意排除」（成本 / 时序考虑）还是「历史遗漏」？需确认后再动。

### B. 探市页数据不在任何调度里

`GET /api/market/overview` → `MarketOverviewService.get_overview()`：

- **按需实时取数 + 进程内 30 分钟缓存**（`_SERIES_TTL = 1800`），**不落库**；
- 一次请求要串行拉 ~14 个资产的全历史序列（每个 1~4 秒，见 §9 实测），**首个访问者必等**；
- 进程重启（含 `flask run --debug` 的热重载）→ 缓存全冷 → 再次慢；
- 无落库 ⇒ 无历史留痕，做不了「昨天 vs 今天」对比，也做不了「数据源挂了仍显示上次值」；
- 6 个资产是**软占位**（海外 4 个 + 中证2000 + 比特币），是「确证无解」而非「待做」（依据见 `market-explorer.md` §2.2 二轮实测）。

### C. 交易日口径一刀切（A股休市 ≠ 全球休市）

本机调度器现在是「`core/trading_calendar.is_trading_day()` 为假 → 整体跳过」。但各市场日历不同：

| 市场 | 收盘（北京） | 周末 | A股法定假期 |
|------|------------|------|-----------|
| A股 | 15:00 | 休 | 休 |
| 港股 | 16:00 | 休 | 部分照常（港股通休，港股本身部分交易日开市） |
| 美股 | 次日 04:00/05:00（夏/冬令时） | 休 | **照常交易** |
| 商品（国内主力） | 含夜盘，近 24h 连续 | 部分 | 部分 |
| 加密 | 7×24 | 照常 | 照常 |

⇒ **A股放假 7 天，探市页的标普/纳指/美债/黄金会整整停更 7 天**。
需要定：「按资产分组指定跟随哪个市场的日历」还是「海外组按周一~周五（非周末）」。

## 5. 探市页专项（本次讨论的**最大一块**）

### 5.1 现在是怎么跑的

```text
前端 GET /api/market/overview
      └─ MarketOverviewService.get_overview()
           └─ 逐个资产 → akshare 全历史序列（30 分钟进程内缓存）
                 · stock_zh_index_daily          （上证 / 沪深300 / 中证500）
                 · stock_hk_index_daily_sina     （恒生 / 恒生科技）
                 · index_us_stock_sina           （标普500 / 纳斯达克）
                 · fund_etf_hist_sina('sh511010')（国债ETF）
                 · stock_us_daily('TLT')         （美债ETF）
                 · futures_main_sina             （沪金 / 沪银 / INE 原油）
                 · currency_boc_sina('美元')      （美元指数 / 离岸（替代））
                 · bond_zh_us_rate                （中 / 美 10Y 收益率）
```

**特征**：串行、每次几千行、只落内存。

### 5.2 三个候选方案

| 方案 | 做法 | 优点 | 代价 |
|------|------|------|------|
| **A 只预热缓存** | 每日 08:00 调一次 `get_overview()`，让缓存热着 | 改动最小（≈10 行，加一个 job）；首屏不再是冷的 | 仍需页面访问期间反复回源（TTL 到期即冷）；重启即失效；无历史留痕；**治标** |
| **B 每日落库 + 前端读库**（推荐讨论） | 每日 08:00 抓一次 → 落 `market_multi_items`（`item_type` 已支持，**优先复用不建新表**，符合 `data-strategy.md` §4.1）→ 新端点或改造现有端点读库；实时取数降级为「库里没有 / 数据过期」的兜底 | 首屏毫秒级；进程重启不影响；有历史留痕；数据源挂了能显示上次值 | 需定「快照表结构与保留期」；需定「读库优先还是实时优先」 |
| **C B + 盘中补充** | B 之外，再在 A股 / 港股收盘后各补一次当日快照 | 当日涨跌更准 | 一天 3 次 × 14 请求；分位 / 涨跌口径要防「同一天两个值」 |

### 5.3 需要拍板的问题

1. **走 A 还是 B**（若 B：是否新建表，还是复用 `market_multi_items`）？
2. 落库后**前端读库还是读实时**？是否保留 `?force=true` 实时刷新？
3. **保真度**：分位（500 日）需要长历史序列，只有「当日快照」不够算分位 ⇒ 需要**同时**落「收盘价序列」或「算好的分位值」。倾向：**只落算好的结果（涨跌幅 + 分位 + trade_date + data_asof）**，序列不落（符合 `data-strategy.md`「不存多余数据」）。
4. 保留期：快照留多久（90 天 / 1 年 / 永久）？

## 6. 频率与时间点：建议的一条时间线（待确认）

| 时点（北京） | 任务 | 理由 |

| **08:00** | 探市 20 资产快照（含海外） | 美股 04:00/05:00 收盘 + 商品「08:00 快照」口径（`market-explorer.md` §3.2 已定） |

| **22:15** | 资产快照 | 必须在净值 / 行情之后（现 CI 版也是放最后） |

补充口径：

- **交易日**：A股组跟随 `trading_calendar`；**海外组跟随「周一~周五」**（§3-C）；商品 / 加密组怎么办需要定。
- **抖动**：沿用 `SYNC_JITTER_SECONDS`（#1400）。
- **补跑**：沿用现有「当天已过触发时刻但无成功记录 → 启动补跑」。
