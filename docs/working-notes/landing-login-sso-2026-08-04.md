## 一、核心结论

- 静态落地页**只做跳板**：导航栏右上角放「登录」「免费开始」两个按钮，均为跳转链接，指向工具站 `/app/login` 与 `/app/signup`。
- 落地页**不处理任何认证逻辑**：不验证 token、不读 cookie、不管 localStorage。点击即走，完事。
- MVP **不做 SSO**。只需要「同一用户体系」（落地页与工具站共用 Supabase 用户表），不需要单点登录（OAuth / CAS 跨站自动登录）。
- 落地页与工具站**不共享登录状态**。落地页只负责展示与引流。

## 二、概念区分（关键设计决策）

| 概念 | 是什么 | MVP 需要吗 |
|---|---|---|
| 同一用户体系 | 落地页和工具站共用同一个 Supabase 用户表 | ✅ 需要（基础） |
| 单点登录（SSO） | 一处登录，其他站点自动登录（OAuth / CAS 等） | ❌ 不需要（企业级） |

## 三、如何让落地页「不割裂」（体验完整性，可选）

- **方案一（MVP 首选）**：不做任何状态同步。用户从工具站回到落地页时，右上角仍显示「登录/注册」。这种「微小割裂」在 SaaS 中极常见（如访问 Notion 官网，页脚不会显示你已登录），用户不会困惑。
- **方案二（可选，稍重但不复杂）**：工具站登录成功后把登录态写入 cookie（域名 `.duoduobei.com`）；落地页加载时读 cookie，有则显示「已登录 · 进入应用」。纯前端判断，无后端逻辑。

## 四、具体实现

| 页面 | 登录相关功能 | 实现方式 |
|---|---|---|
| 落地页（静态） | 「登录」→ /app/login；「免费开始」→ /app/signup | 纯静态 HTML，无认证逻辑 |
| 工具站（前后端分离） | 登录/注册表单、Session 管理、退出登录 | 完整认证，Supabase Auth |

落地页唯一「身份感知」：有 cookie/token → 显示「已登录」；无 → 显示「登录/注册」。一行前端判断，无状态管理、无 API 请求。

## 五、MVP 边界（明确不做）

- ❌ 单点登录（SSO）
- ❌ 跨站点自动登录
- ❌ 复杂 token 交换
- 落地页保持纯静态；工具站做完整认证。这已足够。

## 六、后续动作（最小第一步）

1. 落地页 CTA 链接指向真实 `/app/login`、`/app/signup`（替换占位）。
2. （可选）工具站登录后写 `.duoduobei.com` cookie；落地页加一行读 cookie 显示「已登录」。
3. 与 `brand-guide.md` 一致：落地页不碰任何用户数据，只引流。
