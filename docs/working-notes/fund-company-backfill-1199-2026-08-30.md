# 基金公司 code 回填实测与归一化增强（#1199，2026-08-30）

## 背景

**#1199** 承接 #1168（PR #1190）的范围外遗留：

- PR #1190 已落地「东财适配器接入 + 去硬编码选源 + 基金公司 code 回填」，但仅回填 `code`，**未做实 backfill 命中率**、也未对 `fund_companies.full_name` / `scale` 给结论，两项目处于悬空。
- `fund_companies` 表 127 行在历史数据期全部是 `code == name` 占位（akshare 只给名不给 code），新写入已走真值 code，但存量占位从未回填。

本卡目标：实测 backfill 命中率并留档、评估归一化规则、对 `full_name` / `scale` 给明确结论。

## 实测过程与结果

### 1. 占位基线

`scripts/backfill_fund_company_codes.py` 作用于 `fund_companies` 表 `code == name` 的占位行。实测本地市场库共 **127 行，且 127 行全部为占位**（命中率基线 0）。

### 2. 归一化增强（迭代剥离 + 去属地括号）

原 `company_resolver._normalize_company_name` 只剥「最长一层」后缀，且后缀元组顺序使 `有限公司` 先于 `股份有限公司` 被匹配，导致 `银华基金管理股份有限公司` 只剥成 `银华基金`，而天天基金列表简称归一化后是 `银华`，差一级对不上。

修复（`app/services/sync/company_resolver.py`）：

- 每轮迭代选**最长**可剥后缀，反复剥到不再变化（`股份有限公司` + `证券` 等组合后缀逐级剥离）；
- 先去掉 `（中国）` / `(中国)` 属地括号，避免其阻断后缀剥离（摩根士丹利、摩根由此命中）。

### 3. 命中率提升

| 阶段 | 命中 | 占位 | 命中率 |
|---|---|---|---|
| 增强前（原单次剥离） | 103 | 127 | 81.1% |
| 增强后（迭代剥离 + 括号） | 118 | 127 | 92.9% |

增强多命中 15 家（银华、南方、建信、安信、中邮创业、汇添富、新华、东海、东方、中科沃土、新疆前海联合、长信、浦银安盛、汇安、摩根士丹利/摩根）。

### 4. `--apply` 真实回填

执行 `pdm run python scripts/backfill_fund_company_codes.py --apply`：

- **实际回填 116 条**（118 命中中，2 条因真值 code 已被同名行占用而冲突跳过）；
- **剩余 11 条占位**未回填，分类如下。

剩余 11 条：

- 无匹配（9 条，不在天天基金 `jjjz_gs.js` 基金公司列表，含 4 家真基金管理人 + 证券/资管子公司）：`中邮创业基金管理股份有限公司`、`中科沃土基金管理有限公司`、`新疆前海联合基金管理有限公司`、`浦银安盛基金管理有限公司`、`上海国泰海通证券资产管理有限公司`、`上海东方证券资产管理有限公司`、`浙江浙商证券资产管理有限公司`、`中银国际证券股份有限公司`、`中国人保资产管理有限公司`；
- code 冲突（2 条，归一化命中的真值 code 已被占用）：`招商证券资产管理有限公司` → 国都证券 code `80431710` 已被占；`财通证券资产管理有限公司` → 中信证券 code `80161341` 已被占。

实际回填率 116/127 = 91.3%。backfill 幂等，重跑仅处理剩余占位、不产生新变更。

## full_name / scale 结论（正式降级）

`fund_companies` 有 `full_name`（全称）、`scale`（管理规模）两列，但**没有任何已接入数据源能提供**：

- 东财 `jjjz_gs.js` 仅给 `code` + 简称；
- akshare 给基金管理人全称但不给公司 `full_name` 字段、也不给 `scale`；
- 当前无任何业务逻辑依赖 `full_name` / `scale`（仅模型字段）。

结论：**正式从 #1168 范围降级剔除**，不在 #1199 补齐。承接方为后续独立的「基金公司主数据 enrichment」任务（需新增适配器抓东财基金公司详情页或 akshare 基金公司资料），届时再回填；当前降级不影响任何功能。
