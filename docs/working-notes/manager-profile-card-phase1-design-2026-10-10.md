### 1.1 根因（真 bug，本卡修）

`backend/app/services/sync/jobs/fund_manager_job.py:117`：

```python
rec = {'mgr_code': item['mgr_code'], 'name': item['name']}   # ← 只写两个字段
```

### 1.3 三个必须写进实现的坑

1. **`jjjl` / `manager` 页面是 UTF-8，不是 GBK。** 用 `r.content.decode('utf-8')`；
   按 `apparent_encoding` 判成 gbk 会把「历任」「张坤」全解成乱码，
   进而**误判为「该基金无经理数据」**。这是本轮探测阶段真实踩过的坑。
2. **`ak.fund_manager_em()` 偶发 `ChunkedEncodingError(IncompleteRead)`**（36468 行）。
   现有 `akshare_adapter` 的有限重试方向正确，补抓时沿用，勿改成无限重试。
3. **同一人多行的规模 / 回报三列完全相同**（张坤 3 行全为 307.94 / 297.54）。
   落库必须按 `mgr_code` 聚合去重后写`managers` 单行；
   **禁止**直接灌进 `fund_managers`（会造成同经理每只基金一行重复同值）。

## 3. 转换层（本卡的核心设计决定）

**存储保真原始值，展示层统一换算，换算逻辑单点收口在服务层。**

### 3.1 原则

- **库内存原始单位**：从业时间存天数（东财原值 5125），前端**永远拿不到** 5125 这个数。
- **转换层落在 `services/manager_profile.py`**（唯一出口），不在前端、不在视图层。
- 每个转换后的值**必须附带口径元数据**，让「14 年又 15 天」能被追问来源
  （呼应 `services/fund_metrics.py` 既有做法：只给数字不给口径是不合格的）。

### 3.2 换算约定

| 原始值 | 展示 | 口径元数据 |
|---|---|---|
| `5125`（天） | `14 年又 15 天` | `basis: 'em_days'`, `raw: 5125` |
| `307.94`（亿） | `307.94 亿元` | `basis: 'em_yi'`, `raw: 307.94` |
| `43.59`（%） | `+43.59%` | `basis: 'em_tenure'`, `raw: 43.59` |
| 回撤 | `-18.52%` + 峰谷日期 | 复用 `MaxDrawdownResult`（已有 `peak_date`/`trough_date`/`sample_size`/`as_of`） |

> **涨跌色由前端按语义变量渲染**（`--color-rise` / `--color-fall`，红涨绿跌），
> 服务层**不返回颜色**，只返回带符号的数值。

### 3.3 「至今」的口径

`end_date` 为 `null` 表示仍在任。展示为「至今」而非 `—`，
并由 `is_active` 布尔位承载，**不靠前端比对 `null`**。

## 4. 实现路径

### 4.1 写入侧（唯一的库变更，零迁移）

**模型列全部已存在**（`Manager.appointment_date` / `sum_scale` / `best_return`；
`FundManager.start_date` / `end_date`），因此**不需要迁移、不动表结构**。

改三处：

1. `akshare_adapter._filter_managers`：把三列透传进返回 dict
   ```python
   'sum_scale'     -> float(row['现任基金资产总规模'])
   'best_return'   -> float(row['现任基金最佳回报'])
   'tenure_days'   -> float(row['累计从业时间'])   # 仅溯源用，不落库（见下）
   ```
2. `fund_manager_job._derive_appointment_date`：**由 `tenure_days` 反推首次任职日**
   写入 `managers.appointment_date`。
3. `fund_manager_job._backfill_manager_profile`：把三列回填到**已存在**的经理行。

**规模聚合去重**：同一 `mgr_code` 多行规模相同 → 写前按 `mgr_code` 聚合取首个非空值。

#### 4.1.1 `tenure_days` 的口径与处置（原方案已推翻，实测后重写）

**⚠️ 原方案「用 `min(start_date)` 推算从业年限、`appointment_date` 留空」是错的。**

理由一：`managers` 表**没有 `tenure_days` 列**，原方案下该字段是悬空死代码。

理由二（更关键）：`min(start_date)` 只覆盖**本库关联基金**，
会漏掉张坤 2012 年就管过、但不在本库关联里的老基金 → **从业年限系统性偏低**。

理由三：**语义混淆**。经理级「首次任职」（职业起点）与基金级「任职起始」
不是一回事，而 `min(start_date)` 恰好把后者当前者用，混用会造出假数据。

#### 4.1.2 实测：存日期而非天数（本轮定稿）

「累计从业时间」是**相对抓取日的滚动值**：今天 5125、明年同一份数据 5190。

| 存法 | 问题 |
|---|---|
| 存**天数** | 运行时 `today − days` 反推 → 起始日**每次同步都漂移**，且无法复核（不知哪天算的） |
| 存**日期** ✅ | 首次任职日是已发生的客观事实，**一次写入即终局**；展示时年数随今天自然增长 |

**实测校准**（2026-10-10）：`5125` → `2026-10-10 − 5125 = 2012-09-28`，
与天天基金 F10 实测的 110011「任职起始日 2012-09-28」**逐日相同** → 两者同源。

**全量验证**：36468 行 / 4358 位经理，**反推成功 4358、失败 0**，
分布健康（`min=1`、`max=8145`、中位 1603，无 0/负值脏数据）。
最老的杨建华（长城）起于 2004-06-22、过钧（博时）2004-08-19，均与公募史吻合。

> **⚠️ 精度边界：反推值是「误差 ≤1 天」的估计，不是精确到日的首次任职日。**
>
> 基准日取 `date.today()`，而东财该字段的**统计截止日未知**（T 日或 T-1）。
> 实测：2026-10-10 跑得 `2012-09-28`（与 F10 一致），**2026-10-11 再跑同一份数据
> 得 `2012-09-29`** —— 跨零点导致，非数据源变化。
>
> 结论：可对用户宣称「约 2012 年起任该职位」，**不可宣称「精确到日」**。
> 年化口径（从业 N 年）不受影响，1 天远小于年化精度需求。
>
> 要精确到日只有两条路（本期均不做）：① 抓东财**经理主页**「上任日期」（每人一次请求）；
> ② 用库内最早任期起始日交叉校正（但会漏掉不在库关联的老基金）。

#### 4.1.3 口径：公转私 / 断档**不另算**，按首次任职起算

同一组实测顺带回答了「公转私、中断怎么算」：

张坤 001373 于 2021-02-11 **卸任**，而反推值仍精确命中 110011 的 2012-09-28 ——
**说明空档天数未被扣除**，即该字段是**日历跨度**而非「累计在任年数」。

故采纳「从从业第一天起算」：断档不扣减、不分段。
分段需要私募任职史，公开接口给不出，**分段就成了编造**。
该结论记入 `basis` 元数据（`em_days_derived`），前端可见。

#### 4.1.4 存量回填是必需的，不是优化

`bulk_insert_if_not_exists` 语义是**只插不更新**，冲突即跳过。
生产库 `managers` 已有 **4267 行**，只补插入逻辑的话这三列永远停在 0%
—— 等于把 #1970 的原始 bug 在旧库上**原样保留**。
故必须有 `_backfill_manager_profile`，且**只补 NULL、不覆盖已有值**
（数据源口径可能修正，无条件覆盖会让历史值被静默改写、无法追溯）。

### 4.2 读取侧：逐基金任期回报与回撤**不入库**

「任期回报 43.59%」jjjl 直接给，但**不新增列**——
`fund_managers` 加列需迁移，而 `daily_worth` 已有完整净值序列：

- 任期回报 = `daily_worth` 在 `[start_date, now]` 区间的累计净值涨幅
- 最大回撤 = 复用 `services/fund_metrics.compute_max_drawdown`

好处：**零迁移**，且与基金详情页的回撤**口径完全一致**（同一个函数，不会出现两个口径）。
jjjl 给的 43.59% 只用作**交叉校验**，偏差超阈值时告警，不直接展示。

> 这条遵循 `AGENTS.md` 数据策略「按需存、禁止全量堆砌」。

### 4.3 端点

| 端点 | 状态 | 说明 |
|---|---|---|
| `GET /api/products/manager-profile/` | **已扩展出参** | 加展示档 `tenure_display` / `scale_display` / `best_return_display`；`funds[]` 加 `is_active` 与逐基金 `tenure_display`；头部加 `company_full_name` / `company_scale` / `active_fund_count` |
| `GET /api/products/manager-holdings/` | **已新增** | 代表作前十大重仓（读`fund_holdings`） |

两者都遵守 #1970 定的规矩：**入参用 `mgr_code` 不用姓名**（库内 119 组重名），
且共用同一个 `ManagerProfileRequest`（入参完全相同，不另造 schema）。

**为什么重仓要单独开端点**：重仓按 `fund_code` 查最新报告期，是独立重查询；
而经理区块首屏并不总需要它（无关联基金/ 未到披露期时为空态）。拆开后前端并发取，
档案可先渲染，重仓慢也不拖累整个区块。

**代表作怎么选**（`manager_holdings._pick_representative_fund`）：
`is_classic=True` 优先 → 否则取**任职最早**那只（任期最长 = 策略延续最久）。
**绝不取规模最大**——规模指标已在头部展示，用它挑代表作会让用户误以为是同一个数。
两个易错点已写进代码注释：① 必须 `min` 不是 `max`（最早 = 任期最长）；
② 必须先剔除 `start_date` 为空的行（库内任期只对目标池回填，大量行为空）。

**口径与`penetration` 严格一致**，不自造第二套：同报告期 `full` 与 `top10` 并存时
**优先 `full`**，无 `full` 才用 `top10` 并据此打标。`basis_label` 必须下发给前端——
用户看到「十大重仓」时需要知道这是季报口径（前十���）还是半年报全量，
否则会把「只披露了 10 只」误读成「只买了 10 只」。

## 6. 头像：本期不做，下期做（有实测结论支撑）

用户拍板下期做，此处记录**已验证的可行性结论**，避免下期重新调研：

### 6.1 命名规律

```plain
https://pdf.dfcfw.com/pdf/H8_{manager_id}_1.{JPG|PNG}
```

`manager_id` 即 jjjl 页面里的 `fund.eastmoney.com/manager/(\d+)\.html`。

### 6.2 防盗链是硬阻断（**不是跨域问题**）

| Referer | 结果 |
|---|---|
| `https://duoduobei.com/` | **567** · 7352B `text/html` 拦截页 |
| `http://localhost:8848/` | **567** |
| `https://example.com/page` | **567** |
| **不带 Referer** | **200** · 40341B `image/png** ✅ |

- 服务器确实返回 `Access-Control-Allow-Origin: *`，但**`<img src>` 本就不走 CORS 校验**，
  跨域不是矛盾所在。
- 真正的阻断是「Referer 存在即 567」，而浏览器**必然自动携带 Referer**，前端无法省略。
  故「前端直连」是死路，**死因是防盗链而非跨域**。
- **后端代理可行**：`requests` 默认不发 Referer，实测连测 3 次稳定 200；
  本仓 `core/requests_patch`（东财 impersonate chrome）实测**不注入 Referer**，不冲突。

### 6.3 覆盖率 80%

20 位经理随机抽样：**有照片 16 / 无照片 4**。无照片者 `src` 为
`//j5.dfcfw.com/avatar/nopic.gif`。**张坤本人也是 `nopic`** ——
故下期实现必须做「取不到则降级 DiceBear」，不能假设有照片。

### 6.4 下期建议形态

`GET /api/products/manager-avatar/<mgr_code>`：内部解析 manager_id → 代理 H8 URL →
**本地缓存**（约 20KB/张，全库 4358 人上限约 85MB；命中缓存则零外部流量）。
检测到 `nopic` 返 404，前端降级 DiceBear。

## 7. 风险与边界

| 风险 | 缓解 |
|---|---|
| 全量补抓 4358 位经理的 tenure 需逐基金请求 jjjl（≈ 26000+ 次） | **不做全量回填**。按需：用户打开哪位经理才解析哪几只基金的 jjjl，结果进缓存 |
