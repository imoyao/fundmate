# 账户绑定类现金产品（「余额宝」）设计（2026-08-29）

> ⚠️ 分类口径（货基 / 逆回购算现金还是投资）已统一至 `docs/working-notes/cash-equivalent-classification-design-2026-09-07.md`；本文仅保留「账本绑定 / 自动申购」特性设计（§4–§9），分类相关决策以实时文档为准。

> 关联 issue：<https://github.com/imoyao/fundmate/issues/1137>（A / B / C 三块）
> 设计规范：`frontend/design.md`
> 前置：A（卖出回款不再自动划转至绑定现金账户）已落地；C（新增「现金管理」大类）已取消

## 1. 背景

用户在证券 / 基金账户卖出后，资金应留在**投资账户内**（账户现金，或账户绑定的类现金产品），
而银证转账、货基赎回到银行卡都是**用户显式发起**的操作，系统不应代劳（A 已修复）。

A 解决了「钱不该自动流出投资账户」，但没解决「钱在账户里怎么归类、怎么管理」。
用户在天天基金等平台卖出后，钱实际进入账户现金或默认绑定的货币基金（余额宝概念）。
本设计（B）补上这层：**账户可绑定一个类现金产品，用户可开关自动申购，类现金在统计中单独显示。**

### 与 C 的关系（C 已取消）

原计划新增「现金管理」资产大类，已取消，理由：

1. **滑坡问题**：单独提出货基，那债券基金、混合型是否也该提出？分类会无限细分。
2. **维度混淆（根本原因）**：「类现金」是**流动性 / 用途属性**，不是**产品类型属性**。
   把用途属性塞进产品分类维度，迟早出现第二个、第三个「特殊大类」。

系统里已有正确承载位置，且都是用途 / 风险口径、与产品类型正交，证明类现金应走用途维度：

- 收益口径：`backend/app/services/performance/constants.py:9`
  `EXCLUDED_ASSET_TYPES = ('money_fund', 'reverse_repo', 'cash')`（XIRR 已排除货基）
- 用途口径：`backend/app/services/importer/orchestrator.py:167 / 614`（五笔钱把货基归 `liquid` 活钱）

## 2. 目标与非目标

**目标**

- 账户可绑定一个类现金产品（基金标的，余额宝概念）。
- 用户可自行开关「卖出回款自动申购」（主动权在用户）。
- 类现金在统计中**单独显示**，给用户明确心理暗示，便于管理中高风险敞口。

**非目标**

- 不新增资产大类（C 已取消）。
- 不新增持仓 `venue` 字段做场内 / 场外分类（暂缓，现有 `asset_type` 已隐含）。
- 不做自动赎回 / 自动转账（保持用户主导）。

## 3. 类现金口径（零新概念）

> **类现金 = 现金 `cash` + 货币基金 `money_fund` + 逆回购 `reverse_repo`**

直接复用现有 `EXCLUDED_ASSET_TYPES`（`performance/constants.py:9`）——
即「系统里已经有三处把这三样当类现金了」（XIRR 收益口径、五笔钱用途口径、本设计的统计口径），
不再引入第四个概念，也天然避免了口径漂移。

**债券基金不归入类现金**：它有净值波动、XIRR 也未排除，本质是中低风险**投资**而非现金。
若日后需要单列中低风险，那属于「风险分层」维度（低 / 中 / 高），应独立设计，不混入类现金
——这正是 C 被取消时所担心的分类膨胀。

## 4. 数据模型

`Ledger`（`backend/app/domains/ledgers/models.py`）新增两字段：

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `linked_money_fund_id` | Integer, FK `funds.id`, nullable | NULL | 账户绑定的类现金产品（基金标的，余额宝） |
| `auto_purchase_money_fund` | Boolean, not null | **False** | 卖出回款是否自动申购绑定的类现金产品 |

- 绑定目标为**基金标的**（`Fund` 表，`funds/models.py:72`），而非持仓（持仓卖光会悬空）。
- 参照既有 `linked_cash_ledger_id` 的绑定 / 校验模式。
- 开关**默认关闭**：遵循「用户不操作，系统不代劳」。
- 迁移：`scripts/` 下补列脚本，两字段均无需历史回填（NULL / False 即默认语义）。

## 5. 自动申购逻辑

| 条件 | 行为 |
|---|---|
| 开关关闭（默认） | 回款留在账户现金（即 A 落地后的行为，不做任何自动操作） |
| 开关开启 + 已绑定货基 | 回款入账后自动生成一笔申购该货基的记录（`asset_type='money_fund'`，`ledger_id` = 该投资账户，金额 = 回款净额） |
| 开关开启 + 未绑定 | 开关禁用并提示「请先绑定类现金产品」 |

- **触发范围（当前）**：卖出 / 赎回产生的现金流入（`sell` / `withdraw`）。
- **不触发（当前）**：分红、逆回购到期等其他现金流入——保持最小惊讶，后续按需扩展。
- 两条写入路径均需覆盖：手动卖出（前端卖出表单 → 交易服务）、导入回款（`ImportOrchestrator`）。

## 6. 统计口径

- 类现金合计 = 账户现金余额 + 该账户 `money_fund` 持仓市值 + `reverse_repo` 市值。
- 货基金额已有现成实现：`LedgerService.get_money_fund_stats`（`ledger_service.py:235-266`）
  返回 `money_fund_amount` / `money_fund_ratio`。
- 中高风险投资资产 = 其余 `asset_type`（股票 / 基金 / ETF / 可转债 / 债券等）持仓市值。
- 需在账户详情页与资产总览中**分开展示**，不合并为一个笼统的总额。

## 7. UI 设计

### 7.1 账户编辑 / 创建

- 新增「类现金产品（余额宝）」选择器：基金搜索（限定货基），绑定 `funds.id`。
- 新增「卖出回款自动申购」开关（`el-switch`），默认关闭。
- 未绑定货基时开关**禁用**并提示「请先绑定类现金产品」。

### 7.2 控制粒度：每账户单独控制（主）+ 批量应用（辅）

- **单独控制为主**：不同账户策略天然不同（证券账户可能希望回款自动买货基吃收益，
  场外基金账户可能想留现金再投）。统一开关会逼用户妥协。
- **批量应用为辅**：账户列表提供「把当前设置应用到所有账户」；新建账户继承上一次设置。
- 一键是「批量设置」而非「全局锁定」——用户随时可单独改某个账户。

### 7.3 展示：借鉴支付宝，但**主次反转**

支付宝以现金为主（总金额大字 + 余额宝 / 余额并列）。本产品是投资工具，用户主要资产是中高风险资产，
因此反转权重：

```
┌─────────────────────────────────────────┐
│ 投资资产（中高风险）                       │
│ ¥ 128,450.00              ← --text-hero │  ← 主显示，大字（48px / 600）
│ 股票 45% · 基金 32% · ETF 18% · 可转债 5% │
├─────────────────────────────────────────┤
│ 类现金（辅助）                  ¥ 12,300 │  ← --text-small（14px）+ --text-tertiary
│ 现金 3,200 · 货基 8,600 · 逆回购 500      │
└─────────────────────────────────────────┘
```

- 中高风险：主显示，`--text-hero`（48px / 600，`design.md` 总资产规格）。
- 类现金：辅助显示，`--text-small`（14px）+ `--text-tertiary`，**单独成块**
  （用户要的心理暗示：一眼看到多少在中高风险里）。
- 复用 `SectionHeader` + `CardBlock`，配色走 `--chart-01~08` 语义变量，**禁止硬编码颜色 / 样式**。

### 7.4 design.md 对照清单（前端实现强制遵循）

> 依据 `frontend/design.md`。实现时逐条对照，禁止硬编码颜色与样式。

| 维度 | design.md 规范 | 本设计落点 |

| 卡片容器 | `CardBlock`（`--bg-card` + `--radius-lg` + `--border-light` + `--shadow-raised` + `--space-standard`），禁止手写卡片样式 | 两个区块卡片 |
| 主显示字号 | `--text-hero`（48px / **600** / 56px 行高 / -0.5px） | 中高风险投资资产金额（主显示） |
| 辅助字号 | `--text-small`（14px / 400 / 20px 行高）+ `--text-tertiary` | 类现金金额与明细（辅助显示） |
| 卡片标题 | `--text-heading`（20px / 600） | 由 `SectionHeader` 内部统一，不另设 |
| 间距 | `--space-standard`（24px，卡片默认）；仪表盘 / 概览卡片用 `--space-loose`（32px） | 区块内边距与区块间距 |
| 图表配色 | `--chart-01` ~ `--chart-08`；**所有图表颜色经 `getComputedStyle` 读取 CSS 变量，禁止硬编码色值** | 资产占比环形图 / 占比条 |
| 涨跌色 | `--color-rise`（涨，红）/ `--color-fall`（跌，绿）；不用绿色传递正面情绪 | 收益相关数字（若涉及） |

| 无障碍 | 可交互元素带 `:focus-visible` 焦点环与 `aria` 标签；正文对比度 ≥ 4.5:1（WCAG AA） | 绑定选择器、自动申购开关 |
| 禁止项 | 不硬编码色值、不用 <6px 小圆角作卡片、不在暗色模式简单反转亮度、不用颜色作为唯一信息载体 | 全部走语义变量 |

## 9. 验收标准

- [ ] 可为账户绑定类现金产品并持久化，重新进入能正确回显。
- [ ] 开关关闭时，回款留在账户现金（行为与 A 一致，不产生额外交易）。
- [ ] 开关开启时，卖出回款自动生成一笔绑定货基的申购记录。
- [ ] 未绑定类现金产品时，开关禁用并给出明确提示。
- [ ] 类现金在统计中单独显示，与中高风险资产分开，字号 / 层级符合 §7.3。
- [ ] 单元测试覆盖开关两种状态 + 未绑定的降级路径。

## 10. 待定 / 后续

- 分红、逆回购到期等现金流入是否纳入自动申购（当前否）。
- 中低风险（如纯债）是否单列——属「风险分层」维度，当前否。
- 持仓 `venue`（场内 / 场外）字段：概念已存在于自选与 AI 识别，持仓维度暂缓。

## 11. 与「现金等价物分类开关」的正交关系（2026-09-07 补充）

`cash-equivalent-classification-design-2026-09-07.md` 提出 per-asset `is_cash_equivalent` 覆盖项（这笔算现金还是投资）与收益口径分家。本设计的账本绑定机制（§4）与它**正交、互不替代**：

- `linked_cash_ledger_id`（现金账户绑定）、`linked_money_fund_id` + `auto_purchase_money_fund`（类现金绑定 + 自动申购）管的是**钱流向哪**；
- `is_cash_equivalent` 管的是**这笔在统计上算现金还是投资**。

自动申购生成的货基流水本就是 `money_fund` 类型 → 默认现金等价，与新设计天然一致。两者叠加不产生冲突，但前端需在「账户编辑」同时呈现两类开关并说明区别，避免用户混淆「自动申购」与「分类开关」。
