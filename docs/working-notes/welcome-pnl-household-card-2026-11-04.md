# 首页「最新收益」卡：家庭口径与隐私模式（2026-11-04 用户拍板）

> 涉及：`TodayPnlCard.vue` / `WelcomeAssetBoard.vue` / `MoneyDisplay` /
> `usePrivacyMode` / `summary_service.ratio_pct` / `today_pnl.build_today_pnl`

## 一、用户提出的四个问题

1. 卡片只有「最新收益」和「投资类资产」，为什么没有**家庭总资产**？
2. 底注那一行数字全堆在左下角，右半边空着；
3. 总负债是不是该**特殊显示**？
4. 要不要加一个**隐藏数字**的按钮（行情不好 / 办公室隐私，只看百分比）？

## 二、结论

| # | 结论 | 落点 |
|---|---|---|
| 1 | `total_assets_cny` 后端**早就有**，只是前端没用；补上后 `总资产 = 总负债 + 净资产` 才闭合 | `TodayPnlCard` 家庭三列 |
| 2 | 底注一行小字 → 三列等宽 band（复用 `OverviewAssetsCard` 的「三列 + 竖细线」模式） | 同上 |
| 3 | 负债**不染涨跌色**，改用「比率 + 结构条 + 阈值仅限资不抵债」 | `liability_ratio` + `__leverage` |
| 4 | 隐私模式做，但必须**渲染层换文本**，不是 CSS 模糊 | `usePrivacyMode` + `MoneyDisplay` |

### 为什么负债不能用红/绿

这套体系的红绿语义是「涨=好、跌=坏」。负债增加是**坏事**，染红会变成「红色=好事」，
语义直接反转。负债真正需要的是三样东西，颜色一样都不在里面：

- **比率**（负债率 51.8%）：1,760,000 单独看只会吓人，51.8% 才说得清是房贷还是危险；
- **结构条**：把绝对值变成「杠杆水位」；
- **不设经验阈值**：60% / 70% 都给不出依据，51.8% 的房贷家庭不该被判「风险」。
  唯一保留的染色条件是 **负债率 ≥ 100%（资不抵债）**——那时它表达的是风险，不是符号。

## 三、口径：所有占比由后端直出

前端曾计划只把两个宏观比率放后端、分项占比前端算，**已否决**：
同一张卡上四个数各自都能被用户心算验算，前端再除一遍就会出现
「金额对得上、百分比差 0.1」，这类观感 bug 无法靠对账解释。

| 字段 | 出口 | 分母 |
|---|---|---|
| `liability_ratio` | `summary_service.get_summary_data` | 家庭总资产 |
| `invested_ratio_of_assets` | `today_pnl.build_today_pnl` | 家庭总资产 |
| `classes[].share_of_invested` | `today_pnl.build_today_pnl` | 投资类资产 |

三者共用 `summary_service.ratio_pct`（唯一实现）：两位小数、分母 ≤ 0 一律 `None`。
`None` 不是 0%——「负债率 0%」会被读成「一分钱负债都没有」。

### 盘中要重算，否则占比停在旧值

`todayPnlOverlay` 改写市值后，占比必须跟着动（否则股票涨 1% 后金额变了、占比不变）。
故 overlay 里有一份与后端**逐条对齐**的 `ratioPct`；分母由 `useTodayPnl` 的
`householdAssets` 取值器注入（来自同一份 `summary`，不另取一份）。

### 踩到的坑：分子分母是两条取价路径

写测试时先撞了一次：投资类资产 2,200、家庭总资产 1,800，占比 **122%**。

- 分子（投资类资产）来自 pnl 引擎 → **历史价格序列**（as-of）；
- 分母（家庭总资产）来自 `family_totals` → `market_value_cents` → **持仓快照价**。

两条路径取价，加上 fixture 只写了价格序列没写 `current_price`，就出现了分子大于分母。
这既是测试陷阱，也是**真实存在的时点错位**（盘中分子可能是昨天收盘、分母是今天的快照）。
占比只作结构参考（1 位小数），不用于任何对账——注释已写进 `today_pnl` 模块头。

## 四、隐私模式的三条硬规则

1. **渲染层换文本**：`filter: blur()` 后 DOM 里仍是真数字，屏幕共享 / 审查元素 / 读屏都能拿到；
2. **占位符不带位数**：统一 `¥ ••••`，不写 `¥••,•••.••`——位数本身就是信息；
3. **真值不进 `title` / `aria-label` / `data-*`**：读屏念「金额已隐藏」，不念数字。

其余约定：

- **保留**百分比、涨跌色、占比、负债率、日期、估/确认徽标——用户要知道「今天红不红」；
- 状态是**模块级单例**（`localStorage` 持久化），否则「这张卡遮了那张没遮」比不遮更糟；
- **长按 180ms 窥视**，松手复原（低于 180ms 视为滚动误触）；
- `MoneyDisplay` 单点生效 + `no-mask` 逃生门（表单回显必须看得见真值）。

## 五、家庭三列各自是入口（2026-11-04 追加）

三列原本纯只读。用户拍板「需要」，于是每列指向一个**不同的既有页面**——
同一个链接复制三次，点击只证明「能点」，不带来新信息：

| 列 | 目标 | 为什么是这里 |
|---|---|---|
| 家庭总资产 | `/panorama` | 资产总览：大类构成 + 桑基流向，回答「钱在哪」 |
| 家庭总负债 | `/inventory?tab=liability` | 全面盘点负债档：逐笔可看可改，回答「欠谁的」 |
| 家庭净资产 | `/analysis` | 投资复盘「资产净值走势」：每日快照序列，回答「最近怎么走」 |

净资产去复盘页而不是总览页：总览页只拿快照算环比同比，真正的净值**时间序列**在复盘页。

### 三个实现细节（都不是可选项）

1. 用 `<a :href>` 而不是 `<div @click>`：中键新标签页、键盘 Enter、读屏「链接」角色全都白拿；
   `click` 里 `preventDefault()` 后自己 `router.push`——history 模式下让 href 直跳等于整页刷新。
2. **长按 ≠ 点击**：这一带的长按已被「窥视金额」占用。`peekFired` 记「这次按压确实揭开了」，
   由 `onColClick` 吃掉紧随的 click；否则手机上「看一眼数字」的代价是「被带走」。
   每次 `pointerdown` 重置该标记，不误伤下一次正常点击。
3. **触屏长按会弹系统菜单**（新标签打开 / 拷贝链接），一弹就打断窥视：遮罩中且
   `(hover: none)` 时拦 `contextmenu`，桌面右键照旧放行。iOS 另加 `-webkit-touch-callout: none`。

### 视觉

- 悬停只铺一层 `--bg-soft`，**不动**字号/颜色/字重——这一带是「读数」，数字悬停跳一下会被读成「数值变了」；
- 箭头 `ep:arrow-right`（12px）默认 `opacity: 0`，悬停/聚焦才淡入并从左 2px 归位：
  三个常驻箭头会把「读数区」读成「按钮排」；
- 命中区**不用**「padding + 负 margin」：桌面端列自带 44px 高、宽撑满 1/3，
  已经够；而窄屏三行只隔 8px gap，负 margin 会让相邻两行的命中区互相盖住
  （点「总负债」落到「总资产」上，截图实测已复现）。窄屏改为整行 `padding: 8px 0`，
  命中区从 21px 抬到 ~37px，**不加负 margin**；触屏没有 `:hover`，补 `:active` 反馈、
  箭头常驻 0.45 透明度；
- 焦点环用全局 `--focus-ring`（不用 `outline`：圆角块上会画成直角，贴边列还会被切）。
