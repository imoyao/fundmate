# 投资策略引擎 —— 需求分析与可行性讨论（v0.1 讨论稿）

> 状态：**讨论稿 v0.2**（2026-10-15 二次讨论补充见 §13，含历史 issue 核查与形态决策），仅作需求层分析，未进入设计/开发。
> 日期：2026-10-15
> 范围：内置大众投资策略库 + 持仓诊断 + 纪律性交易计划提醒（面向基金的买卖约束）
> 立场：**买方视角**（站在散户投资者的收益体验一侧，而非平台增长一侧）

---

## 0. 一句话结论

**值得做，但必须先换掉成功标准。**

这个功能的目标不是"帮用户提高收益"（收益由市场决定，任何产品都不该承诺），而是
**降低用户的"行为损耗"**——即"基金涨了、账户没涨"的那部分缺口。
收益是纪律的**副产品**，纪律才是产品主线。

技术上难度**中高**，但真正的难点不在代码，而在三件事：
① 策略语义的严谨定义（否则是"玄学卡片"）；② 数据口径（尤其基金估值）；③ 信任建立（信号一次不可信，用户就永久弃用）。
建议按 **L0 → L1 → L2 → L5** 四期落地，**首期只做"策略库 + 持仓诊断"（纯只读、零风险）**。

## 1. 需求还原与边界

### 1.1 你想要的（据描述 + 5 张截图）

截图分两类：

- **策略卡片页 × 4**（趋势交易 / 价值投资 / 趋势跟踪 / 长期持有）——结构高度统一：
  策略定位 → 关键指标条（年化 / 最大回撤 / 胜率 / 适合人群）→ 核心要点 → 买卖操作指引 →
  工具配置建议 → 心法与纪律（金句）→ 综合维度排序 → 案例回测（某基金 +45% / +78% / +38% / +42.5%）→
  关键数据 → 进阶学习 → 底部两个按钮：「关闭策略」「**结合我的持仓**」。
- **AI 策略总页 × 1**——「**找到适合你的策略**」（4 大策略智能匹配，纪律执行）：
  2×2 策略卡片（长期持有 / 趋势投资 / 波段交易 / 价值投资，均可"已选/未选"）→
  **策略收益对比**（近 3 年，长期持有 vs 趋势投资 累计收益折线）→
  **推荐策略（基于基金特征匹配）**：每条带"策略类型标签 + 近 3 年收益 + 胜率 + 跑赢基准"，
  并用**自然语言回测规则**呈现（例："买入：净值波动 < 1；卖出：净值波动 > 75；每周检查"）→
  **自定义策略交易计划** → **我的策略交易计划** → 风险提示。

归纳出的功能诉求：

1. 内置**大众策略库**（首批 4 个：长期持有 / 趋势投资 / 波段交易 / 价值投资；后续加**全天候**等）
2. 对用户**持仓的基金与股票**做分析，产出**纪律性交易计划**
3. 用户**自定义策略**可绑定内置策略（不是各玩各的）
4. **测评**：判断"用户适合什么策略 / 擅长什么交易"，据此选中适用策略
5. 解决"**产品维度 vs 用户维度**"的匹配问题
6. **消息通知**（复用首页横栏 + 消息 Box）
7. 未来可扩展（加全天候不用重写底层）

### 1.2 我们现状盘点（避免重复造轮子）

| 层 | 现状 | 与本次的关系 |
|---|---|---|
| 后端 `domains/strategy` | **仅策略标签**（`StrategyTag` + `PositionStrategyTag`），自由文本（如"成长"），绑定持仓做**风格分组**；页面自述"**纯分析功能，不参与组合收益率计算**" | **没有任何策略计算**。本次是在标签之上**新建"策略引擎"** |
| 数据底座 | 基金净值序列、指数日线、基金持仓穿透、基金经理、多个投顾 adapter（天天/且慢/好买/东财） | 底子不错，是本次能落地的关键前提 |
| 通知底座 | `lay-notice`（**仍是 pure-admin 脚手架 mock**，未接后端）、`RealtimeWarningBanner`（localStorage 一次性横幅） | 通道**形态有、能力无**，本次要真正打通 |
| 收益率能力 | 已有 XIRR（真实收益率） | **极关键**：这是我们度量"行为损耗"的天然标尺（见 §3.4） |

### 1.3 本次**不做**什么（先划边界，防跑偏）

- ❌ 不做量化交易系统 / 不做自动下单 / 不做参数寻优平台
- ❌ 不做高频信号（**日频为上限**，基金本身就是日频净值）
- ❌ 不做收益承诺 / 不做"跟单"
- ❌ 不追求策略数量，首批 4 个做扎实即可

## 2. 必要性分析（买方视角）

### 2.1 买方真正的痛点不是"缺信息"，是"知道却做不到"

散户不缺"该长期持有"的道理，缺的是**在下跌时拿得住、在狂热时不追高**的能力。
这不是知识问题，是**行为问题**。两条硬证据：

**证据一（国内，2026 年首次有官方口径）**
2026 年公募基金中报**首次强制披露"盈利投资者数量占比"**（证监会 2026 年 3 月修订信披新规，
5 月 1 日起实施；统计区间 2025-07-01 ~ 2026-06-30，口径为扣除申赎费后区间净收益 ≥ 0）：

| 观测 | 数值 |
|---|---|
| 披露基金数 | 5,662 只 |
| 盈利投资者占比 **中位数 / 平均** | **92.49% / 79.02%**（中位数与均值差 13 个百分点，说明有一批"极低"产品拉低均值） |
| 盈利占比 **< 50%** 的基金 | **1,005 只，占 17.77%** |
| 融通产业趋势精选A | 近一年净值 **+57.87%**，盈利投资者占比 **仅 9.92%** |
| 招商安裕A | 近一年净值 **-1.95%**，盈利投资者占比 **却 89.24%** |
| 偏股混合型 / 普通股票型 平均盈利占比 | **71.81% / 72.02%**，而同期约 **86%** 的产品是赚钱的 |

> 解读：**"净值涨 57%、九成人亏钱"与"净值跌 2%、九成人赚钱"能同时发生**，
> 说明真实收益的主要变量不是"买了什么"，而是"**怎么买、怎么拿**"。
> 数据来源：Wind 统计，转引自天天基金 / 网易财经 / 中国经济网（2026-08~09）。

**证据二（海外，长期、跨资产）**
Morningstar《Mind the Gap》（截至 2024-12-31 的 10 年）：
- 投资者**实际**年化收益 **7.0%**，而所持基金**总回报** **8.2%** → 缺口 **1.2%/年 ≈ 总回报的 15%**
- 该缺口在 2020 / 2021 / 2022 / 2023 各期**持续存在**（"像费用率一样稳定的成本"）
- **交易越频繁**（现金流波动越大）的基金，投资者实际收益越低
- 波动最大的板块基金，投资者平均落后"买入持有" **超过 7 个百分点/年**
- 彼得·林奇管理麦哲伦基金年化近 **30%**，但**平均投资者只赚约 13%/年**
- Vanguard Advisor's Alpha：投顾增值中，**行为指导（behavioral coaching）是权重最大的单项**

### 2.2 为什么"策略化提醒"能切进去

行为金融学给出三个可被"规则"对冲的本能：

| 本能 | 表现 | 规则化如何对冲 |
|---|---|---|
| **处置效应** | 赚一点就跑、亏了死扛 | 用"卖出条件"替代"感觉"（趋势破了才走 / 目标到了才走） |
| **损失厌恶** | 下跌时恐慌出逃（卖在底部） | 前置规则：回撤阈值触发的是"检查"而非"清仓" |
| **追涨/近因效应** | 涨得最好时买入（买在顶部） | 买入条件绑定"状态"而非"涨幅" |

一个**天然实验**支持"外部纪律有效"：盈利占比最高的产品几乎都是**持有期基金**
（如中泰兴诚价值一年持有 98.42%）——**产品设计把"最容易犯错的那只手"锁住了**。
我们做策略提醒，等于用软件给非持有期产品**补上这只手**。

### 2.3 对产品的价值

- **从"记录过去"到"改善未来"**：纯记账是低频、可替代性强的功能；纪律引擎是留存与差异化的支点
- **形成数据闭环**：诊断 → 提醒 → 用户行为 → 复盘改进。闭环越转越准，构成护城河
- **为未来变现留接口**：投顾/策略订阅的内容基础（合规前提下）

### 2.4 反向压力测试：不做的理由 / 做砸的理由

**不做的理由（要正视）：**
- 用户可能"看个热闹"，看完策略卡片就忘了 → 陷入"内容消费"而非"行为改变"
- 维护成本高：策略要持续校准，信号要持续产出，是**长期运营**而非一次性开发

**做砸的理由（更要正视）：**
- **假信号摧毁信任**：一次像样的"打脸"（例如趋势策略让用户高买低卖），用户就再不信第二次
- **提醒疲劳**：提醒太多 = 等于没提醒
- **合规风险**：措辞稍有越界就可能构成"投资建议"（见 §10）

**结论**：必要性成立，但**成败取决于"克制"**——宁可少提醒、少策略，也要保证每次提醒都站得住。

## 3. 能否提高纪律性 → 能否创造价值（核心判断）

### 3.1 先给结论（不和稀泥）

| 问题 | 判断 | 确定性 |
|---|---|---|
| 能否**提高纪律性** | **能** | **中等偏高**（行为金融学机制成立 + 实证支撑 + 持有期产品的自然实验） |
| 能否**提高收益** | **不能保证** | **低**（取决于市场；最多改善"相对自己不做纪律"的结果） |
| 能否**创造真实价值** | **能，但价值定义要对** | 价值 = **减少行为损耗**，不是 = 提高绝对收益 |

**必须诚实对外表达的定位：**
> "我们帮你**少犯错**，不承诺帮你**多赚钱**。"

### 3.2 成立的四个前提（缺一不可）

1. **信号可信**：策略不能频繁打脸。宁可信号少，也不要噪音多 → 决定"策略要用低频、稳健的规则"
2. **提醒可执行**：不能只说"该减仓了"，要给**明确动作 + 一键操作入口**
3. **有承诺约束**：用户把规则**写下来、被跟踪**（类似"投资契约"），才会产生自我约束
4. **频率克制**：同标的同策略不重复轰炸；每日聚合而非逐条推送

### 3.3 失效/有害的情形（必须设计规避）

- 用户认知与策略冲突（价值投资者被推"趋势"）→ 靠**匹配**解决（§7）
- **多策略互相矛盾**（同一标的一个说买、一个说卖）→ 靠**组合仲裁**解决（§6.4）
- 只提醒不跟踪 → 无法验证有效性 → 用户流失 → 靠**执行闭环**解决（§8 L4）

### 3.4 如何验证有效（把"价值"变成可度量的指标）

**这是我们最大的隐藏优势**：系统已有 **XIRR（真实资金加权收益率）** 与持仓成本数据，因此可以直接度量：

```
行为损耗率 = 用户 XIRR（真实收益率）
           − 其持仓的"买入持有"收益率（假设从未加减仓）
```

- 缺口越大 = 行为损耗越重 = 功能价值空间越大
- **上线前**：对存量用户**离线算一遍这个缺口**（只读、无风险）→ 既验证需求真伪，又拿到"痛点基线"
- **上线后**：跟踪同一用户的缺口是否随策略使用而收窄 → 这就是**北极星指标**

> 建议 P0 阶段就把这个指标做出来。**如果存量用户的缺口普遍很小，这个功能的必要性就要重新评估**——
> 这是对"必要性"最硬的反向压力测试，应优先执行。

## 4. 实现难度评估

| 模块 | 难度 | 关键依赖 | 主要风险 |
|---|---|---|---|
| 策略定义层（语义/参数/解释） | 中 | 领域知识 | 定义含糊 → 变玄学 |
| 数据供给层（净值/估值/持仓/宏观） | **中高** | 现有数据源扩展 | 基金层**无估值数据**；转债/商品缺 |
| 信号计算层（指标/状态机） | 中 | 数据完整性 | 缺失/异常数据处理 |
| 组合层（多策略×多标的仲裁） | **中高** | 冲突消解规则 | 信号互相打架 |
| 匹配层（产品 × 用户画像） | **中高** | 测评体系 | 测评问卷设计不当=乱推荐 |
| 回测/收益对比 | **高** | 长历史 + 算力 | 过拟合；幸存者偏差；**回测≠未来** |
| 展示层（卡片/诊断/对比） | 中 | 前端 | 信息过载 |
| 通知层（分级/节流/闭环） | 中 | 通知底座重建 | 提醒疲劳 |
| 合规层（全链路措辞） | **中高** | 法务口径 | 越界即"投资建议" |

**总体：中高。** 结论重申：**难的不是技术，是语义与信任。**

## 5. 数据是否足够（策略 × 数据矩阵）

| 策略 | 所需数据 | 基金（现状） | 股票（现状） | 转债 | 缺口 |
|---|---|---|---|---|---|
| **长期持有** | 净值序列、持仓成本、持有期 | ✅ 有 | ✅ 有 | ✅ 有 | 无 |
| **趋势投资** | 净值/价格序列 + 均线 | ✅ 有 | ✅ 有 | ✅ 有 | 无 |
| **波段交易** | 净值序列 + 波动区间识别 | ✅ 有 | ✅ 有 | ⚠️ 需溢价率 | 基金日频、含申赎费，**不宜高频** |
| **价值投资** | **估值（PE/PB/股息率/盈利）** | ❌ **缺**（基金只有净值） | ✅ 有 | ❌ 需纯债价值/YTM | **最大缺口** |
| **全天候/配置** | 多资产指数（股/债/商品/黄金） | ⚠️ 部分（有指数日线） | — | — | 跨资产需扩展 |
| **可转债专用** | 价格 + 转股溢价率 + 纯债价值 + YTM | — | — | ❌ 需新数据源 | 独立品类，**单独评估** |

**关键结论：**
1. **趋势/波段/长期持有 —— 数据现成，一期即可做**
2. **价值投资的"基金估值"需要加工，但概念并不含糊**（v0.2 修正，见 §13.6）：
   场内 **LOF/ETF 本身就有 PE、股息率**（跟的是指数/个股），**口径清晰**；
   场外**主动基金**没有直接估值，但有**三条可达路径**：
   ① **穿透重仓股加权**（我们有持仓穿透能力）；② 用**跟踪指数估值**做代理；③ **行业指数估值**（行业主题基金）。
   **结论：这是"数据加工成本"，不是"概念不清"。**
3. **全天候**要等"多资产数据供给层"就位（§6 架构要预留），**这正是"底子要打好"的核心**
4. **可转债**是一等公民还是二等公民，需要你定（见 §11 问题 1）

## 6. 架构设计（可扩展性：为全天候留底子）

### 6.1 核心抽象——统一策略接口

所有策略（含未来的全天候）都实现同一契约，**核心框架永不为新策略改动**：

```
Strategy
├── meta            # 名称/简介/适合人群/心法/解释模板（对应截图卡片文案）
├── required_data   # 声明依赖的数据（净值 / 估值 / 多资产 / 宏观）→ 由数据层按需供给
├── params_schema   # 参数定义（如"净值波动<1 买入"）→ 可被用户自定义覆盖
├── warmup          # 预热所需历史长度
├── evaluate(ctx)   # 核心：输入(状态+数据) → 输出 Signal
└── explain(signal) # 把信号翻译成"人话"（合规措辞）
```

### 6.2 策略分类（按"数据依赖"而非"名字"分，决定可扩展性）

| 类别 | 代表 | 数据依赖 | 说明 |
|---|---|---|---|
| **择时型** | 趋势投资、波段交易 | 价格/净值序列 | 只依赖时间序列，最易做 |
| **估值型** | 价值投资、定投 | 估值序列 | 需要估值数据（§5 缺口） |
| **配置型** | **全天候**、股债平衡、风险平价 | **多资产** | **新类别 = 新增一个实现，不改核心** |
| **行为型** | 止盈止损、再平衡提醒、纪律打卡 | 持仓 + 成本 | 最轻，价值感却最强 |

> **"加全天候不用从头再来"的答案**：全天候属"配置型"，只要数据供给层已支持多资产，
> 它就是**一个新增插件**（新 `required_data` + 新 `evaluate`），核心策略框架、状态机、通知链路全部复用。

### 6.3 状态机（每个"标的×策略"实例一台）

```
空仓 → 试探 → 持有 → 减仓 → 清仓 → 观望
                ↑___________________________|
```
- 每次状态跃迁写一条 **Signal 日志**（时间/原因/建议动作/依据指标值）
- **信号日志 = 复盘的原材料 + 可信度的证据**（"我上次让你减仓，是因为 X，后来验证如何"）

### 6.4 四个必须解耦的点

1. **数据供给层（DataProvider）**：统一契约（净值 / 估值 / 持仓 / 宏观），策略只声明依赖，不自行取数
2. **策略注册表**：插件式注册，新增策略零侵入
3. **策略实例（StrategyInstance）**：`用户 × 标的 × 策略 + 参数`，**与现有 `strategy_tags` 衔接**
   （现有标签可升级为"策略实例"的轻量载体，见 §12）
4. **组合仲裁层**：同一标的命中多个策略且**结论冲突**时，按 **优先级 / 投票 / 保守优先** 出唯一结论

## 7. 策略匹配：产品维度 vs 用户维度（正面回答你的困惑）

### 7.1 结论：**不是二选一，是两层过滤**

> **产品维度决定"候选集"，用户维度决定"从候选集里选谁"。**

你的两个直觉**都对，但各自只对了一半**。

### 7.2 第一层：产品-策略适配（**客观层**，回答"这个产品适合怎么买"）

由资产的**客观属性**（波动率 / 风格 / 是否持有期 / 流动性）决定**哪些策略在物理上适用**：

| 产品特征 | 适配策略（候选集） | 不适配 |
|---|---|---|
| 宽基指数基金 | 长期持有、定投、趋势 | 波段（无高频空间） |
| 高波动行业主题基金 | 趋势、波段 | 纯长期持有（拿不住） |
| 深度价值个股 | 价值投资 | 趋势（常与基本面背离） |
| 债券基金 | 持有 | 趋势/波段 |
| 可转债 | 转债专用策略 | 通用股票策略 |

**这一层是"某产品的最佳策略"**——你说的"一个产品到底最佳策略是不一样的"**成立**。

### 7.3 第二层：用户-策略适配（**主观层**，回答"这个人能做得了吗"）

即使产品适合"趋势"，也**不该推给一个每月只看一次账户、且情绪化的人**。
测评维度建议：

- **风险承受**（能忍受多大回撤）
- **投资期限**（资金多久不用）
- **精力/时间**（能否盯盘、能否按周检查）
- **经验**（是否理解止损纪律）
- **性格**（下跌时能否不慌）—— 决定"**拿不拿得住**"

### 7.4 最终推荐公式

```
推荐 = 产品候选集 ∩ 用户画像适配
       ↓
默认值 = 产品级推荐（弱画像时的兜底）
       ↓
用户可覆盖（尊重自主选择，但记录偏离）
```

### 7.5 打个比方把逻辑讲透

> **产品维度 = "这道菜适合什么吃法"**（川菜适合配米饭，不适合配甜酒）
> **用户维度 = "你能吃多辣"**（川菜再合适，你不能吃辣也白搭）
>
> 所以：**先看菜（产品）筛出可行吃法，再看人（用户）从可行吃法里选一个能接受的。**
> 你说的"擅长价值投资的人，是否所有产品都按价值投资做"——**答案是否定的**：
> 一个人可以"整体偏价值"，但保守型债券的持仓依然该用"持有"策略。
> **策略是"人 × 产品"的联合函数，不是单变量。**

### 7.6 落到产品上

- **产品级推荐**：进"基金详情/持仓详情"页时，展示"这只标的的适配策略 + 当前信号"（截图里的"基于基金特征匹配"）
- **用户级策略**：在"策略中心"由**测评**选出（截图里的"找到适合你的策略"）
- **两者关系**：产品级给**候选**，用户级做**选择**，冲突时以用户显式选择为准并提示风险

## 8. 需求分层与分期路线

| 层 | 能力 | 读/写 | 价值感 | 风险 | 建议期次 |
|---|---|---|---|---|---|
| **L0 策略库** | 策略卡片（定义/心法/工具/案例，纯知识） | 读 | 中 | 低 | **P0** |
| **L1 持仓诊断** | 把策略套到持仓，显示"当前状态 + 信号"（只读，不推送） | 读 | **高** | **低** | **P0** |
| **L2 纪律提醒** | 信号触发 → 通知（分级/节流/一键动作） | 推送 | **高** | 中 | **P1** |
| **L3 交易计划** | 生成**具体计划**（价位/仓位/批次） | 建议 | 高 | **中高（合规）** | P2 |
| **L4 执行跟踪** | 记录用户是否执行 → 复盘 → 修正 | 读/写 | **高（闭环）** | 低 | P2 |
| **L5 个性化匹配** | 测评 → 用户画像 → 千人千面推荐 | 读 | 高 | 中 | **P1~P2** |
| **L6 回测/收益对比** | 策略历史收益对比（截图的总页图） | 读 | 中 | **高（过拟合）** | P3 |

**推荐节奏：**

- **P0（首期）＝ L0 + L1**：纯只读、零合规风险、能立刻验证"用户看不看"。
  **同时离线跑 §3.4 的"行为损耗率"基线**。
- **P1 ＝ L2（＋L5 可选）**：打通通知，形成"诊断→提醒"的**第一次闭环**。
- **P2 ＝ L3 + L4**：进入"计划 + 执行跟踪"，这才是**纪律性的真正来源**，但合规措辞要求最高。
- **P3 ＝ L6 + 全天候**：回测与策略扩展。

> **为什么先 L0+L1 而不是先做最炫的"回测对比"**：
> 回测最容易做、最吸引眼球，但**最容易过拟合、最容易引发"为什么你回测这么好我却亏了"的信任反噬**。
> 先做"当前状态诊断"，是**用最低成本验证需求真伪**的正确顺序。

## 9. 消息通知设计

### 9.1 概念模型（**信号 ≠ 通知**，这两者必须分开）

```
Signal（信号：规则触发的客观事实）
   → Event（事件：去重/合并/降噪后）
      → Notification（通知：分级 + 节流 + 措辞）
         → User Action（一键动作：加入计划 / 标记已执行 / 忽略并说明）
            → Log（记录：供复盘与效果度量）
```

### 9.2 通道分工（复用现有资产）

| 通道 | 定位 | 承载 |
|---|---|---|
| **首页横栏** | **强提醒、常驻** | 当前"需要你关注"的**少量**高优先事项（0~1 条） |
| **消息 Box** | **弱提醒、历史** | 全部信号历史、已忽略、周报聚合 |
| （未来）站外推送 | 提醒 | 价格触及类强事件（需评估） |

### 9.3 分级与节流（**这是成败关键**）

| 级别 | 例子 | 通道 | 节流 |
|---|---|---|---|
| **P0 强** | 估值/趋势触发"该检查了"；回撤触及预设阈值 | 首页横栏 + 消息 | 同标的同策略 **N 天内不重复** |
| **P1 中** | 策略状态跃迁（持有→减仓） | 消息 Box | 每日聚合 |
| **P2 弱** | 周报（本周信号回顾、行为损耗变化） | 消息 Box | 每周一次 |

**铁律：宁可漏报，不可滥报。** 一条被忽略的提醒，不如一条被执行的提醒。

### 9.4 闭环动作（决定"提醒"能否变成"纪律"）

每条通知都必须带**可执行动作**：
「加入我的计划」/「标记已执行」/ 「忽略（并可选原因）」——**没有动作的提醒只是噪音**。

## 10. 合规与风险边界（**必须先立规矩**）

1. **不构成投资建议**：全链路措辞用"**规则触发提醒**"，而非"**建议买入/卖出**"。
   例：❌"建议减仓" → ✅"你的'趋势跟踪'规则显示：已触发减仓条件"
2. **不承诺收益**：回测数据必须显著标注"**历史不代表未来**"，且不得作为宣传卖点
3. **投资者适当性**：测评属"风险承受能力评估"，结论只能用于**功能适配**，不得暗示"适合买什么"
4. **数据免责**：净值/估值延迟、数据错误的责任边界
5. **牌照边界**：判断是否触及"证券/基金投资顾问"专属业务，必要时咨询法务口径
6. **不代客决策**：所有动作由用户**手动确认**，系统不下单

### 13.1 价值判断：按「价值 / 成本」重排（正面回答"价值到底大不大"）

先给结论：**价值大，但价值不在你以为的地方。** 逐项打分：

| 候选功能 | 对用户收益的影响 | 实现成本 | 价值/成本 | 裁决 |
|---|---|---|---|---|
| **配比偏离 / 再平衡提醒** | **中**（有学术与实证支撑；强制"涨卖跌买"= 纪律内核） | 中（模型有 `portfolios`，服务要新写） | **★★★★★** | ✅ **首推** |
| **执行闭环（承诺 + 复盘）** | **中高**（把"提醒"变成"约束"的唯一机制） | 中（`next_review_date` 已有雏形） | **★★★★★** | ✅ **首推** |
| **行为反推（自检）** | **中**（不改收益，但改认知，成本极低） | **低**（数据全在库里：交易记录 + 净值） | **★★★★★** | ✅ **建议 P0** |
| 持仓诊断（只读信号） | 低-中（认知层） | 低 | ★★★★ | ✅ 做 |
| 自选异动提醒（价格） | **低**（噪声大，易致过度交易） | **低**（`WatchlistAlert` 模型已有） | ★★★ | ⚠️ 做，但**强节流** |
| 策略介绍卡片 / 心法 / 案例 | **零**（纯内容，不改变行为） | 低 | ★★ | ⚠️ **归 DOCS**，不进 APP 主线 |
| **历史回测 / 收益对比** | **低**（回测≠未来；曲线好看还会诱发追高） | **高**（长历史 + 算力 + 过拟合风险） | **★** | ❌ **后推 / 仅作解释工具** |
| 全天候策略 | 中（改善配置结构） | 高（需多资产数据层） | ★★ | 后期 |

**这就是对你"不要华而不实"最直接的回答：**

> **你最初最想要的（策略卡片内容页 + 回测收益对比）恰恰是最"看起来热闹、实际不产生收益"的两项；
> 而最能提升纪律性的三项（再平衡提醒、执行闭环、行为反推）反而不炫、甚至不需要新概念。**
>
> - **回测**：Morningstar 的缺口数据（§2.1）证明投资者亏在**行为**，不亏在"不知道历史收益"。
>   回测无论多漂亮，都不会让用户在下跌时拿住。**它的唯一正当用途是"解释规则为什么这么定"，不是"展示我能赚多少"。**
> - **策略卡片**：用户看完就忘（这正是 §2.4 说的"内容消费 ≠ 行为改变"）。
>   它的合理归宿是**文档站**（可持续运营、零 APP 负担），而不是占用 APP 的主线开发资源。

**结论：必要性成立，但要做的是"约束工具"，不是"内容产品"。**

### 13.2 形态决策（回答 Q1 / Q2 / Q3）：**内容归 DOCS，功能归 APP**

| 层 | 放哪 | 内容 | 频率 |
|---|---|---|---|
| **入口** | **APP — 产品详情页 / 持仓页 / 自选页**（小卡片） | "这只标的当前策略状态 + 一条待办" | **高频**（每次看持仓都会看到） |
| **管理** | **APP — 「我的策略」页** | 策略实例配置、信号历史、复盘记录 | 低频 |
| **内容** | **DOCS — 文档站** | 策略是什么 / 心法 / 原理 / 案例 / 名词解释 / 免责 | 按需，可长可短 |

**判据（一句话）：与用户持仓**无关**的内容，一律去 DOCS。**

- ❌ **不做"策略市场"**：浏览策略列表 = 内容消费，价值低、维护成本高。参考产品把它做成独立 Tab，是因为它要卖策略；

### 13.10 付费与合规（对你 Q17 的直接回答：**不能**）

你说"做成付费，合规尺度是不是能大一点"——**不能。这一点必须诚实。**

- **合规看"行为性质"，不看"是否收费"**。是否构成"投资建议/代客决策"由内容与动作决定，
  收费**不改变**性质。
- 而且收费会**提高**监管关注度：**收费 = 经营行为**，适用更严的适当性与宣传规范。
- **真正能"放大尺度"的不是收费，而是定位**：
  - ❌ "建议买入" → 投资建议（需牌照）
  - ✅ "你的规则触发了"（陈述客观事实）→ 工具
  - ✅ "过去 12 个月你的行为接近波段交易，与买入持有差 −8%"（陈述用户自身历史）→ 自检
  - 这**第三类**才是我们该主攻的：**陈述事实**远安全于**给出意见**，且价值不减。
- **付费的正确定位**：不是"买更大的合规尺度"，而是"**为愿意约束自己的人提供更硬的工具**"（提醒频次、多策略、执行跟踪）。

### 14.2 免费诊断的成本核算（回答"成本高不高"）

用 AGENTS.md「数据准入四问」的第 4 问 + `#826` 付费判定准则逐项核算：

| 行为反推 | `services/strategy_engine/behavior_profile.py` | FIFO 配对 → 持有天数 / 追涨比例 / 盈利卖出比例 / 提前卖出代价 |
| 接口（只读） | `GET /api/strategy/engine/strategies/`<br>`GET /api/strategy/engine/diagnosis/`<br>`GET /api/strategy/engine/behavior/` | 全部只读，不写库 |
| 单测 | `tests/services/strategy_engine/` | 纯计算用例，**不连库** |

### 15.2 一处对验收标准的**有意偏离**（已留痕）

`#2224` 原验收写「信号日志表落库 + 登记 `DATA_DOMAIN_REGISTRY`」。实现时改判为 **P0 不建表**：

1. **场景不需要**：P0 诊断是"用户打开页面看一眼"的只读场景，每次实时重算即可，**没有"上次是什么状态"的需求**；
2. **AGENTS.md「数据策略」硬规则**：新表必须有读路径，**只写不读的表禁止建立**——诊断场景下信号日志没有读者；
3. **第一原则**：数据策略由产品场景驱动，不由工程完整性驱动（`conventions.md` §16.2 禁止过度工程）。

状态持久化的真正需求方是 **P1 提醒**（那时才需要"上次状态 → 本次跃迁"），届时再建表并登记注册表，一次做对。

### 15.3 两个必须守住的口径

- **合规**：P0 诊断表达的是「**趋势当前支持的方向**」，**不是**"对你持仓的买卖指令"
  （无状态、不知道用户是否真的持有）。措辞一律「趋势成立 / 走弱 / 结束」，
  单测里有一条专门断言 reason 中**不得出现"建议"**（`test_watch_has_no_action_word_in_reason`）。
- **诚实降级**：样本不足 → `WATCH`，**不补零、不伪造日期**（`test_sma_prefix_is_none_not_zero`）。
  "用 0 兜底"会让信号在缺失数据上表现得像真有信号，属静默失真。

### 15.4 加策略的扩展路径（验证"不用从头再来"）

新增一个策略 = ① 写 `strategies/xxx.py` 继承 `BaseStrategy` ② 在 `strategies/__init__.py` 注册一次。
**核心框架、接口、诊断服务均无需改动。**
全天候属 `StrategyFamily.ALLOCATION`（配置型），届时只需扩展 `data_provider` 的多资产供给能力。
