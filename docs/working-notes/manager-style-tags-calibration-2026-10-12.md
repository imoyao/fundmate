## 1. 样本口径

- **母体**：`fund_holdings` ∩ `fund_industry_allocs` 覆盖的 **101 只基金**（= 持仓池内有季报/年报持仓数据的全部基金；两表覆盖完全一致）。
- **期数**：每只基金取**各自最新报告期**（不全局取 `max(report_period)`——与 `penetration.py` 硬口径 5 同一纪律）。实际分布：持仓 2026Q2 为主（6,389 行），行业配置 2026Q2 为主（823 行）。
- **披露口径**：`holding_basis` = `full` 100 只 / `top10` 1 只（2026Q2 半年报全量披露占绝对多数）——前十大集中度在 full 口径下 = 按占净值比降序取前 10 求和。
- **不完整样本剔除（集中度维度）**：`161115` 是唯一的 `top10` 口径基金，但最新期只有 **4 行**持仓（应为 10 行，疑似抓取不完整）——按 4 行合计会系统性低估集中度。处理：**标定样本剔除该基金（n=100），运行时判据同规则回 `None`**（`top10` 口径不足 10 行 → 集中度维度不出标签，装配侧闸门在 `manager_holdings._build_style_labels`）。剔除前后分位漂移 ≤0.3pp，四舍五入后阈值仅 P80 由 65.78→66 一处理论差（原全样本 65.78 若四舍五入亦为 66）。`full` 口径不足 10 行**不适用**此闸门——全量披露下基金真持有不足 10 只时，合计值就是其真实集中度。
- **行业体系**：只取 `scheme='csrc'`（证监会门类），**不与 gics 混算**（penetration 硬口径 2）。99/101 只有 csrc 行业数据，2 只缺失 → 行业维度回 `null`。
- **市值分桶**：`index_constituents` 中 `000300`（300 只）/ `000905`（500 只）/ `000852`（1000 只）成分归属，规则：`large = ∈300`；`mid = ∈500 且 ∉300`；`small = ∈1000 且 ∉500 且 ∉300`；其余（含港股、债券、未入指数股）为**未覆盖**。

### 关键边界事实

- 集中度存在极低值（min 0.10%）：持仓池内的债基/货基，股票仓位极低。其「分散」标签在字面与数据上均成立，**不额外做基金类型豁免**（豁免规则属主观例外，违反「可复算」原则）；若后续产品认为债基不应展示风格标签，应另立卡按 `fund_types` 过滤展示层，不动判据。
- 市值覆盖率 <60% 的基金有 23 只（主要是重仓港股的 QDII/沪港深基金——港股代码不在 A 股成分表内）、覆盖率为 0 的 7 只 → 这 30 只（去重后 78 只通过）**size 维度回 `null`**，与「覆盖率不足时不猜」的降级纪律一致。60% 门≈全库 P25（61.9），取整为 60。

## 3. 阈值 → 判据的映射（`manager_style.py` 实现口径）

| 维度 | 档位 | 条件（含边界） | key | 中文标签 |
|---|---|---|---|---|
| concentration | 低 | `top10 < 50` | `concentration_low` | 持仓分散 |
| concentration | 中 | `50 ≤ top10 < 66` | `concentration_mid` | 持仓中性 |
| concentration | 高 | `top10 ≥ 66` | `concentration_high` | 持仓高集中 |
| industry | 低 | `top1 < 60` | `industry_low` | 行业分散 |
| industry | 中 | `60 ≤ top1 < 81` | `industry_mid` | 行业中性 |
| industry | 高 | `top1 ≥ 81` | `industry_high` | 行业集中 |
| size | 中小盘 |覆盖率 ≥60 且 `300占比 < 36.5` | `size_small` | 偏中小盘 |
| size | 均衡 | 覆盖率 ≥60 且 `36.5 ≤ 300占比 < 67.4` | `size_balanced` | 市值均衡 |
| size | 大盘 | 覆盖率 ≥60 且 `300占比 ≥ 67.4` | `size_large` | 偏大盘 |

- 边界归属统一：**下界含本档**（`≥` 进高档、`<` 留低档），保证任意实数值恰好命中一档。
- 指标值缺失（`None`）、越界（`<0` 或 `>100`）→ 视为缺失，**该维度不产出标签**（issue 问题 3：回 `null`，不猜、不用默认值填充）。
- 每个标签带 `basis` 依据文本，格式：`{指标中文名} {值:.1f}%，{分位注记}`（如「前十大重仓 65.8%，全库 P80」）。**不含颜色**——配色由前端令牌决定，后端不返回颜色（第一期转换层硬约束）。

## 4. 成长/价值维度：本期不实现（数据不足）

穿透（`penetration.py`）产出的是**行业/个股两层**，不含任何成长-价值属性；`securities` 表无市值/估值/风格字段；全库无风格箱类表（`sqlite_master` 按 `%style%`/`%cap%`/`%mkt%` 检索 0 命中）。**按 issue 问题 3 规则，该维度数据不足 → 判据不实现、不产出字段**，待未来有每股估值/风格主数据后再以增量方式补维度（判据模块按维度独立，新增维度不影响既有档位）。

> 与 2026-10-12 issue 评论的差异说明：评论建议答案 1 中把「成长/价值」列为可选维度（依赖穿透数据）；本轮真库核查确认穿透不含风格属性，故**降级为「不实现」而非「实现后恒回 null」**——不产出没有读路径的字段（数据策略硬约束 1 的代码侧同理）。

## 5. 换手率：放弃（有据）

- 库内无调仓流水（`fund_holdings` 每只 1 期，跨期对比无从谈起；`fund_position_job` 从未多期回填）。
- fundfof 无基金级换手率端点（`fundfof_crowding` 的 `turnover_rate` 是**行业级**，已在温度计使用）。

## 6. 复现方式

计算为只读单次脚本（sqlite3 `mode=ro`，纯标准库），过程伪码：

```text
1) 每基金最新期 := max(report_period) GROUP BY fund_code（持仓、行业配置各自独立取）
2) top10_ratio := sum(降序前10的 ratio)（full 口径）；basis 记录披露口径
3) top1        := max(csrc ratios)；hhi_norm := sum((r/Σr×100)²)（仅旁证）
4) size 分桶   := holdings JOIN index_constituents(000300/000905/000852)，ratio 按桶求和
5) 分位数      := 线性插值（(n-1)×p/100），对 101 只全样本
```

逐基金明细快照（101 行 CSV）存于本次会话临时目录，未入库——阈值如需复算，按上述伪码重跑即可（数据只随报告期更替缓慢变化，阈值应**低频重标**，建议随「持仓多期回填」落地后复标一次）。

## 7. 数据准入四问（新增判据字段的自证）

1. **谁在用？** 基金经理详情区块（#1970 一期卡片）的风格标签行，`GET /api/products/manager-profile/` 消费。
2. **什么场景用？** 用户打开基金经理页，扫一眼代表作的持仓/行业/市值风格，辅助选基。
3. **缺了会怎样？** 数据不足维度回 `null`，前端显示「—」，卡片其余信息不受影响——降级可接受。
4. **成本多大？** 零新增抓取、零新增表列；判据为纯函数，请求路径上无额外 DB 查询（指标由既有两张表装配）。
