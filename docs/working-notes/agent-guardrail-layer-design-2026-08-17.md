## 1. 背景与动机

账本精灵（对话 Agent）要对用户账本做「查询 / 表现分析 / 行为解读 / 快速记账」。其最大风险不是技术，而是**用户预期管理**——模型把主观判断包装成「分析 / 数据显示」自信输出，用户误读为投资建议，产生「你让我卖亏了」式投诉。

与同花顺「账本精灵」的多轮对标（见备忘第十~十七轮）给出两个决定性结论：

1. **纯 prompt 约束拦不住越界**。同花顺自承边界靠 `SOUL.md`/`AGENTS.md` 的 prompt 软约束，却在真实对话中反复越界（直接给「该卖 / 清仓」结论、评价基金经理「平庸」、给机械止损百分比），仅当用户敏锐反驳才被动纠偏。这证明**不能信任模型在安全边界上的自我声明，必须硬过滤**。
2. **模型在边界触发后会产「通识填充」内容**（答不出准确内部实现时，用行业通识填充而非说「不知道」）。说明输出侧过滤是必须项，且要能识别「伪装成分析的建议」，不能只匹配「买 / 卖」字样。

本项目相对同花顺有架构优势：现有 `ai_recognizer` 已用**代码隔离**做硬护栏（模型只收结构化字段不碰 DB、写操作走 importer 且前端逐行确认），比同花顺纯 prompt 更硬。本设计在此地基上，补上「输入侧意图护栏 + L3 输出侧词法过滤」两道新增硬防线，形成完整分层。

## 2. 分层护栏总览

护栏从「最软（可绕过）」到「最硬（架构/代码强制）」分五层，越靠后越不可绕过：

| 层 | 机制 | 硬度 | 当前状态 |
|---|---|---|---|
| L1 Prompt 软约束 | 数据真实性铁律（可复用同花顺原文措辞） | 最软（模型可不听） | 待注入 system prompt |
| L2 工具可用性 | 无预测 / 建议类工具，模型无从编造数据支撑 | 较硬（天然成立） | 现有工具均只读 / 计算，天然满足 |
| 输入侧意图护栏 | A 意图分类 / B 模式命中 / C 重复追问 / D 情绪+建议复合 / E 通用知识补数据 | 硬（前置拦截，预测建议类不进模型） | 待建 `safety/` |
| L3 输出侧词法过滤 | 扫描生成文本，拦截预测 / 建议 / 评级 / 收益承诺 | 最硬（最后兜底，无法绕过） | 待建 `safety/output_filter.py` |
| L0 代码隔离 | 模型不直接碰 DB、写操作走 importer + 前端确认 | 最硬（架构强约束） | 已有（`ai_recognizer` 现状） |

设计原则：**L1 可复用同花顺原文做低成本 prompt 工程；L2/L0 是既有地基；输入侧意图护栏与 L3 是本次新增的硬防线，二者配合覆盖「模型不听 prompt 时」的所有越界路径。**

## 3. L0 代码隔离（已有，地基）

- 模型只接收结构化抽取字段（如交易候选行），绝不整库外传；不直接操作 `positions` / `transactions` / `assets` 等业务表。
- 写操作（记账 / 修改持仓）一律走 importer 管线 + 前端逐行人工核对，无自动入库后门（呼应 AGENTS.md「禁止 skip_lot_check 类后门」）。
- 护栏权限 / 配额 / 限流集中在 `ai_recognizer/guards.py`（网关层），工具内不判权限（呼应同花顺 C2 结论：权限校验放网关非工具内）。
- 「快速记账」≠「免核对」：识别出的日期 / 金额 / 份额前端必须逐行核对。

## 4. L1 Prompt 软约束（数据真实性铁律）

复用同花顺 `AGENTS.md`「数据真实性铁律」原文，核心要点直接抄入精灵 system prompt（省去自拍措辞的试错成本）：

- 开头否定模型「我知道」的幻觉：「你是一个没有用户实际数据的 AI 模型……一无所知」；
- 核心原则「工具先行，数据为真，严禁编造」；
- 规则采用「禁止 XX + 应该 XX」双结构（不只说不许做什么，还说该做什么）；
- 「工具失败如实说……绝对禁止用模型自身知识推测或补全数据」；
- **最管用一句**：「宁可说『我不知道』，不可编造答案」——给模型安全出口，否则模型倾向硬编；
- 自查清单（回复前三条逐条确认：有无数字全来自工具返回？有无提持仓全来自查询？有无「觉得应该」而非工具返回→删除）。
- 附「can / cannot 边界清单」（复用同花顺自划）：✅ 能查已发生数据、帮梳理行为模式、提供思考框架、查公开信息；❌ 不能预测涨跌、不能评判基金经理好坏、不能给买卖建议、不能保证策略有效。

> 注：L1 软约束**必须**与 L0 代码隔离 + L3 词法过滤配合。同花顺实证单靠 L1 会越界，本项目不抄这套 prompt-only 做法。

## 5. L2 工具可用性约束（天然成立）

- 现有 `ai_recognizer` 与计划中的对话工具，全部是「只读查询 / 纯计算」型（查持仓、算 XIRR、查净值），**不注册任何预测 / 建议类工具**（无「预测涨跌」「荐股」「买卖评级」工具）。
- 模型想越界也拿不到数据支撑——这是比 prompt 更硬的约束。但同花顺实证「模型用通用知识编造」可绕过 L2（不调工具也能编），故 L2 不能单独依赖，须 L3 兜底。

## 6. 输入侧意图护栏（新增）

从同花顺自认「prompt 拦不住」的五类场景提炼，作为**请求进入模型前**的前置拦截。命中后直接阻断或不进模型，比 L3 更早、更省 token。

- **A 意图分类**：将用户消息分类为「数据查询 / 通用知识 / 预测 / 建议 / 情绪施压」。预测与建议类直接拦，不进模型。
- **B 模式命中**：正则命中越界句式（「会涨 / 会跌 / 推荐 / 评级 / 该不该 / 如果我是你 / 你觉得…会」等）→ 拦。须识别「伪装成分析的建议」（confident analytical framing），而非仅匹配字面「买 / 卖」。
- **C 重复追问检测**：同一问题（归一化后）连续追问 N 次 → 强制标准话术（模型不再自由发挥），防「反复追问软化」式越界。会话内状态，可内存或 Redis。
- **D 情绪 + 建议复合**：情绪词（焦虑 / 慌 / 亏惨了 / 怎么办）+ 建议意图 → 强制插入风险提示 / 免责声明后再回复，避免模型顺情绪给安慰式建议。
- **E 通用知识补数据检测（输出侧辅助）**：若回复涉「当前市场判断 / 具体标的该不该动」却未调用任何数据工具 → 拦，防模型用训练知识补用户数据（十六节实证该场景高频）。

## 7. L3 输出侧词法过滤器（新增，最硬）★

L3 是最后一道、不可绕过的防线：模型生成的**最终回复文本**在返回用户前，经 `output_filter.py` 扫描。即便 L1 失效、模型不听 prompt，L3 仍兜底拦截越界内容。

### 7.1 设计原则

- **只拦「预测 / 建议 / 承诺 / 主观评价」类意图，不拦「客观数据陈述」**。区分判据：是否含未来方向判断、是否对用户的资产动作给出指令、是否对标的 / 经理做主观褒贬。描述已发生事实（「本周下跌 2%」「近一年收益 -5%」）一律放行。
- **识别 confident analytical framing**：模型会把建议包装成「数据显示你应该…」「从数据看，最佳做法是…」，须用「第二人称 + 建议动词 / 最佳 / 理应 / 不妨」组合命中，而非仅匹配「买 / 卖」。
- **命中即拦截，强制替换为预设免责声明**，不把越界文本透传给用户；同时记录命中日志供审计。
- **避免误伤**：数值、事实陈述、框架性提问（「你可以看看行业集中度」）放行；仅当建议动词 + 第二人称 / 动作指令同现时拦。

### 7.3 命中后行为

- 单次命中：整句 / 该段替换为对应预设免责声明（按类别取模板），其余合规内容保留，不整篇拒答（避免体验崩坏）。
- 多次 / 高频命中（同会话）：升级为「标准话术」+ 置顶免责声明，并记录 `guard_hit` 审计日志（类别 / 命中规则 / 原始片段脱敏）。
- 拒绝透传任何越界原文，绝不把「模型差点说出的建议」暴露给用户。

### 7.4 实现要点

- `output_filter.py` 输出 `(blocked: bool, hit_rules: list[str], sanitized_text: str)`，在 `llm.py` 返回链路末端统一调用（对话 Agent 模式新增，识别器模式暂不需要）。
- 中文正则须处理全角 / 半角、空格、标点变体；建议动词列表与否定词（「不建议」属正常提醒，需白名单豁免）分离管理。
- 过滤器本身**无状态、纯函数**，便于单测（mock 生成文本断言拦截 / 放行）。
- 预置免责声明模板集中常量管理，与产品层固定文案（UI 置顶免责组件）保持一致口径。

## 8. 模块落点（代码）

现有 `backend/app/services/ai_recognizer/`：`base.py` / `guards.py` / `llm.py` / `registry.py` / `schemas.py` / `catalog.py` / `recognizers/`。新增 / 扩展：

```
ai_recognizer/
├── safety/                        # ★ 新增：护栏子包
│   ├── intent_guard.py            # 输入侧 A（意图分类）+ B（模式命中）
│   ├── output_filter.py           # L3 输出侧词法过滤（§7）
│   └── repeat_tracker.py          # C 会话内重复追问检测（内存 / Redis）
├── guards.py                      # 扩展：加 per-user token 配额（I1 债）+ 网关层拦截
└── registry.py                    # 扩展：引入意图路由（A 前置分类，对话精灵用）
```

- 输入侧 D（情绪+建议复合）、E（通用知识补数据）可落在 `intent_guard.py` 与 `output_filter.py` 的协同逻辑中：D 由意图分类识别情绪 + 建议复合后插风险提示；E 由 output_filter 检测「未调工具却涉市场判断」拦截。
- `guards.py` 现有全站 `ARK_DAILY_TOKEN_BUDGET=300000` 无 per-user 维度、且 SCF 多实例计数器按实例重置（I1 债）。须加 per-user 配额表 + 网关层拦截，防止单用户击穿预算。
- `registry.py` 当前静态 `scenario`（watchlist_import / txn_import），对话精灵需引入意图路由：A 前置分类结果决定走「查询工具链」还是「直接拦截 / 标准话术」。
