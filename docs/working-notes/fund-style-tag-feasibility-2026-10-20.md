# 基金风格标签（投资风格箱）数据获取可行性评估

> 调研日期：2026-10-20 ｜ 方法：韭圈儿 APK 逆向成果（154 个免登录端点清单）+ 公开 API 实测
> 结论口径：只接 App 自身标记 `need_login:!1` 的端点；不破解签名/鉴权（沿袭 2026-09-09 既定口径）

---

## 1. 结论（先行）

**能拿到，且形态比预期好。** 韭圈儿免登录 API `/v2/tubiao/get-style-history` 提供**晨星式 8 分类投资风格箱 + 成立至今的完整月度历史**，实测 9/9 基金全覆盖（主动/指数/债基/货基/QDII/新基金）。天天基金公开 API **无**风格箱数据（实测只有持仓明细与基本信息），韭圈儿是当前唯一实测可用的免费完整源。

**价值判断（买方视角）**：对**主动基金**高价值——风格定位（筛选）+ 风格漂移监控（纪律性）+ 组合风格透视（差异化）；对指数基金增量低（风格由成分股决定，箱体即宽基映射）。

**建议接入，分三层推进**：当日风格定位（筛选/详情页）→ 全历史一次性落库 → 组合层加权暴露。编辑标签体系（`getalltags`）**本期不做**（见 §5 剔除项）。

## 4. 诚实披露的存疑点（反向压力测试）

1. **QDII 映射异常**：270042 广发纳斯达克100 → 韭圈儿给出「固收风格 81.28 / 大盘成长 18.72」，明显不合理（应为大盘成长主导）。**韭圈儿对海外资产的口径处理存疑** → 展示层须注明数据来源，QDII 基金不作为风格筛选依据。
2. **口径未公开**：韭圈儿的风格暴露计算方法（持仓映射 or 净值回归）未披露；与晨星箱的差异未知（可对同一基金交叉验证，但无晨星免费源）。
3. **私有接口无通知变更风险**：沿袭行业恐贪先例——契约留档 + job 失败记 errors 不阻断 + 展示层标注来源；**不做跨年回测级依赖**。
4. **数据所有权**：风格标签是韭圈儿算的，落库时应带 `source` 字段留痕，展示层注明「数据来源：韭圈儿」。

## 5. 价值评估：保留 vs 剔除（买方视角）

### 保留（高价值）

| 场景 | 用户收益 | 落地形态 |
|---|---|---|
| **主动基金风格定位** | 用户按自己的风格偏好（如"大盘价值"）筛选/匹配基金，填上 fundmate 缺失的基础数据维度 | Fund 派生标量 `dominant_style`；筛选器风格维度 |
| **风格漂移监控** | 纪律性：基金经理宣称的风格 vs 箱体实际漂移（000001 从混合暴露→中盘成长 100 即实例），可视化 + 偏离提示 | 详情页风格漂移图（283 点全历史已含） |
| **组合加权风格暴露** | 与用户记账持仓结合的**组合级风格透视**——"我的组合实际是什么风格"，市面 App 少有，差异化 | 组合页/探市页：持仓份额加权 8 箱暴露 |

### 剔除（看着热闹实际意义不大）

| 项 | 剔除理由 |
|---|---|
| 指数基金风格箱展示 | 风格由成分股决定，箱体即宽基映射（510300→大盘成长45.6/大盘价值18.0），信息增量低；仅组合层汇总时顺带经过 |
| `getalltags` 编辑标签体系 | 韭圈儿编辑观点（"机构青睐""亮点选基"），带主观性，非结构化风格属性；接入后维护的是别人的 editorial 口径 |
| 东财持仓自算风格箱 | 需全市场个股市值/PB 快照 + 归因计算，工程量大；且季频持仓滞后于月度箱体 |
| 全市场 1 万只一次性回补 | 无消费场景的数据扩展（用户明确反对）；按「核心池 + 用户自选/持仓」范围抓取 |

## 6. fundmate 接入设计（草案，待拍板后实施）

### 6.1 存储层（对齐既有先例）

- **新表 `fund_style_exposures`**（long 格式，对齐 `MarketSingleValue` 与「存储层保留原始数据」原则）：

  | 字段 | 说明 |
  |---|---|
  | fund_code | 基金代码 |
  | stat_date | 上游时点（月末/当月最新，原样） |
  | style_name | 上游原文（'大盘成长'…'固收风格'，不做本地枚举硬编码） |
  | value | SafeNumeric 暴露值(%) |
  | source | 'jiucaishuo_style' |
  | — | UniqueConstraint(fund_code, style_name, stat_date)，同日重复 save 去重 |

- **Fund 派生标量**：`dominant_style`（当前主导风格）+ `style_period`（口径与版本留痕）——对齐 `equity_position` 的「明细是源、标量是派生，无源即不派生」模式（models.py L118-133 先例）。

### 6.2 采集层

- **adapter**：`jiucaishuo_adapter.py` 增加 `fetch_fund_style_history(fund_code)`（复用现有节流/重试/UA 约定；`cycle='1y'`）。
- **job**：`FundStyleSyncJob`——首次**一次性全量回补**（目标池范围，见待拍板 2），其后**月度增量**（对齐 `FundPositionSyncJob` 核心池逐只先例；`category_lists` 日期轴用于断点续传，只补缺失时点）。
- **断档防护**：本数据是**一次性全历史**，断档即永久缺口——回补 job 失败记 errors，落库进度可观测（对齐行业恐贪的 freshness 思路）。

### 6.3 展示层（按优先级，非本期全做）

1. 基金详情页：当前风格箱 + 漂移趋势图（**可并入 #1968 基金详情页二次扩展**）。
2. 筛选器：风格维度（探市/自选页基金列表按 `dominant_style` 过滤）。
3. 组合页：持仓加权 8 箱暴露条形图。

### 6.4 改动量预估

| 层 | 文件 | 量级 |
|---|---|---|
| adapter | `jiucaishuo_adapter.py` | +~60 行 |
| models | `domains/funds/models.py` 新表 + Fund 2 字段 | +~30 行 |
| job | `services/sync/jobs/fund_style_job.py` 新建 | +~80 行 |
| service | `fund_style_service.py` 新建（save/latest/history/组合加权） | +~120 行 |
| 测试 | 离线单测（解析/去重/回补断点/组合加权） | +~150 行 |

## 7. 待拍板

1. **存储形态**：long（fund_code, date, style, value）vs wide（8 列一行）？——我倾向 **long**（上游风格名原样、集合可变时免迁移，与 `MarketSingleValue` 先例一致）。
2. **抓取范围**：核心池 + 用户自选/持仓（对齐 `FundPositionSyncJob` 先例）vs 全市场？——我倾向**前者**；全市场 1 万只 × 283 点属无消费场景的数据扩展。
3. **展示优先级**：先做「详情页风格箱+漂移图」（并入 #1968）还是先做「筛选器风格维度」？——我倾向**先详情页**（数据消费的最小闭环，筛选器依赖 `dominant_style` 派生标量，可随后）。
