# 分红未记扣税提醒（2026-10-19，CNB duoduobei/fundmate#541）

## 用户的原话与取舍

> 「如果说我们不自动的话，可以在对账台或者是哪些地方对用户进行一个提醒，或者说首页的
> 消息条里面进行一个提醒，让他知道他有一些……没有进行扣税处理的登记。」

即：**不自动算税**，改为**提醒 + 让用户自己补记**。这一条把「要不要做」定死了，
剩下的只是「怎么判、判完放哪」。

## 为什么坚决不自动算税

A 股股息红利税按**实际持股期**在卖出时补扣（≤1 月 20% / 1 月~1 年 10% / >1 年 0）。
要算准，必须知道每一笔分红对应的每一份股份是哪天买的——**lot 级批次账**。
本系统只有：

- `positions`：成本均价 + 聚合份额；
- `transactions`：流水，无批次归属。

在聚合持仓上按某个税率反推，产出的**不是税，是一个会被交易所按先进先出否掉的猜数**。
给它记一笔负数，等于污染已实现盈亏、股息率、XIRR，且用户无从分辨哪笔是券商真值。

> 判据：**宁可账上少一笔税（用户一眼能看出「这儿还没记」），也不要多一笔假税
> （用户以为已经算过了）。** 前者可以补，后者没人会去查。

## 判据：只问「这一年记没记过税」

| 步 | 做什么 |
|---|---|
| 1 | 取 `txn_type='dividend'` 的**现金分红**（排除红利再投：同 `link_group_id` 有 `buy`） |
| 2 | 按 `(symbol, account_name, 分红所属年)` 分组 |
| 3 | 同键存在 `txn_type='dividend_tax'` ⇒ 视为已结清，不报 |
| 4 | 否则报出来，按金额降序 |

两个刻意选择：

- **按年、不按笔**：券商的「股息红利差异扣税」常是多笔合并成一条，且扣税日晚于分红日数周。
  逐笔一一对应必然误报 ⇒ 退一步问「这一年有没有记过税」。
- **只看现金分红**：红利再投份额已增加，没有现金税这回事；拿它催用户补一笔现金支出是错的。

回溯窗口 400 天：更早的税早在券商交割单里结清了，催一年以上的旧账没有意义。

## 放在哪

| 位置 | 形态 |
|---|---|
| 对账工作台 **域 E**「分红未记扣税」 | 实时派生列表（不落差异表），每项含标的/年份/分红合计/笔数/最近一笔日期 |
| 首页消息条 + 消息盒 | `notifications` 表，`level=P1`、`category=system`、`source_type=dividend_tax_pending` |
| API | `GET /api/reconciliation/dividend-tax/`（读列表，**顺带幂等写一条提醒**） |

**不落 `reconciliation_discrepancies`**：那张表描述「应然 vs 实然」的差额，
而本域**没有应然值可算**（我们不推算税率）。硬塞进去会造出一列假的「应有税额」，
正是这次刻意不做的事。

## 一个刻意的例外：GET 里有写

`/api/reconciliation/dividend-tax/` 在读列表时调 `refresh_reminders` 写通知。
通常写操作不该藏在 GET 里（会被预取/重试，`strategy_engine` 那边就是这么坚持的）。这里放行，是因为：

- 写的是**幂等通知**（`dedup_key` 含年份），重复读不会刷屏；
- 它不改变对账结果，只决定「用户会不会知道有这回事」；
- 触发点只有对账台 —— 用户主动来查差异的地方，若这里都不写，首页永远等不到那条消息。

真正的写操作（补记扣税流水）仍然只有用户手动。

## 已知边界（没做）

- **不判断「该扣多少」**，也不给建议税率区间 —— 给了就会被当成答案。
- **不识别「配股不缴款」**（属另一件事，见 PR #581 的边界说明）。
- 同一账户同一标的**跨年**会各提醒一次（这是有意的：每年独立申报）。

## 2026-11-08 修正：判据缺了「卖出」这个前提

> 用户的原话：「超过一年之后，好像不扣税。比如海大集团这只股票，我现在看交割单里好像
> 没有扣税，只有红利入账的 30 块钱。」「可能我们之前的逻辑写错了？」

**写错了。** 上面那版判据只问了「这笔分红配上税没有」，漏了税收**什么时候**发生。

### 制度事实（财税〔2015〕101 号，原文第二条）

> 上市公司派发股息红利时，对个人持股 1 年以内（含 1 年）的，
> **上市公司暂不扣缴个人所得税**；待个人转让股票时，证券登记结算公司根据其持股期限
> 计算应纳税额，由证券公司等股份托管机构从个人资金账户中扣收。

也就是说，**派息那一刻账上本来就没有税**，税要到**卖出**时才由券商扣。持股 >1 年免税；
1 个月~1 年实际税负 10%；≤1 个月 20%。

旧判据把「法定暂缓」当成了「用户漏记」——于是每一笔仍在持有的分红都在催，
用户翻交割单找不到税，只能怀疑系统坏了。海大集团那 30 元就是这么被误报的。

### 新判据：先问「卖出过没有」，再问「配没配上税」

| 该标的该账户在分红日之后… | 手上有没有税 | 结论 | 进待办 |
|---|---|---|---|
| 没卖出过 | 无 | `暂不扣税`（法定暂缓） | 否 |
| 没卖出过 | 有 | `已记-比例异常` 复核 | 是 |
| 卖出过，持股 ≤1 年 | 无 | `待核对`（漏导入 / 券商未扣） | 是 |
| 卖出过，持股 >1 年 | 无 | `依法免税` | 否 |

关键认识：**这里不需要 lot 账**。只要没卖出，「一定没扣」是 101 号文给的确定性，
与先进先出无关；只有「已卖出」才轮到持股期，而那一刻账上有没有那笔税是**看得见的事实**，
直接读交割单即可。所以本系统「不推算税率」的立场没有动摇 —— 我们只是把「该不该有税」
这个是非题问对了。

### 配对窗口锚定到卖出日

原来窗口是 `分红日 + 30 天`，隐含假设「扣税紧跟分红」。实际可能持有 11 个月才卖、
卖时才扣。窗口上限改为 `max(分红日 + 30 天, 末次卖出日 + 5 天)`：30 天内的场景不放大窗口
（既有边界与误报边界不变），长持有场景由后半段兜住。

### 持股期粗判的偏差方向

用「持仓快照 `confirm_date` → 分红日」的间隔近似持股期（无 lot 账，取不到精确批次）。
偏差方向**刻意倾向判免税**：宁可少记一笔税（用户看得见「这儿没记」），
也不要多记一笔假税（用户以为已经算过了）——与上面那条判据同源。

### 不记「0 元扣税」

用户问过「记一笔 0 元还是当没有」。答案是**两者都不对**：0 元在税法上不是
「交了 0 元税」，而是「无需纳税」，是两个不同的法律事实。记 0 元会：

- 虚构一次现金流出，污染已实现盈亏 / 股息率 / XIRR；
- 将来真卖出被扣税时，那笔 0 元还会在配对时抢走额度（`_match_taxes` 按额度消耗）。

改成落一条**确认事实**（`dividend_tax_acks`，只存 `symbol + account_name + dividend_on`，
撤销即删行，照 `GhostDuplicateIgnore` 的形态），扫描时排除。

> **踩过的坑**：`account_name` 是这条确认的身份之一。分红流水的账户名会被自动回填成
> 账本名，前端若只回传 `symbol + dividend_on`，后端查不到、接口照样 200、下次刷新照旧
> 被催——**没有任何报错**。两个入口（表格行、处理区）都回传账户名，并各有一条源码断言钉住。

### 基金分红不该问这个（财税〔2002〕128 号）

「投资者从基金分配中取得的收入，暂不征收个人所得税」（该优惠经财政部 税务总局
公告 2018 年第 177 号确认继续有效）。免税品种白名单原来漏了 `fund`，
所有基金/ETF 分红都被报成「未扣税」——**既有的
`test_ordinary_fund_dividend_still_pending` 还把这个错误前提固化成了反向断言**，
现已改名为 `test_ordinary_fund_dividend_is_exempt` 并翻转断言。

### 验证

- `tests/services/test_dividend_tax_service.py` 63 例 + `test_dividend_tax_import_hook.py` 6 例；
- 回退探针三处**全部 CAUGHT**：去掉「未卖出⇒暂不扣税」分诊（4 例红，含导入钩子）、
  去掉基金豁免（2 例红）、窗口不锚定卖出日（1 例红）；
- 首次变异「4 passed」是假绿：锚点未落盘（`write_text` 对 CRLF 的处理），
  改成按行定位 + `assert` 校验落盘后才咬住；第二次变异只删了 `deferred.append`
  却漏了 `continue`，落到 `max([])` 抛异常被钩子的 `except Exception` 吞掉 → 也假绿。
  **变异必须确认「真的应用了」且「不是被兜底吞了」。**

### 呈现：域 E 改名 + 两类折叠

- 域标签 `分红未扣税` → `红利税核对`。旧名现在会误导：列出来的已经不是「未扣税」，
  而是「已卖出却没配上税」。
- `暂不扣税` / `依法免税` **不进待办**，只在表底折叠成一句
  （「另有 N 笔仍持有…、M 笔持股已满一年…」）。全藏起来会让人以为分红没被识别
  （owner 就曾对着「只有红利入账」怀疑系统漏记）；全列进待办则这个列表永远清不完。
- 每条真待办给两个动作：「补记这笔税」（原有）与「确认无需记账」（新增，落 ack 表）。
- 撤销走 `POST /ack/revoke/` 而不是 `DELETE /ack/`：前端 `PureHttp` 只暴露 get/post，
  `http.delete` 在运行期才会炸。
