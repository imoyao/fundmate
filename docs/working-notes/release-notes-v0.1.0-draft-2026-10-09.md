# v0.1.0 Release Notes（草稿，待用户定稿）

> 用途：作为 `v0.1.0` 的 Release notes body，经 `bridge-feedback.yml` 自动同步为 FeedLog 首条 changelog 条目。
> 写入方式：`.github/workflows/bridge-feedback.yml` → `release-to-changelog` job。
> 注意：标题会被 `create_changelog_entry()` 截断至 70 字符（`varchar(70)`）。

---

## 首条 entry 的定位（重要）

第一版 changelog **不是「变更记录」，是「产品介绍」**。

- 没有前序公开版本 ⇒ 「变化」没有参照系，读者不知道「以前是什么样」
- 所以分类徽章**只能用 `New`**（`Improved` / `Fixed` 在没有前序版本时是无意义的）
- 目的：回答「这到底是什么东西、能帮我做什么」，而不是罗列 413 个issue

## 草稿正文（Benefit-led 变体，约 170 词）

```markdown
## 多多贝 0.1.0 —— 家庭投资理财的账本精灵

**把散落在不同平台的钱，合成一你自己看得懂的账。**

### ✨ 现在可以做什么

- **多账户合并算总账**：把银行、券商、基金、投顾账户归到一起，看到家庭真实的
  总资产与真实收益率（XIRR 资金加权，精确到日），不用再自己对着几张表加总。
- **持仓穿透到底层**：买了几只基金，能看到它们最终压在哪些行业和个股上，
  持仓市值占比一目了然。
- **一句话就能问**：「我的钱现在亏了多少」「哪些该减了」，账本精灵直接读你的
  真实数据回答，不给泛泛而谈的建议。
- **导入不用手敲**：券商流水、盈米等同花顺数据都能导进来，自动对齐。

### 还在早期

这是预览版，功能会持续调整。你遇到的问题、想要的功能，都可以反馈给我们，
每一条都会被认真读。

[提交反馈](https://feedback.duoduobei.com)
```

## 为什么这么写（对照取舍）

| 写法 | 问题 |
|------|------|
| 罗列 413 个 issue | 读者没有任何前序参照，全部无法解读 |
| 按模块罗列（资产/基金/导入/温度计…） | 这是**开发视角**不是用户视角 |
| 「我们完成了 2327 次提交」 | 没有人关心 |
| ✅ 按「用户能干什么」组织 | 每条都回答「这对我有什么用」 |

## 待你确认的三处

1. **要不要提「免费」**：目前定价未定，如果定价策略未定，暂不提
2. **要不要提温度计/探市**：这是已上线的独立能力，可作为第4 条，但我担心条目变长
3. **「早期」段落措辞**：现在的写法比较直白，FeedLog官方文档强调 AI 起草要避免
   夸大收益，本条严格照此办
