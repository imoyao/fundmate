# 红利税提醒：从「按年一次」改成「逐笔 + 导入即提醒」（2026-10-19，CNB duoduobei/fundmate#541）

> 上一篇 `dividend-tax-reminder-2026-10-19.md` 定的是「不自动算税，改为提醒」。
> 这一篇修的是那个提醒**本身不成立**的地方。

## 用户的原话

> 「你说的这个跨年提醒一次，这个是会持续提醒吗？我的想法是，分红之后，一般扣税大概在
> 一周之内就会进行吧……而不是说你等到一年。……不能每年等到都过了几个月了再去提醒用户，
> 那这个消息有什么价值呢？**最重要的是消息的提示及时性和幂等性，不能重复提醒，也不能漏提醒。**
> 还有……同花顺这种，它会把扣税信息直接记录进来，相当于我们已经扣过税了，
> 你要能够识别出来，防止误提醒，让用户双重记账。」

三条要求，逐一对应到判据：

| 要求 | 原实现 | 现在 |
|---|---|---|
| 及时 | `dedup_key` 含**今天**、按**年**匹配 ⇒ 一轮轮刷、又跨年才有效 | 逐笔匹配；键钉在**分红日**；导入完成即复核 |
| 幂等 | 键含今天 ⇒ 同一笔分红每天一条新消息 | 键不含今天 ⇒ 同一笔永远一条 |
| 不误提醒（导入已带税） | 同标的**同年**记过税就整年闭嘴 | 逐笔配对：那笔配上了才闭嘴，没配上的照报 |

## 一、按年 → 按笔（核心修正）

原判据是「同标的同一年有 `dividend_tax` ⇒ 视为已结清」。实测后果：

- 一年分两次红、只扣了一次税 ⇒ **第二次永远不提醒**（要等到明年）；
- 用户投诉的「过了几个月才提醒」不是延迟，是**根本没有**。

现在配对到**每一笔分红**上：同标的 + 同账户 + 扣税日 ∈ [分红日, 分红日 + 30 天]，
一笔扣税只能用一次（用金额当额度）。分红按**金额降序**配对 —— 税按股息金额收，
合并扣税应先结清大额那笔，否则大额的税会被藏在尾巴里。

**合并扣税不猜对应关系**：券商把多笔分红合成一条「股息红利差异扣税」时，
两笔里必有一笔配不上，它会被继续报出来。这是有意的取舍 ——
**宁可多提醒一次（用户看一眼就关），不可漏提醒一笔（钱就少记了）。**

## 二、幂等：键里不能有「今天」

上一版的 `build_dedup_key(SOURCE_TYPE, f'{symbol}:{year}', today)` 把今天拼进键里，
等于「同一笔分红每天一条新提醒」。等价于用户原话里的「重复提醒」。

现在 `dedup_key = dividend_tax_pending:{symbol}:{分红日}`，**不含今天**：

- 同一笔分红 ⇒ 同一键 ⇒ 用永远只提醒一次；
- 新分红 ⇒ 新键 ⇒ 立刻提醒（不用等到下一年）。

两个方向各有一条用例钉住（`test_dedup_key_does_not_roll_with_today` /
`test_new_dividend_gets_a_new_key`），且回退探针实测：把今天拼回键里 ⇒ 红。

## 三、及时：导入完成即复核

原来提醒只在「用户打开对账台」时生成。用户不会天天打开对账台，
而**导入交割单**恰恰是「他刚刚面对过那张单子」的时刻。

`CommitMixin._refresh_dividend_tax_reminders` 在提交落库后跑一次，只对本批标的：

- 本批有现金分红、没有扣税行 ⇒ 立刻写提醒；
- **本批自己带了扣税行 ⇒ 一条都不发**（刚记完就说「你没记」，比不提醒更伤人）；
- 只扫本批涉及的标的（导入路径不许做全表派生）；
- 任何异常都吞掉并记日志 —— 提醒失败不能连累已完成的导入。

## 四、不误提醒：`txn_type='dividend'` 是个大杂烩

同花顺把下面这些**全部**落成 `txn_type='dividend'`（见 `core/constants.THS_OP_TYPE_MAP`）：

```
基金红利拨入 / 债券兑息 / 红利入账 / 利息归本 / 配股退款退息 / 转股零款
```

而「债券兑息兑付」甚至被映射成 **`tax` ⇒ `dividend_tax`**。
不排掉这些，用户会被推着去给**存款利息**补一笔根本不存在的红利税 ——
一次误提醒就足以让整个提醒功能失去信任（用户原话：「防止对用户进行一个误提醒」）。

判据用两样账内事实，都能从流水本身读到，不需要外部数据：

1. 标的资产类型（流水 `asset_type` 优先，其次持仓表 `positions.asset_type`）
   ∈ {bond, money_fund, reverse_repo, cash, bank} ⇒ 派息是利息，排除；
2. 操作名关键词：含「利息 / 兑付 / 退款 / 退息 / 零款 / 兑息」⇒ 排除。
   ⚠️ 排除表必须**先判**且显式含「兑息」—— 白名单里也有「兑息」（基金派息的说法），
   顺序反了「债券兑息」就走成「这是分红」（本次实测踩过）。

## 五、顺手补的一个洞：已记税也可能记错

`bond` 的派息被同花顺记成 `dividend_tax`，于是「一只低分红股票的现金分红」旁边
可能配到一笔**债券的税**，比例远超 20%（红利税的差异化上限）。
这种账本身是错的，但**不是我们能改的**（那是用户的账），于是：

- 只要「这笔扣税 / 这笔分红 > 20%」且分红 ≥ 100 元 ⇒ 出一行 `已记-比例异常`，
  提示「核对是不是记错了品种」；
- **不写任何自动修正**，也不给税率建议 —— 给了就会被当成答案。

## 六、补记入口：没被做的提醒等于没提醒

上一版让用户「去流水页补记一笔」。可红利税在交割单里是一条独立行，
没人愿意为此打开记账表单填六个字段 ⇒ 提醒看了不动。

现在域 E 每行一个「补记这笔税」按钮，弹框只问**税额**（默认空，不给猜数），
扣税日默认取分红日。落库走 `record_tax`：

- `import_hash = dividend_tax|{symbol}|{date}`，撞 `uq_txn_import_hash` 唯一约束；
- 撞约束时用 **savepoint** 兜住（`db.rollback()` 会把整个 `user_session()` 事务抹掉 ——
  AGENTS.md 记过这个坑），返回既有那笔，语义是「已经记过了」。

## 七、验证

- `tests/services/test_dividend_tax_service.py` 45 例 + `test_dividend_tax_import_hook.py` 5 例；
- **10 个回退探针全部 CAUGHT**：按年聚合 / 不排除利息 / 窗口不限 / 扣税在分红日之前 /
  一笔税结清两笔 / 键带上今天 / 比例阈值关掉 / 回溯窗口关掉 / 再投不排除 /
  幂等键不含标的 / 钩子只扫不写 / 钩子不排除本批带税行；
- 首版有 2 个 MISSED，都记在案：`record_tax` 幂等键去掉标的（先查分支掩盖了它 ⇒
  改成直接钉键的形态）；「拔掉导入钩子」MISSED 属预期（用例直接调私有方法，不是走 `commit`）。

## 已知边界

- **合并扣税会留下尾巴**：一笔税只能结清一笔分红，多笔合并时其余几笔继续提醒。
- **30 天窗口是我定的**：太窄把「已扣」判成「没扣」，太宽把上一季的税串到这一笔。
- **不给税额估算、不给税率区间**：那是猜（见上一篇）。
- 导入钩子只覆盖「用户导入」这条路；自动抓取的分红由对账台读取时触发。
