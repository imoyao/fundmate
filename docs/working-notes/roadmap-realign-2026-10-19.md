## 2. 为什么感觉失控：四个根因

### 根因一：里程碑层叠，且失去时序表达

14 个里程碑 = **编号产品系列**（M0/M1/M2/M3/M5/M6/M7）+ **主题系列**（基础数据、自选增强、双库架构、产品详情页、账本能力对齐、Pro 面板、反馈闭环）。两套并存本身合理（一个是阶段、一个是领域），但缺一层「现在只推哪几个」的时序视图——里程碑只回答「这张卡属于哪个领域」，不回答「接下来做什么」。看板承担了这个职能，但象阵标签已经漂移（§1.3）。

### 根因二：M6 Backlog 二次垃圾桶化

2026-09-02 曾治理过一次（31 张无里程碑卡清零，写入 AGENTS.md 强制规则）。两个月后 M6 又积到 36 张 open，混装着三类完全不同的卡：
- **战略卡**：#1001 定价、#1002 支付对接、#1006 账户渠道费率分层（付费主线！却在 Backlog 里）；
- **债务卡**：#949/#966/#967/#968/#975 五张「债务:」前缀（Q3-GREEN，其实是数据可靠性工作）；
- **真垃圾/远期**：#1003 礼品卡、#1004 早鸟码、#1005 家庭版暂缓、#939 一键自动源（Q4-GRAY）。

规则「必须挂里程碑」只解决了「无家可归」，没解决「家本身就是垃圾场」。

### 根因三：双轴（里程碑 × 四象限）交叉视图无人维护

象阵 Q 标签 + 里程碑强制两个机制都是对的，但它们的**交叉视图**没有 owner：`launch-priority-baseline.md` 最后更新 2026-08-18，此后两个月 issue 大进大出（305 close + 若干 new），基线文档与现实的偏差已经大到无法用。单一维度的标签没有失效，失效的是「每月重新裁定一遍优先级」的**节奏**。

### 根因四：两套进度事实源

`docs/spec/roadmap.md`（最后核实 2026-08-17）维护着一套 P1-xx / P2-xx 编号体系，与 GitHub 里程碑/issue 完全平行。文档里的「P2-30」「P2-31」要靠人脑映射到 GitHub #922、#2018 等卡上。两套体系各自腐烂速度不同步，文档必然滞后（现在已滞后两个月）。**双事实源 = 没有事实源。**

## 3. 阶段判断与战略主线

### 3.1 产品阶段（R1 修订）：从「上线」转入「日常跑起来」

> 原 R0 口径写的是「当前唯一战略目标 = 让付费可以被验证」。owner 明确不认可：**现在不着急上付费版本**。以下是修订后的判断。

证据链：
- M0 上线 closed 22 / open 4，剩余全是收尾（部署配置、SSO、告警、演示账户）——**站已上线**；
- 应用站 app.duoduobei.com、反馈站 feedback.duoduobei.com 已在运行（M16 描述），但 **feedback 站仍有线上 503**（#2001，失败率约 20%）——「跑起来」这件事本身还没做完；
- 免费核心正带着 4 张在途缺陷：#2372（转换记账）、#2405（分组键错按账户名）、#2406（转入腿漏传 name/market）；
- dev 与生产 Supabase 未隔离（#1028）——日常开发有误伤生产数据风险；
- 数据可靠性欠账集中：#1397 估值源不稳、#1502 拥挤度源未授权、#1490 快照任务无告警、#1525 Turso 308；
- 账本数字还互相说不清：M17 口径未收口（B' → C/F/D/E）。

结论：**当前阶段目标 = 基础可用 + 免费功能上线，让日常跑起来**。判据是「一个真实用户能连续用一个月不踩坑、数据不骗人」，不是「收到第一笔订阅」。付费是这一层稳定之后的自然下一步，不是现在的瓶颈。

**付费相关如何处置（不删除、不清零，只冻结 + 收安全洞）**：
- M1 付费验证（#4）保留在里程碑列表但**移出 NOW/NEXT**，标记「冻结至免费层稳定」；
- #2324（Pro 端点无后端权益校验）虽是安全洞，但**仅当 Pro 面板已经对外可见**时才需立刻处置；若 Pro 面板尚未上线，则降级为「上线前必须完成的前置」，避免为不存在的付费墙写代码；
- #1288（前端软拦截）、#1001（定价）、#1002（支付对接）→ LATER，本季度不动；
- #1294（OCR 用量二期）、#1000（自选上限 Pro 附赠）、#2285（风险榜付费候选）、#2361（Pro 权益运营）→ LATER；
- M19 Pro 面板：拆分口径——**Phase 0 数据基建与免费可用的分析模块可进 NEXT**，面向付费的模块划分/权益编排留 LATER。

### 3.2 价值链与依赖主线（R1 修订）

```
数据可信 ──→ 账本可信 ──→ 免费功能好用 ──→ （日后）付费与差异化
(基础数据     (M17 口径     (缺陷清零 /        (M1 + M19 + M18
 + 双库架构)    统一)        日常可运行)         + 策略引擎)
      │              │                │
      └──────────────┴────────────────┴──→ 反馈通道 M16（耳朵）
```

关键依赖：
- **一切的前置是 #1028（dev 环境隔离）**：不隔离则任何数据修复都有误伤生产的风险；
- **免费层可信依赖 #1490（任务告警）+ #1397/#1502（数据源稳定）**：数据不骗人是免费产品最硬的护城河；
- **M17 的 C（TWR）/F（现金闭环）/D/E（超额与归因）依赖 B'（快照体系收口）**——先收口径再算数；
- **#1001 定价依赖 M19 的价值定义**，但既然不着急付费，#1001 可无限期挂起，不阻塞任何免费层工作；
- **M18 策略引擎 P0（#2225 持仓诊断）依赖 M17 收益口径**，且它本身对免费用户也有价值，可与 M17 同期推进。

### 5.5 一个观察：护栏类机制的教训已发生过两次
