## 1. 横向滚动条与「默认列预算」

### 1.1 事实
- #1341（已 CLOSED）修的是**页面级**溢出（`flex min-width:0` 链）；本次是**表格内部**横向滚动。
- 默认可见列总宽 ≈ **1282px**；#1381 的「备注」列默认可见时 +180 = **1462px**。
- 布局：侧栏固定 **240px**、内容区流体（`frontend/design.md` §布局）→ **1366 屏内容区 ≈ 1040–1080px**。

### 1.2 分辨率调研（2024–2025）
- 桌面端：**1920×1080 ≈ 43%** 主导；1536×864、1366×768 仍占相当比例。
- 笔记本新机：**2.5K（2560×1600）≈ 40%** 在涨，2.8K ≈ 13%。
- 结论：以**最受约束的主流笔记本 1366×768** 为设计下限 → 内容区 ≈ 1040px，**默认列预算 ≤ 1040px**；1920/2.5K 屏留白更从容；<1366 出现滚动属预期。

### 1.3 目标（用户明确）
- **默认列集总宽 ≤ 预算**；超预算的列走「列设置」开启；**用户自行加列导致的滚动是正常的**。
- **不得以"藏列"为手段**——列有意义就不能因怕滚动而砍掉；要做的是"默认集按价值与宽度预算设计"。
- 备注等**编辑能力**不应依赖某列是否可见（入口去列化，见 §5）。

### 1.4 待定
- 默认列集具体保留哪几列（现默认集 1282px 超预算 ~240px，需下沉若干列或改 `min-width` 弹性收缩）。
- 是否在 `frontend/design.md` 登记「表格默认列预算 ≤1040px」为规范。

### 2.3 通用架构（Ports & Adapters，避免一次性代码）
- **接口（Port）**：`AdvisorPortfolioSource` 协议，方法 `fetch_overview / fetch_returns / fetch_holdings / fetch_industries / fetch_rebalances`。
- **适配器（Adapter）**：每平台实现该协议 + **声明式字段映射**（平台字段 → canonical）。**新增平台 = 加一个适配器，不改表、不改调用方**。
- **平台特有字段**：进 `extra` JSON 列，不新开列（防表过宽）。
- **缺失值策略**：能算的**派生计算**（年化、最大回撤、相对基准超额）；不能算的置 `null` 并标 `source`。
- **AI 补全（扩展项）**：无抓取源的字段（如定性"备注"）后期可 AI 生成并标 `source='ai'`——**列入扩展，不阻塞本期**。
- 落点：`app/services/sync/adapters/`（一平台一文件）+ 统一 `AdvisorPortfolioSyncJob` 消费 canonical。

## 5. 行内交互：抽屉 vs 详情页（完整设计，需先定后写码）

### 5.1 用户顾虑
- 抽屉与详情页"都是点一下"，会**冲突**；
- 若本期做抽屉、后期又要删（为详情页让路），则白做。
- 抽屉能承载**重要数据**，但**完整数据**可能仍需**详情页**。

### 5.2 建议模型（避免冲突、可渐进）
**两级：行点击 → 抽屉（速览）→ 抽屉内「查看详情 →」→ 完整详情页。**
- **行点击 = 抽屉**：不离开列表，展示该类型的关键维度 + 少量亮点（"一眼看清"）。
- **详情页入口放在抽屉内**（显式按钮/链接），**不占用行的点击**——因此与抽屉不冲突。
- 详情页**分类品实现**（基金详情 / 经理详情 / 组合详情 / 指数详情），是**后期**（单只基金详情页目前尚未落地）。
- 备选：若某类型详情页先有，可在抽屉内直达；无详情页的类型，抽屉即"完整视图"（渐进增强）。

### 5.3 待定
- 行点击是否区分"普通查看"与"进入详情"（如 cmd/双击）——暂不做，保持单一交互。
- 抽屉信息层级（首屏给哪些字段、其余折叠）。

## 6. A/C 类份额关联（创新项，远期）

- 场景：看业绩时 **A 类**（历史长、可比）更好，但买入常选 **C 类**（费率低，近年差异变小）。
- 设计：在**抽屉**中把 A/C 份额关联展示（切换查看同一基金的不同份额）。
- 定位：**远期 / 讨论项**（依赖基金份额数据 + 详情页/抽屉）。
