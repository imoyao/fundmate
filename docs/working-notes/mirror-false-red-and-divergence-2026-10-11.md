# 镜像自检的假红与分支分叉自检（CNB #123）

日期：2026-10-11　关联：CNB #118 / #120 / #123　状态：待合入 `dev`

## 一、起因：上一轮留下的两件「不需要拍板却还没做」的事

#123 的上一轮评论把待办收成三条（发版需拍板 / 镜像卡追更正需授权 / 分叉巡检可选）。
本轮「接着做」处理的问题是：**#118 造出的自检能力本身有一个假红**。

## 二、假红：只读正文 + 正文只增不覆盖 = 修好了也永远红

`check_mirror_refs.py` 的判定读的是**正文**（`body = detail.get('body')`），
而 #120 拍板的更正通道是「**正文不动、更正写评论区**」。两者一叠加：

> 正文引用失效 ⇒ 自检报红；按 #120 的通道更正 ⇒ 正文没变 ⇒ 自检**继续报红**。

即 **红却不指向任何还需动手的事**。这与 #118 要治的「静默降级」是同一族：
那边是**假绿**，这边是**假红**，红灯的可信度一样会掉没。

### 修法

报告改为读评论区（靠 `mirror_correction.py` 的幂等键 `更正键：<sha1>` 识别，
正则从该文件源码里提取而非抄第二份），把失效引用分两类：

| 类别 | 含义 | 要动手吗 |
|---|---|---|
| ⚠️ **待更正** | 正文引用失效，评论区无任何更正 | **要** |
| ✅ **已更正** | 正文引用失效，评论区已有更正说明 | 不要，账已记 |

**实测**（110 张镜像卡）：修复前 4 张全为「待办」；修复后 **0 张待办 / 4 张已记**
（4 张的更正评论此前已按 #120 通道发布，`mirror_correction.py list` 可复核）。

### 探针自检

按 AGENTS.md「守门通过 ≠ 守门有效」做回退验证，**3/3 CAUGHT**：

- 报告不读 `corrected`（永远报待办）→ CAUGHT
- `load_corrected_numbers` 永远返回空 → CAUGHT
- `run()` 不传 `corrected`（接线断开）→ CAUGHT

## 三、分叉自检：把「写完了，跑的不是它」变成可发现

`crontab` 只能挂具体分支，`.cnb.yml` 挂在 `main`。若整改代码在 `dev`，
就会出现「**写完了，跑的不是它**」——且没有任何信号提示。

新增只读脚本 `scripts/bridge/check_branch_divergence.py`：

- 判据：`main` 独有提交数 > 0 ⇒ 分叉（正常态恒为 0）；
- 列出两侧互不包含的作业配置文件（`.cnb.yml` + `.github/workflows/*.yml`）；
- 退出码 `0` 未分叉 / `1` 已分叉 / `2` 取不到分支；
- **纯离线**（只读本地 git，**不 fetch**——否则「网络不通 = 报告绿」又是一次静默降级）。

**实测**：`main` 独有 15 / `dev` 独有 20，互不包含；`.cnb.yml` 只在 `main`、
`cnb-github-backfill.yml` 只在 `dev`。

### 本轮踩到的坑（写进回归网）

`git diff --name-status left right` 的 `D` = **只在 left**、`A` = **只在 right**——
方向敏感。初版把 `A` 与 `D` 都算「只在 right」，于是 `.cnb.yml` 与
`cnb-github-backfill.yml` **同时出现在两侧列表**，报告自相矛盾。
判据方向错等于报告不可用，故回归网专项钉住
（`test_side_only_no_duplicate_across_sides`）。

探针自检 **3/3 CAUGHT**（方向语义 / 分叉判据恒绿 / 退出码不表达）。

## 四、分叉的成因（供发版时参考）

不是「main 落后 dev」，是**双向分叉**：两条功能分支
（`feat/github-issue-cnb-mirror`、`feat/2-cnb-github-backfill`）从**同一个 base**
（`0de73e21`）分出后各自只投递到一侧 ⇒ `main` 拿到镜像链路、`dev` 拿到回写链路。

**处置是发版**（`dev` → `main` 的 PR，head 必须是 `dev` 本身）。
已实测 `dev` 合进 `main` 会**保留**两侧文件（真正的合并，不是覆盖）——
唯一的成本是 3 个冲突：`.github/workflows/ci.yml`、`docs/spec/decisions.md`、
`docs/working-notes/README.md`。

- **GitHub 原卡是否也过期**：本环境无 GitHub 凭据，`#968` / `#1095` / `#2001` / `#2032`
  未核实。若原卡也过期，「CNB 改了、源头还错的」会反过来制造新的不一致。
