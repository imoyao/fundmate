# 其余项目评估与数据库成本决策（市场验证期）（2026-08-04）

> 性质：内部备忘（`docs/working-notes/` 屏蔽出构建，不对外）。
> 日期：2026-08-04
> 定位：沉淀与用户的讨论（数据源/熔断、Supabase 用法、架构一致性、优先级），并针对"数据库要不要迁到腾讯云 PostgreSQL"做成本综合评估。属于"市场验证期"决策，非立即执行项。
> 结论先行：验证期**不迁**腾讯云 PostgreSQL（它会从第一小时起产生费用，无长期免费档）；继续用 **Supabase 免费档（¥0）**，选新加坡/东京 region，并在数据路由层加重试+超时+告警来吸收跨境抖动。

## 〇、一句话决策

- 腾讯云 PostgreSQL：**无免费档，必产生费用**（最小实例约 ¥100–300/月，按量更贵）。与你"验证期零购买"冲突 → 不选。
- Supabase 免费档：**¥0**，但**无中国大陆 region**，最近为新加坡(ap-southeast-1)/东京(ap-northeast-1)。对单人每日批处理+自己查询，延迟（约 80–150ms）与偶发 GFW 抖动可接受。
- 验证期结论：**留在 Supabase 免费档**，region 选新加坡或东京，路由层加固即可。等出现"真被墙 / 真多用户"再考虑迁移。

## 一、上一轮"其余项目"看法沉淀（精简）

（详细讨论见对话；此处留要点便于后续回看）

1. **数据源路由/熔断 + 偏置（BIAS/乖离率）数据源替换**：方向认可，但别过度建设。若实际只有 1 个免费源，熔断=预备役（逻辑在跑但无真正兜底源）。重点应是"1 个稳源 + 失败告警 + job 幂等重跑"。
2. **Supabase 用法**：当托管 Postgres 很省事、免费档够用，赞成保持。Auth 若目前只自己用可暂缓，用轻量 session 顶着，等真多用户再接。
3. **架构一致性**：主线自洽（前端 EdgeOne Pages / 后端 SCF Web Function APIFlask / 调度只喊话、计算留 Flask）。唯一不一致是"SCF 上海 ↔ Supabase 海外"跨境数据链。隐性成本是同时看 3 个控制台（EdgeOne / SCF / Supabase）。
4. **优先级**：① 后端+定时任务上线（最高）② job 失败告警+幂等 ③ 前端先不动 ④ 移动端等真有需求再上 Vant/uni-app。

## 二、数据库选址与成本综合评估

### 2.1 问题

用户原话：迁移到腾讯云 PostgreSQL 是不是又要产生费用？验证期不想购买任何云服务产生费用。
→ 需回答：腾讯云 PG 是否免费；有没有零成本替代；跨境问题能否在不花钱的前提下缓解。

### 2.2 腾讯云 PostgreSQL 成本事实（官方文档 cloud.tencent.com/document/product/409/49577，更新 2026-05-07）

事实：

- 计费模式仅两种：**包年包月**（预付费）、**按量计费**（后付费，三阶梯，用越久越便宜）。
- **没有任何长期免费额度 / 免费档**。实例规格费用 + 存储空间费用从创建起计费；备份空间仅"赠送购买容量 100%/200%"，超出才收费；日志/流量目前免费——但这些是附加项，不是实例免费。
- 计费示例佐证：16核32G + 500GB 按量第一阶梯 **11.377 元/小时**；包年包月同规格 **¥4096/月**。最小规格官方未在概述中列出，按同文档每核费率推算，最小 1–2 核实例仍属付费实例，约 **¥100–300/月（包年包月）** 或更高（按量）；精确最小价需登录价格计算器（buy.cloud.tencent.com/price/pgsql）。

推断：即便选最便宜的基础版单节点，也**从第一小时起扣费，且月费 ≳ ¥100**，违背"零购买"目标。
边界：新用户偶有"试用/代金券"活动，但非长期免费档，不能当作验证期稳定方案。

### 2.3 Supabase 免费档事实（官方 supabase.com/pricing + docs/guides/platform/regions）

事实（Free 计划）：

- 数据库：**每项目 500 MB**（dedicated Postgres），**API 请求无限**，出站带宽 5 GB/月，2 个活跃项目。
- Auth：MAU 5 万，用户数无限；Storage 1 GB。
- **自动暂停**：免费项目 **1 周无活动会自动暂停**（pausing after 1 week of inactivity）。→ 对多多贝无影响，因为每日 cron job 会持续访问，不会触发暂停。
- Region：官方明确列表**无中国大陆**。APAC 可选：**Southeast Asia (Singapore) ap-southeast-1**、**Northeast Asia (Tokyo) ap-northeast-1**；另有 Mumbai、Sydney、Seoul 等。

推断：对大陆单人用户，最近可选新加坡或东京，延迟约 80–150ms 量级，通常可达，但属"跨境"，存在偶发 GFW/抖动风险（概率性，非确定性阻断）。
边界：500 MB 对单人多年每日快照足够；若未来接近上限或要自动备份/分支（PITR / Branching，免费档不含），才需升 Pro（约 ¥25/月级）。

### 2.4 选项对比（验证期视角）

| 选项 | 月费用 | 是否同区（无跨境） | 适合验证期？ | 备注 |
|---|---|---|---|---|
| A. 留 Supabase 免费档（选新加坡/东京） | ¥0 | 否（跨境） | ✅ 首选 | 延迟/抖动靠路由层重试+告警吸收 |
| B. 腾讯云 PostgreSQL（托管） | ≈¥100–300+ | 是 | ❌ | 无免费档，必付费，违反零成本 |
| C. 腾讯云轻量服务器自建 PG | ≈¥5–10/月（约¥60–100/年） | 是 | 备选（仍付费） | 比托管 PG 便宜一个量级，但需自己运维；仍非 ¥0 |
| D. SQLite 打进 SCF | ¥0 | 是 | ❌ 不可行 | SCF 本地盘临时/随冷启动丢失，数据不安全 |
| E. 国内其他云免费 PG | ¥0? | 是 | ❌ 不存在 | 阿里/华为等无长期免费托管 PG（仅短期试用） |

### 2.5 确定性结论

1. **验证期留在 Supabase 免费档（选项 A）**，成本 ¥0，满足"零购买"硬约束。
2. 创建/迁移项目时把 **region 选为 Singapore（ap-southeast-1）或 Tokyo（ap-northeast-1）**，取离你网络最近者（可实测决定）。
3. **在数据源路由层补三件事**（零成本、纯代码）：① 连接超时与重试（指数退避）② 失败即告警（邮件 / Telegram / 微信）③ job 幂等，避免重跑污染。这能把"跨境抖动"从"静默失败"变成"可观测可控"。
4. **不做 B / C / D / E**：B 付费、C 仍付费且增运维、D 数据不安全、E 不存在。

> 补充（诚实说明）：后端 SCF 在 3 个月新用户免费期过后是"按量计费"，但单人用量极小（几千次调用/月 ≈ ¥0.01–0.05），与"数据库迁移"是两件事；本评估只针对数据库。验证期整体仍接近 ¥0。

### 2.6 何时才 revisit 数据库选址（触发条件）

满足任一即重新评估（届时再出迁移补丁）：

- 你实测确认 Supabase 从你的网络被稳定阻断 / 严重超时（先测，别猜）；或
- 真实用户量上升到"跨境延迟 / 一致性开始影响体验"（如多用户并发读写、需要低延迟仪表盘）；或
- 需要 Supabase 付费功能（自动备份 / PITR、Branching、去暂停、更大容量）。

若届时想同区且控成本，优先 **C（轻量服务器自建 PG，≈¥60–100/年）** 而非 B（托管 PG ≈¥100+/月）。

### 2.7 边界与待验证

- 腾讯云 PG "最小实例精确月费"为推断值（基于官方每核费率），非登录计算器实测；但"无免费档、必付费"为文档确认事实，足以支撑本决策。
- Supabase 跨境可达性为概率性，需你本地实测（ping/连接延迟、连续几天定时任务成功率）确认，非纸面定论。
- 本文档为评估 / 决策沉淀，不含任何已执行的操作。
