## 0. 结论先行

**做。但做的不是「照抄报告版式」，是三件事：**

1. **先补一个 P0 洞**——基金资料区块**从来没被 import 过**，#1968 交付的 261 行组件 + 端点
   全是死代码。基金详情页现在根本没有基金区块。不先修这个，后面全部建在沙上。
2. **一期只接已在库的数据**（持仓明细 / 行业配置 / 最大回撤），零新数据源、零新算法。
3. **外部源问题必须先纠正一条项目文档的错误定论**：多处文档写「风险等级源不提供」、
   「同类排名无数据需自建算法」，实测**天天基金移动端接口直出这些字段**。
   这不是新开源，是**在已认定的一等源上补端点**（详见 §3，风险等级 0% 填充的根因）。

**否掉一条用户设想**：fundFOF 的数据**外部拿不到**——`/api/fund/detail` 返回 404，
页面 200。它的数据全在自己服务端聚合。§1 那三份报告里的数据本就出自它自己的库表
+ NeoData/WeStock，不是它对外的接口。**不能也不该接 fundfof**，
`external-source-policy-2026-09-30.md` §0.1 的红线维持。

## 3. 必须纠正的一条项目文档错误定论

### 3.1 实测证据

天天基金移动端接口 `fundmobapi.eastmoney.com/FundMNewApi/FundMNBasicInformation?FCODE=110020`，
**一次调用**即返回：

| 字段 | 值 | 对应我方空缺 |
|---|---|---|
| `RISKLEVEL` | `"4"` | **`funds.risk_level`（0% 填充）** |
| `ENDNAV` | `"14127047017.76"` | **`funds.scale`（0% 填充）** |
| `FEGM` | `"7017164631.32"` | 基金份额 |
| `SOURCERATE` / `RATE` | `"1.20%"` / `"0.12%"` | **申购费率** |
| `SHARP1` | `"-0.3474"` | 夏普比率 |
| `MAXRETRA1` | `"12.9303"` | 最大回撤 |
| `STDDEV1` | `"16.6041"` | 波动率 |
| `INDEXCODE` / `INDEXNAME` | `"000300"` / `"沪深300指数"` | **跟踪指数（结构化，可直接 join `index_daily`）** |

`FundMNRateInfo` 返回完整费率阶梯，`sg[]` 数组里 `source` = 申购、`rate` = 赎回，
按购买金额四档对齐（`<100万` / `100-500万` / `500-1000万` / `≥1000万`）。
⇒ **`purchase_rules` 空表的根因找到了：不是没数据，是适配器把申购/赎回两列映射错了位。**

`FundMNPeriodIncrease` 返回 **10 个区间的同类排名**：
`{Z: 近1周, Y: 近1月, 3Y: 近3月, 6Y, 1N, 2N, 3N, 5N, JN: 今年以来, LN: 成立以来}`，
每档含 `syl`（本基金）/ `avg`（同类平均）/ `hs300`（沪深300）/ **`rank`（排名）** / `sc`（同类总数）。

### 3.2 错误在哪

`data-strategy.md:116` 写的是「**akshare** 的 `fund_info_ths`(18 字段) 与
`fund_individual_basic_info_xq`(14 字段) 均无风险等级」——**这句话本身是对的**。
但结论层把「**akshare 封装里没有**」误推成了「**数据源没有**」，
于是 `risk_level` 被判为永久空列、列进「不做」清单。

**事实是：数据源有，只是我们用的那个封装没暴露。** 同类问题很可能不止风险等级一项。

### 3.3 因此推翻的既有判断

| 原判断 | 出处 | 修正后 |
|---|---|---|
| 风险等级「源不提供」 | `data-strategy.md:116` | ❌ 源提供，天天基金接口直出 |
| 规模「链路未跑通，需先修 job」 | `data-strategy.md:117` | ⚠️ 根因不同：可能同样是封装缺字段，**先探针再决定是否修 job** |
| 同类排名「无落库，需自建算法 + 全库横截面，触碰数据策略红线」 | `impl-research` §5.2 | ❌ **不需要自建**，源直出 rank/sc/avg/hs300 |
| 回撤/波动/夏普「零实现」 | `gap-analysis:131` | ⚠️ 我方自建仍要（口径要用 `acc_nav`），但可**交叉校验** |
| 「12,551 行费率已落盘」 | `gap-analysis:187` | ❌ 结论过期（只有 redeem 侧） |

### 3.4 合规性判定：✅ 成立，且不是新开源

| 判据 | 事实 |
|---|---|
| 是否已认定的一等源？ | ✅ `backend/app/core/config.py:8`：**默认 eastmoney（天天基金/东财一等数据源，#1168）** |
| 是否已在用？ | ✅ `FUND_NAV_SOURCE_LABEL = '天天基金'`；xalpha 走 `pingzhongdata` / `f10/lsjz` |
| 是否触碰 fundfof 红线？ | ✅ 不触碰。`external-source-policy` 的红线**只针对 fundfof** |
| 是否绕过鉴权？ | ✅ 匿名 GET，无鉴权 |

**结论：在已认定的一等源上补端点，不新增源、不新增政策豁免。**

### 3.5 但有两个必须先做的前置动作

**① SSOT 未登记。** `external-datasource-reference-2026-08-03.md`（全仓外部源端点 SSOT）
grep `fundmobapi` **零命中** ⇒ 这个接口**从未被正式纳管**。落库前必须先登记。

**② 稳定性风险分级。** 现有链路走 `pingzhongdata`（静态 js，`xalpha` 封装），
本次走 `FundMN*`（**移动端 JSON 接口**）。两者稳定性不同，且后者是**未登记的内部接口**。
`pingzhongdata` 挂了我们能改适配器；`FundMN*` 挂了我们只能降级。
⇒ **适配器必须内置字段缺失容错**，任何字段取不到就 `None` 走既有降级路径，不得抛错。

> 用户提到「天天基金 / 东方财富 / fundFOF 三个来源」——
> **前两者是同一个源**（天天基金 = 东财旗下，`fundmobapi.eastmoney.com` 一个域名），
> **第三个不可用**（§0）。所以实际是**一个源、一个接口族**。

## 4. 一期方案（不依赖任何新数据源）

**目标：把已在库的数据全部接出来 + 修 P0。零新数据源、零新算法。**

### 4.1 卡片清单（按页面顺序）

| # | 卡片 | 内容 | 数据来源 | 依赖 |
|---|---|---|---|---|

| 1 | **我的持仓** | 现有（含产品级 XIRR #1972），不动 | — | — |
| 2 | **基金资料** ⭐修复 | 单位净值 / 日涨跌 / 类型 / 公司 / 经理 / 费率 / 基准 | `fund-profile`（已有端点） | **仅需补 import** |
| 3 | **业绩与风险** ⭐新 | 区间收益切面（近1周/1月/3月/6月/1年/2年/3年/5年/今年以来/成立以来）+ 最大回撤 + 波动率 | `daily_worth` + `fund_metrics` + `performance` | 自建算法（库里已有底座） |
| 4 | **行业配置** ⭐新 | 环形图 + 表格（csrc 主口径，gics 单列） | `fund_industry_allocs` 830 行 | 复用 `AssetAllocationDonut` |

**合计新增 3 张卡 + 修复 1 张。** 不引入 13-tab 布局、不引入折叠导航（区块数还不到 8 个，
`impl-research:248` 说「8 个区块后没有锚点会很难用」——一期不触发）。

### 4.2 关键设计决定

**① 数据来源前置到卡片标题上方。** 借鉴 b.html 的 `card-meta`，
每张卡片标题下用 12px 弱色写「数据日期 · 来源站点 · 口径」。
抄 `ProductTrendSection.vue:301-307` 的既有体例（来源给**站点名**不给表名）。

**② 指标区只渲染有值项。** 抄 `ProductAdvisorSection.vue:68,92` 的
`.filter(m => m.value != null)`。基金资料有 14 个字段，若全渲染必然出现一排「—」，
那是「没数据」的另一种噪声。

**③ 持仓明细表必须带 `holding_basis` 标注。**
`penetration.py:52`（硬口径 7）已定此要求：季报只披露前十大，全量口径与前十大口径不可混。
本库 99% 是 `full` 但仍须显式标注——万一某天混进 `top10` 而用户不知情。

**④ 行业配置必须按 `scheme` 分区。** `penetration.py` 硬口径 2：
csrc（证监会门类）与 gics **禁止跨体系相加**。主口径 csrc，gics 单列并带覆盖度与 note。

**⑤ 图表硬约束照抄 `ProductTrendSection` 四条：**
`getCssVar` 取真实色值（ECharts 不解析 `var(--x)`）/ `smooth: false`
（平滑会画出实际不存在的峰谷）/ 无数据显空态绝不 mock / 脚注写站点名与口径。
**且 `chartOption` computed 必须读 `themeTick.value`**——
`theme.ts:63-82` 的 `useThemeTick` 是模块级 `MutationObserver` 单例，
`getCssVar` 是命令式读取不建立响应式依赖，不读 `themeTick` 则暗色切换后图表不重绘。

**⑥ 回撤/波动/夏普口径统一用 `acc_nav`。**
`fund_metrics.load_nav_points`（:81-92）优先 `acc_nav`、缺失才回退 `unit_nav`。
一期自建时必须同源，否则详情页与自选页数字打架。
注意 `fund_metrics.py:9-11` 的诚实声明：`acc_nav` 是「分红不再投」口径的
**近似复权序列，非严格分红再投复权净值**——这个 caveat 必须显示给用户。

**⑦ 最大回撤直接抽公共 service，不复制代码。**
`watchlist_display.py:127-160` 的 `_apply_fund_drawdown_fields` 已在跑，
抽成 `services/fund_metrics.py` 的公共函数，两域共用。
口径保持：场外基金专用、近 3 年固定窗口、日频、`basis='fixed_3y'`、
样本不足时 `basis='insufficient'`。

**⑧ 货基走独立分支。** `money_fund_daily_worth` 121 万行
（`nav_per_10k` 万份收益 + `annual_return_7d` 七日年化），
货基卡片改显这两项 + 规模，**不显日涨跌**（源就没有，实测 `RZDF="--"`）。
`build_fund_profile` 需按 `is_money_fund` 分流。

## 6. 约束清单（实施时必须遵守）

### 6.1 数据策略（`data-strategy.md`，约束级别等同硬约束）

1. **L2 必须自己算，L1 必须自己存；L3/L4 按需+缓存+可降级，不追求全量。**
2. 新增列必须**当场指定至少一个读者**（API 序列化 / 计算输入 / 界面展示三选一）。
3. 新增 job 目标池必须显式；**禁止空 targets 静默退化为全库**；`--full-sync` 必须带范围。
4. 验收优先采用**用户触达口径**（持仓池 142 只）而非全库口径（26,938 只）。
5. **「0% 填充」≠「无价值」**，必须写清是源缺失 / 链路未通 / 设计废弃——三者处置相反。
   本次 §3 已把 `risk_level` 从「源缺失」重新定性为「封装缺字段」，**处置从「可删」变为「可救」**。

### 6.2 前端

| # | 约束 |
|---|---|
| 1 | 金额必须 `MoneyDisplay`，涨跌必须 `RiseFallText`，**禁止手写格式化** |
| 2 | 区块必须 `CardBlock` + `SectionHeader`（全站统一，**无一处用 el-card/el-descriptions**） |
| 3 | 事实项网格统一 `repeat(auto-fit, minmax(140px, 1fr))`——**不可用 `minmax(0,1fr)`**（#1969 P0：轨道塌成几像素、标签逐字竖排） |
| 4 | 所有交互元素 `:focus-visible` 必须有可见 Focus 环（`--focus-ring` 双环；输入类用 `--input-focus-shadow` 单环） |
| 5 | 颜色一律走令牌；文字级涨跌色用 `--color-rise-ink`/`--color-fall-ink`，**勿用图形级** |
| 6 | 断点一律 `@include bp.*`，**禁止裸 `@media (width <= 768px)`**，且必须写在同规则基础声明**之后** |
