# 导航信息架构（侧边栏 + 面包屑）

**定稿日期**：2026-11-01（侧边栏重组 2026-10-29 起，2026-10-30 补齐面包屑与文案，
2026-11-01 三次修订：`我的关注` 提为一级 `自选`、资产下分组全部平铺）
**适用范围**：`frontend/src/router/modules/*.ts`、`SidebarBreadCrumb.vue`、`utils/breadcrumb.ts`
**守卫**：`router/__tests__/routeRankGuard.spec.ts`、`utils/__tests__/breadcrumb.spec.ts`、`scripts/check_router_links.mjs`

## 一、结论先行

导航按**财务动作**切一刀：**看结果 / 管配置 / 挑标的 / 记事实 / 问助手**。五刀对应五个顶级，
业务顶级下一律**平铺**，除此之外不再有第二套分组逻辑。

| 顶级 | 财务动作 | 一句话判据 | 现有页面 |
|:--|:--|:--|:--|
| **概览** | 看结果 | 纯读，不写库、不下配置 | 投资概览 / 资产总览 / 持仓分析 / 投资复盘 |
| **资产** | 管配置 | 已经在我名下的钱：怎么摆、放在哪、算谁的 | 投资组合 / 策略分析 / 定投计划 / 账户管理 / 家庭成员 / 贵金属 / 房产 |
| **自选** | 挑标的 | 还没买、在挑、在盯 | 我的自选 / 特别关注 / 同类优选 |
| **记账** | 记事实 | 把已经发生的事落库，不产生判断 | 全面盘点 / 交易流水 / 分红股息 / 对账中心 |
| **账本精灵** | 问助手 | 不落在账本结构里 | 对话页（单页模块，侧边栏只有一级） |

```
概览     投资概览 · 资产总览 · 持仓分析 · 投资复盘
资产     投资组合 · 策略分析 · 定投计划 · 账户管理 · 家庭成员 · 贵金属 · 房产
自选     我的自选 · 特别关注 · 同类优选
记账     全面盘点 · 交易流水 · 分红股息 · 对账中心
账本精灵 对话页（一级，点击直达）

隐藏页（不进菜单）：/stocks 股票 · /funds 基金 · /asset/ledgers/:id · /asset/portfolios/:id
```

顺序即语义相近度，成对相邻（不靠目录层也读得出分组）：

```
投资组合 · 策略分析 · 定投计划   —— 一篮子的做法
账户管理 · 家庭成员             —— 钱放在哪、算谁的
贵金属 · 房产                   —— 要手动登记、手动估值的线下资产
```

### 1.1 2026-11-01 三次修订：为什么再拆一次

> 方案来自用户的一版构想（概览四平铺 / 资产五项 / 自选独立 / 记账五项 / 个人中心）。
> 采纳其中两条，其余按下面的判据否掉。

**采纳 ①：「我的关注」提为一级「自选」。** 三条依据，与"高频"无关：

1. **名实不符**。顶级「资产」的字面是"已经在我名下的东西"，而这一组装的是**还没买的候
   选池**（我的自选 = 在盯的标的、特别关注 = 私有思考卡片流、同类优选 = 同类筛选的候选）。
   把候选池放进"资产"，与当初把「同类优选」塞进「品类持仓」是**同一种错**：名字与成员
   互相否定。拆开后两侧都名副其实——`资产` = 我的钱怎么摆，`自选` = 我还在挑的。
2. **点击深度不齐**。此前三个业务顶级里，概览与记账是 2 次点击（展开顶级 → 点页面），
   只有资产是 3 次（展开顶级 → 展开分组 → 点页面）。这是"同一个侧边栏里两种操作成本"，
   与本轮一直在减层级的动作同向。提级后 `/watchlist` 降为 2 次。
3. **命名重复**。分组名「我的关注」与其第一项「我的自选」几乎同义，用户要读两遍同一个词、
   点两次才到。这条单独不足以改结构，但与 1、2 叠加时说明"这一层本来就不该在"。

**采纳 ②：资产下三个分组目录全部撤销，叶子直挂。** 分组带来的只是多一层点击，没有增加
区分度：「组合策略」「实物资产」「账户成员」三个名字都解释不了"为什么这几项在一起"，
而顺序 + 相邻已经表达了同一件事。撤销后资产是 7 项平铺，仍是 2 次点击。

**没做的事，以及为什么**（避免下一轮重新论证）：

| 构想 | 取舍 | 理由 |
|:--|:--|:--|
| 记账加「对账单导入」为可见项 | 不做 | 它是**录入流程页**，`全面盘点` 的快捷卡片已直达（`import_txn`）；放进侧边栏就是给一个流程开特例，而"手动记账 / 导入持仓 / 录入资产"凭什么不进？全进则记账变 9 项。见 §七 反向约束。 |
| 个人中心做成含 5 个子项的"中心" | 不做 | 现存 `/profile`（头像下拉进入、hidden 路由）只有**个人资料 + 账号安全**两个真有内容的区块；偏好散布在各页（自选列设置 / 快捷筛选，均走 `PUT /api/users/preferences/<key>/` 双写云端），Token 尚未实现。拆 5 个子页 = 3 个空架子 + 每个真实设置多一次点击。**门槛是"≥3 个真有内容的子页"才拆。** |
| 家庭成员迁入个人中心 | 不做 | 它是**账户归属维度**（页面自述"把账户归属到具体成员"、建账时 `OwnerMemberSelect` 要选它、成员删改的影响面在账户列表）。搬走后"改的地方"和"看到后果的地方"分居两地。要入口就给链接，不搬路由。 |
| 一级菜单用「概览 / 资产 / 自选 / 记账」2 字 | 采纳，并改守卫 | 一级是"扫列"，短才扫得动；原"一律 4 字"改为**分层**：一级 2~4 字、叶子 4 字。见 §四.1。 |

> 2026-10-30 二次修订（保留记录）：第一版四组叫「组合策略 / 品类持仓 / 观察名单 / 账户家庭」，
> 用户连着否掉后三个——「账户家庭是什么意思？说人话」「观察名单也不好」「品类持仓也不好」。
> 复盘发现**不是名字不好听，是成员装错了**：「品类持仓」里装着**同类优选**，而那是
> 「按你的持仓与自选做基金同类排序」的**筛选页**，页面副标题自己写着；名字与成员互相否定。
> 该轮先把 `/stocks`、`/funds` 提到直接子级，本轮再把剩下的分组层也撤掉——
> 同一判据（名要副实 + 少一层）连着走了两步。

## 二、为什么不再用「总览 + 资产管理」两套逻辑

重组前是 17 项平铺在两个顶级下，同一件事被劈开：

- **看**散在 5 处（投资概览、资产总览、持仓分析、复盘、同类优选）；
- **记**散在 4 处（全面盘点在概览、交易流水在概览、对账在资产、导入挂在「投资管理」目录）；
- **我的自选**（概览）与**特别关注**（资产）隔着两个顶级——同一件心事分住两栋楼。

根因不是条目多，而是**两个顶级用了两把不同的尺子**：「总览」按**使用频次**分组，
「资产管理」按**资产类型**分组。两把尺子交叉，必然有页面两边都像、只能靠 `rank: 3.5`
这类小数补位（小数补位本身即「已无序可插」的病征）。

## 三、为什么不按「四笔钱」分导航

`docs/design/si-bi-qian.md` 的四/五笔钱（活钱 / 稳健 / 长期 / 保险 / 博弈）是**资产配置**
维度，落在「配置目标」下拉与资产配置图里（`allocation` 字段）。它回答「这笔钱该放哪」，
不回答「我要去干哪件事」。若拿它做菜单，用户想记一笔账时得先判断这笔钱属于几笔钱——
把分类成本转嫁给最高频的动作。**配置维度与导航维度必须正交，不得互相复制。**

## 四、命名规则

1. **字数分层（2026-11-01 修订）**：一级目录 **2~4 字**（概览 / 资产 / 自选 / 记账，
   越短越快扫），二级叶子**一律 4 字**；唯一豁免是资产类别名词（「贵金属」「房产」）
   ——扩写成 4 字会改变语义。原「一律 4 字」把一级也钉死，逼出一批新造词
   （「自选观察」「自选跟踪」），语义并不比「自选」更准。
2. **名要副实**：目录里装什么就叫什么；名字读不懂时先查成员，再改字面。
   - 「投资管理」→「品类持仓」→「实物资产」→ **拆为平级「贵金属 / 房产」**：前两版都在
     暗示「这里涵盖全部投资」，实际只有贵金属/房产（股票/基金是隐藏路由）；「品类」是
     电商品类思维；到第三版名字终于对了，但只剩两项还套一层目录——本轮连目录一起撤。
   - 「观察名单」→「我的关注」→ **「自选」（一级）**：直译与冗词都去掉了；
     它压根不属于"资产"（还没买），见 §1.1。
   - 「账户家庭」→「账户成员」→ **拆为平级「账户管理 / 家庭成员」**：两个名词硬拼，
     拼完什么也没说；拆开后各自可读，顺序相邻仍表明它们是同一对。
   - 「资产概览 / 资产管理 / 记账中心」→ **「概览 / 资产 / 记账」**：顶级不需要"中心""管理"
     这类后缀来撑气势，去掉后与「自选」长度一致。
   - 隐藏的基金筛选页「同类优选」：从「实物资产」→「我的关注」→「自选」。它的输入是
     你的持仓与自选，产出是候选清单，属「在挑的」而非「已持有的」。
   - 「全面盘点」实质是**录入工作台**（页面自述「选择资产大类，快速录入或导入」），
     归「记」不归「看」。
   - 「复盘」→「投资复盘」：单说「复盘」不知复什么。
   - 「分红与股息」→「分红股息」、「对账工作台」→「对账中心」（页内 h1 与提示文案已同步）。
3. **隐藏路由只在两种情况下存在**：详情页（`/asset/ledgers/:id`）、
   被别处按 name 跳转的聚合下钻页（`/stocks`、`/funds`）。删前者丢面包屑锚点，
   删后者产生**静默死链**（`check_router_links.mjs` 会报）。

## 五、面包屑：为什么以前显示「总览 / 同类优选」

### 5.1 根因

`formatTwoStageRoutes` 把三级以上路由**拍平**挂到根 `/` 下，于是任意页面的
`route.matched` 永远是 `[Home, 当前页]`——父级信息在路由层就不存在了。
旧面包屑直接遍历 `matched`，所以无论点哪个入口，父级都只能是「总览」。
这不是「有时候不显示」，而是**父级恒错**。

### 5.2 修法

面包屑改为读**路由树**（`breadcrumbMenus`，见 5.5），三级解析，**顺序不可换**：

1. **静态精确命中**当前 path（`/stocks`、`/investment/manual` 这类不进侧边栏的页面，
   树里的结构父级就是真归属）；
2. 命中不到则取**最长前缀**（详情页 `/asset/ledgers/9` → 「账户管理」）；
3. 仍取不到才用**带参路由匹配**（`/fund/004369` → `/:assetType/:symbol`）；
4. 都没有返回空数组，调用方退到 `matched`（**必须剔掉根 `/`**）、最后退到当前页标题——
   **宁可少一级，不允许空着**。

> 顺序为什么是 2 在 3 前：`/asset/ledgers/9` 同时能命中带参路由 `/asset/ledgers/:id`
> （它是 `/asset` 的直接子级），但用户是从「账户管理」点进去的，按 3 会把他走过的那层
> 抹成「资产 / 账户详情」。
>
> 另一类必须靠**结构**而不是**路径**的例子：`/asset/fund-ranking` 的 path 仍以 `/asset`
> 开头，但结构上归「自选」——前缀法必答错。同类还有 `/asset/asset-entry`（归「记账」）。

实现：`frontend/src/utils/breadcrumb.ts`（纯函数，可在 node 环境直测）。

### 5.3 为什么去掉了过渡动画

旧实现 `<TransitionGroup name="breadcrumb">` + `.breadcrumb-leave-active { position: absolute }`：
离场面包屑被绝对定位留在 DOM 里等 0.3s 过渡收尾，而 Vue 过渡靠 double-rAF 推进。
后台标签页或连续导航让两次过渡重叠时，leave 回调不执行，**旧面包屑永久留存**。

实测（Playwright 逐个点 19 个侧边栏叶子）：

| 版本 | 点「我的自选」读到的面包屑 | 19 项断言 |
|:--|:--|:--|
| 移除前 | `资产管理/品类持仓/同类优选/观察名单/我的自选` | 18 过 1 失 |
| 移除后 | `资产管理/观察名单/我的自选` | **19/19 全过** |

> 上表是 2026-10-29 的实测记录，分组名是当时那版（「品类持仓 / 观察名单」）。
> 2026-10-30 二次修订后读作 `资产管理/我的关注/我的自选`；
> 2026-11-01 三次修订后读作 `自选/我的自选`（只两级）。

面包屑是 2~3 个短词的位置指示，不需要动画。去掉后渲染与路由同步，
顺带解决了「后台标签页面包屑卡住」的老问题（此前用 `PlainGroup` 绕过）。

> 归因澄清：控制台里每次点侧边栏都有 2 条 `Cannot read properties of null (reading 'parentNode')`，
> 来自 `el-menu` 子菜单自身的展开/收拢，**与面包屑无关**——只用 `location.hash` 导航时 0 报错。
> 属既有问题，另案处理。

### 5.4 单子项目录一律拍平（不设 `showParent`）

`SidebarItem.hasOneShowingChild` 会把只有一个可见子项的父级**拍平**成菜单项（父级名消失）。
这是正确行为，不是需要绕过的缺陷：**一个只有一页的模块不该有目录层**——多一层 = 多一次点击、
零信息增益，还凭空多出第二个名字。

2026-10-30 曾反过来修：为了「侧边栏 1 级 / 面包屑 2 级对不上」，给账本精灵子项加
`meta.showParent: true`，让「智能助手」变成可折叠分组。这是**因果倒置**——用户看到的两级
是菜单硬加的，不是结构需要的。用户当场否掉：「为什么不直接让账本精灵出来，点击直接跳页面？
之前就是这样子的呀。」

正确解法是**面包屑跟着拍平**：`utils/breadcrumb.ts` 的 `isFlattenedDir` 判定与
`hasOneShowingChild` 逐字对齐（唯一可见子项且无 `showParent`），该目录不作为一级出现。
于是：

| 位置 | 账本精灵 |
|:--|:--|
| 路由 | 两级（`/agent` Layout 容器 + `/agent/chat` 页面）——two-stage 结构要求顶级带 children |
| 侧边栏 | **一级**：只有「账本精灵」，点击直达 `/agent/chat` |
| 面包屑 | **一级**：只有「账本精灵」 |

父级 `meta.title` 与子项**逐字一致**（都叫「账本精灵」）：拍平后用户只看得到子项标题，
父级另起一个名字（旧名「智能助手」）只会残留在代码与文档里，成为第三个叫法。

### 5.5 面包屑的数据源必须是「完整路由树」，不是侧边栏菜单树

> 2026-10-30 实机盘查（本机 Edge，27 个页面）抓出的错链——问题不在文案，在**喂错了树**。

侧边栏树 `wholeMenus` 被 `filterTree` 剪过（`showLink:false` / `hidden` 且无可见子项的
节点整棵移除）。拿它当面包屑数据源，凡是**不进侧边栏但用户能直达**的页面都不在树里，
只能靠「路径前缀猜父级」，或整条链塌回 `route.matched` 兜底（而 matched 恒为
`[/, 当前页]`，首级就是根 Layout 的「概览」）。实机结果（顶级名按 2026-11-01 口径）：

| 页面 | 修复前 | 修复后 |
|:--|:--|:--|
| `/stocks` | 概览 / 股票 | 资产 / 股票 |
| `/funds` | 概览 / 基金 | 资产 / 基金 |
| `/investment/holding-import` | 概览 / 导入持仓 | 记账 / 导入持仓 |
| `/investment/manual` | 概览 / 手动记账 | 记账 / 手动记账 |
| `/investment/reconcile` | 概览 / E账户对账 | 记账 / E账户对账 |
| `/asset/asset-entry` | 资产 / 录入资产 | 记账 / 录入资产 |
| `/asset/fund-ranking` | 资产 / 同类优选 | 自选 / 同类优选 |
| `/fund/004369` | 概览 / 产品详情 | 产品详情 |

`/asset/asset-entry` 这条最典型：它的 path 以 `/asset` 开头，但结构上声明在 `record.ts`
（记账）下。`/asset/fund-ranking` 同理（声明在 `watch.ts`）。
**路径前缀会说谎，父子关系不会**——所以父级只能从路由结构取。

落地：

- `permission store` 增加 `breadcrumbMenus`：同一棵合并路由树，只按角色过滤，
  **不**按 `showLink`/`hidden` 剪枝（`router/utils.ts` 的 `filterNoPermissionMenus`）；
- `breadcrumb.ts` 不再丢弃「自身不可见」的节点——那是「不进侧边栏」的标记，
  不是「不该出现在面包屑」；录入流程页、下钻页、详情页都要在链上；
- `SidebarBreadCrumb.vue` 的 `matched` 兜底剔掉 `path === "/"` 的根 Layout，
  避免任何页面在过渡帧里闪出「概览 / 某页」。

## 六、守卫清单（都得是机械判据）

| 断言 | 咬住什么 |
|:--|:--|
| 同级 `rank` 不得重复 | 排序键相等 → 次序靠数组先后兜底，改顺序就跳位置（#2152） |
| asset 直接子级 ∈[100,199]、**不得有孙级目录**、全树唯一 | 跨层撞键；也咬住"别再把分组长回来" |
| 顶级顺序 === 概览/资产/自选/记账/账本精灵 | 顶级回到「一个维度」 |
| 各顶级的可见项逐个钉死（资产 7 项 / 自选 3 项 / 概览 4 项 / 记账 4 项） | 防止悄悄挪页面 |
| 标题分层：一级 2~4 字、叶子 4 字（豁免品类名词） | 一级要能扫，叶子要说清 |
| 全静态路由禁止声明 `showParent`；单子项目录必须拍平 | 只有一页的模块不多一层；面包屑同源折叠 |
| 每个绝对路径页面的面包屑末项 === 该页 `meta.title` | 隐藏页/下钻页被剪掉后末项消失或塌回根 Layout |
| 隐藏页的父级逐个钉死（`/stocks` → 资产 / 股票 等 9 条，含 `/asset/fund-ranking` → 自选） | 用路径前缀猜父级（`/asset/asset-entry` 归记账、`/asset/fund-ranking` 归自选） |

| `e2e/nav-visibility.spec.ts`（10 页 × 侧边栏/面包屑/标签栏） | **看得见**：宽度 > 0、不被裁出视口、文字与背景对比度 ≥ 4.5:1 |

### 6.1 为什么必须有「可见性」判据（2026-10-31 教训）

「激活标签白字白底」这个缺陷存在了很久，所有既有测试都是**结构断言**：面包屑文字
对不对、标签有没有生成、层级是否对齐。DOM 里文字确实在，`innerText` 也读得到，
所以一路绿灯，用户界面上却只剩一个 × 按钮。

**DOM 里有文字 ≠ 屏幕上看得到。** 凡是「给人看的文字」，判据至少要钉三条：
有宽度（`> 0`，被 flex 压扁或溢出裁剪会是 0）、不被裁到视口外、与**实际渲染背景**
（自身透明就向上找第一个不透明祖先）的对比度 ≥ 4.5:1。坏味道的典型是
`color: var(--text-inverse)` 配了一个没有背景色的元素——反色文字必须有实底配对。

**已并入合并门禁**（2026-10-31）：`ci.yml` 的 `nav_visibility` job 在 PR 改动命中
`frontend/src/{layout,style,router,store}/**`、`utils/{breadcrumb,tagCache}.ts`、
`frontend/e2e/**` 时自动跑 `e2e/nav-visibility.spec.ts` 与
`e2e/tag-active-contrast.spec.ts`，并计入 `gate`（required check）。不命中则 skipped，
不拖慢无关 PR；全量 E2E 仍留给夜间 `e2e.yml`。

## 七、反向约束（什么不许放进来）

- **读**的页面不许进「记账」，**配置**的页面不许进「概览」——否则又回到
  「两个顶级各装一半」。
- **还没买的**不许进「资产」：候选池（我的自选 / 特别关注 / 同类优选）归「自选」。
  这一条是 2026-11-01 的教训，与「同类优选别塞进持仓目录」是同一条判据。
- 录入流程页（对账单导入 / 导入持仓 / 手动记账 / 录入资产 / E账户对账）不进侧边栏，
  但**归属**「记账」，这样面包屑是「记账 / 对账单导入」而不是
  「资产 / 对账单导入」——定位与动作一致。它们的总入口是「全面盘点」的快捷卡片。
- 唯一子项的模块**一律拍平**（侧边栏与面包屑同时只剩一级），不允许用 `showParent`
  给菜单撑出一层来迁就面包屑；需要「分组」语义的前提是有 ≥2 个成员，单成员不是分组。
- **业务顶级下不再设目录层**：叶子直挂，分组语义靠**顺序 + 相邻**表达。
  多一层 = 多一次点击 + 多一个要学的名字，而这三组名字本身都解释不了成员为何在一起。
- 个人中心**不是**一级菜单：它是 `/profile` 的 hidden 路由，从头像下拉进入；
  在它有 ≥3 个真有内容的子页之前不要拆成"中心"。家庭成员不迁入（账户维度，见 §1.1）。
- 不要给面包屑加回过渡动画；不要让面包屑依赖 `route.matched` 表达层级。
