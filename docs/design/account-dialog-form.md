# 账户类表单弹窗：宽度档位与滚动契约

> 范围：「创建账户 / 编辑账户 / 导入向导建账户 / 资产录入建账户」四个弹窗。
> 依据：2026-11-07 用户反馈「弹窗太窄导致高度特别高、看着费劲」+ 2026-11-08 实测量测。
> 状态：已实现（`--dialog-width-form` / `--dialog-width-compact` / `.form-dialog`）。

## 1. 实测基线（改前，Chromium 1080×648）

「创建账户」弹窗选证券（展开现金账户 / 活期+ / 自动申购 / 销售机构 / 费率）：

| 指标 | 数值 |
|---|---|
| 弹窗尺寸 | 560 × 548（视口 1080×648） |
| body 可视高 / 内容高 | 428 / **522**（溢出 94，需滚动） |
| 控件宽 | **420**（560 − 40 内边距 − 88 标签 − 12 间距） |
| 底部按钮 | 可见（`footerVisible: true`） |
| 字段高度 | 纯下拉/输入 32；带说明文案 52~58；折叠面板约 40 |
| 1440×900 | 弹窗 560 × 642，body 522 全展开（不滚动） |

改前四个弹窗宽度：创建 **560** / 编辑 **420** / 导入建账户 **480** / 资产录入 **420**——同一族动作四种形状，无令牌。

## 2. 结论：先把「宽度」收口到档位，不做双列栅格

- **双列栅格的价值取决于标签位置**。标签左置（`label-width: 88px`）时，600px 宽弹窗的两列控件各只有
  `(600 − 40 − 12) / 2 − 88 − 12 = 174px`——机构名 / 账户名会被截断，属**制造新问题**。
- 换成标签置顶（`label-position="top"`）后每行多出约 22px 标签高度：实测字段序列按两列重排只省约 60px
  （522 → ~460），却要跨 3 个共享组件改显隐契约。**投入产出不成立**，本轮不做。
- 因此**高度问题用「限高 + 滚动 + footer 常驻」解决，宽度问题用档位解决**，两者互不替代。

## 3. 宽度档位（唯一来源：`style/colors.css`）

```css
--dialog-width-form: min(600px, calc(100vw - 32px)); /* 长表单：字段 ≥5 */
--dialog-width-compact: 440px;                       /* 短表单：字段 ≤3 */
```

| 弹窗 | 字段数 | 档位 | 改前 |
|---|---|---|---|
| 创建账户 `CreateAccountDialog` | 10 | `form` → 600 | 560 |
| 编辑账户 `EditAccountDialog` | 10 | `form` → 600 | **420** |
| 导入向导建账户 `import/CreateLedgerDialog` | 8 | `form` → 600 | 480 |
| 资产录入新增账户 `AssetCreateLedgerDialog` | 3 | `compact` → 440 | 420 |

用法与 `--drawer-width` 同源（`ProductDrawer` 先例）：`:width="'var(--dialog-width-form)'"`。
`min(600px, calc(100vw - 32px))` 自带窄屏回退，组件内**禁止**再写 `max-width: calc(100vw - 32px)` 之类的兜底。

## 4. 滚动契约（全局类 `.form-dialog`）

表单弹窗一律套 `.form-dialog`（全局样式，`style/element-plus.scss`——el-dialog teleport 到 body，
scoped 的 `:deep(.el-dialog)` 匹配不到根元素自己）：

```css
.form-dialog .el-dialog__body  { max-height: min(66vh, 560px); overflow-y: auto; }
.form-dialog .el-dialog__footer { padding-top: var(--space-3); }
```

- **footer 常驻**：高度再长也只滚 body，`取消 / 确认` 永远在视口内。
- 66vh 取值理由：1080×648 下 body 428px（刚好 4 行带说明字段），1440×900 下 522px 全展开不滚动——
  两档都不断行、不出现二次滚动条。
- 弹窗改用 `align-center`（创建账户已有），短视口下不再顶到屏幕边缘。

## 5. 无障碍口径（本轮只做能落地的两条）

| 项 | 口径 | 处理 |
|---|---|---|
| 触控目标尺寸 | **WCAG 2.2 AA = 24×24**（2.5.8）；44×44 是 **AAA**（2.5.5） | 「仅看常用」现为 24px 行高的桌面控件，**已满足 AA**；不做 44px 膨胀（会让该字段从 58 → 78px，与压高度直接冲突）。此前把它写成「缺陷」是口径错误，此处纠正。 |
| 标签与控件关联 | 有 `for` / `id` 的字段用 `<label for>`；`el-form-item` 的 `for` 仅支持有 `id` 的控件 | 创建账户的「账户名称 / 备注」已带 `for` + `aria-required`；下拉类控件用 `aria-label`。 |
| 错误反馈 | 后端文案须可操作 | 已由 #2977 改为「计算口径不支持…；如需调整账户类型请归档后新建」。字段级定位（把错误挂到具体 form-item）留待下一轮——需要 form rules，属独立改造。 |

## 6. 验收判据

- 判据：e2e 断言创建账户弹窗宽度 `600px`（token 生效），且在 1080×648 视口下 footer 两个按钮均在视口内（`toBeInViewport`）。
- 判据：1080×648 下 `body.scrollHeight > body.clientHeight` 成立时，`body` 是唯一滚动容器（`overflow-y: auto`），页面本身不出现滚动条。
- 判据：`check_css_vars.mjs` 通过（新令牌有定义且有引用）；`guard_layout_widths.py` 通过（未新增 1280/1400 字面量）。
- 判据：代码级——四个 `el-dialog` 的 `width` 全部引用令牌（`grep -rn "dialog-width" frontend/src --include=*.vue` 命中 4 处引用点），无 `width="NNNpx"` 残留。
- **实测边界**：仅「创建账户」做了实机测量（Chromium 1080×648 / 1440×900）。编辑 / 导入 / 资产录入三个走同一令牌与同一全局类，未逐一实机量测——它们各自需要独立数据桩（编辑需账本行、导入需向导上下文），留待下次动到对应页面时顺带量。

## 7. 不做 / 留待后续

- **双列栅格**：需先把标签改置顶并统一 3 个共享组件的字段跨度，收益 ~60px，单独开卡。
- **44px 触控目标**：AAA 级，与「压高度」目标冲突；移动端适配时整体重排再考虑。
- **字段级错误定位**：需引入 `el-form :rules` + 后端错误码映射到字段，属独立改造。
