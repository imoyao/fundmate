# 调仓提醒 + 调仓解读（付费功能）设计

> 产品方向沉淀文档，非实现项。记录「外部投顾组合调仓 → 影响我自己组合」决策辅助闭环的
> 产品定义、合规边界、数据层口径、落地顺序与待决策项。
> 状态：**方向已对齐，待开工**（数据/代码探查已完成，见「附录 · 代码级事实」）。

## 1 产品定位

一句话：**把「外部投顾组合的调仓」变成「我自己组合的再平衡参考信号」。**

用户关注（自选）了一批看好的投顾组合 / 头部产品。这些组合调仓时自带调仓理由。系统捕捉这些
调仓，聚合提醒用户，并在用户主动追问时，用 LLM 基于**实际调仓动作 + 当前持仓**做深度解读，
最后给出「我的持仓 vs 它的持仓」的客观对照，帮助用户做优胜劣汰的理性判断。

### 1.1 价值锚点

- **对抗行为偏差**：用户买入后受近因效应 / 损失厌恶影响，舍不得卖。用**数据**给出一个
  「理性退出」的理由，说服力强于主观感受，用户基于数据做判断。
- **说的 vs 做的分歧识别**（差异化点）：主理人的调仓理由（文本）只是** B 级数据**，实际
  调仓动作（pre_ratio / after_ratio）才是 **A 级数据**。两者分歧时显式提醒用户——「他说的
  未必是他做的」，权威性反而更高。

### 1.2 功能边界（三条链路）

| 链路 | 触发 | 产物 |
|---|---|---|
| 监控提醒 | 定时抓取，发现关注组合调仓 | 聚合提醒「你关注的产品调仓了」 |
| 调仓解读 | 用户主动追问（LLM 触发式） | 深度分析：看好什么方向、加成长还是权益 |
| 对比建议 | 解读的一部分 | 我的持仓 vs 它的持仓的重合度 + 指标对照 |

三条链路都做，**重头戏在「调仓解读」**（高价值部分），监控提醒是已有功能的增强，不是从零。

## 2 合规边界（收费前提，不可越）

收费 + 个性化 = 证券投资咨询业务，需持牌。因此**必须落在「客观数据对照」而非「投资建议」**。

| 形态 | 合规判定 |
|---|---|
| 「B 回撤 −12%，你持有 A −28%」 | ✅ 客观事实 |
| 「B 夏普 1.2 > A 0.4，表现更稳健」 | ✅ 客观对比 |
| 「该产品在回撤 / 夏普 / 收益率上表现更优」 | ✅ 柔性提醒（合规） |
| 「**建议**你把 A 换成 B」 | ⚠️ 踩线（个性化投资建议） |
| 「**自动**帮你卖出 A 买入 B」 | ❌ 越界（代客理财，坚决不做） |

关键在**动词**：柔性提醒是「陈述」，下指令是「观点」。红线 = LLM 输出不得出现
「建议 / 推荐 / 应该买入 / 卖出 / 替换」等指令性措辞，只允许「对照 + 呈现 + 由你判断」。

**现状（代码级）**：Agent 已有三道合规防线——`intent_guard.py`（输入侧，进模型前拦）、
`output_filter.py`（输出侧 R1~R10 规则 + E1 兜底）。**缺的不是新建拦截，而是「让模型生成时
就主动避开风险措辞」的输出范式 prompt**。L4 的合规工作 = 给「调仓解读」场景写一份专门的
输出范式 prompt，复用三道防线兜底。

## 3 组合分类 → 同类对比 → 声明范围

### 3.1 为什么必须分类

**「偏债 vs 偏股」的对比没有价值**——两者风险收益结构根本不同，夏普 1.2 的偏债组合和夏普
1.2 的偏股组合含义完全不同，拿它们互比「谁更强」等于苹果比橘子。

### 3.2 分类口径

组合资产类型按数据可得性分三级（从准到糙）：

| 判定源 | 依据 | 可得性 |
|---|---|---|
| 持仓穿透 | 组合持仓基金类型的加权（股票型 + 偏股混合占比） | 最准，依赖持仓明细 |
| 风险等级 | `risk_level`（R1~R5） | 已抓取，粗但快 |
| 策展字段 | `product_type`（人工维护） | 已落地，需人工 |

偏股 / 偏债判定线（用持仓穿透算「权益占比」，按阈值分档，阈值可后续校准）：

- 权益占比（股票型 + 偏股混合 + 指数 + QDII 加权）≥ 60% → **偏股类**
- 权益占比 ≤ 40% → **偏债类**
- 40% ~ 60% → **平衡类**（单独一类，或提示「混合型，对比意义有限」）

### 3.3 产品决策：产品替用户决定 + 显式声明范围

**不让用户做分类，产品自动分类，但必须显式声明「本次对比的范围」。** 理由：

1. 用户没能力也没意愿做金融分类题，只想问「这个组合调仓对我有什么参考」；
2. 分类可自动化（`risk_level` / 持仓加权 / `product_type` 都能判）；
3. 「声明范围」本身就是产品价值 + 合规透明：告诉用户「本次在偏股类内对比，已剔除 X 个偏债
   产品」，既避免误导，又守住边界。

## 4 「账户集」数据层界定

「账户集」= 该用户名下所有持仓中**权益类产品打包的虚拟集合**，是「我的组合」这个对比维度的
主口径。

| 维度 | 判定规则 | 数据来源 |
|---|---|---|
| 权益类边界（纳入） | 股票 + 股票型基金 + 混合型（偏股）+ ETF + QDII + 指数型 | 持仓 `asset_type` + 基金 `fund_type` |
| 排除项 | 货币基金、债券型、银行理财 / 存款 | 这些不做分析（用户明确「分析没意义」） |
| 对比对象 | 账户集持仓 vs 外部投顾组合持仓 | `positions` 表 vs `advisor_holdings` 表 |

**两个必须支持的维度**：投资组合（单组合）、账户集（全部权益产品打包）。

**待拍板口径**：混合型基金里「偏债混合」（债券占比 >50%）算不算权益类？建议按 `fund_type`
二级分类（"混合型-偏股"算、"偏债"不算、"平衡"看仓位），不搞一刀切。

## 5 载体（UX）

统一成一个**可复用「解读抽屉」组件**，三个高频入口初始深度不同：

| 入口 | 心智 | 初始深度 |
|---|---|---|
| 自选页 | 主动浏览，注意力完整 | 速览（先看「调仓了、方向是什么」） |
| 组合页 | 决策场景 | 决策深度（直接展开「我的持仓 vs 它的对照」） |
| 消息箱（首页铃铛） | 打断式提醒，注意力碎 | 内嵌速览 + 「去组合页看对照」深链 |
| 账户对话页 | 例外 | 内联完整分析块，不用抽屉 |

**消息箱不要跳独立页**：铃铛是打断式提醒，跳页把「看一眼」变「一个任务」，中途流失率高。
抽屉让用户「看完结论、想深挖再点进去」，上下文不断。

## 6 数据缓冲层（抓 vs 算 vs 存）

### 6.1 核心原则

**「抓优先、算兜底、存复用」**——避免每次分析都现场调 MCP，用缓冲层（快照表）+ 分类型 TTL。

- **能抓官方值就抓**（回撤/夏普官方披露值最权威，口径无争议）；
- **抓不到才自算**（底料是净值序列，复用已有 job，不新增链路）；
- **有价值数据缓存下来**，按数据类型分 TTL，避免每次分析都现场拉（性能 + 成本双重考量）。

### 6.2 分类型 TTL

| 数据类型 | 更新频率 | TTL |
|---|---|---|
| 净值 | 天天变（T+1） | 1 天 |
| 持仓明细 | 季报披露（滞后 1~3 月，天然滞后不需管） | 按披露周期 |
| 风格标签 | 季报 / 半季报 | 按披露周期 |
| 回撤 / 夏普 | 净值驱动，增量更新 | 随净值 |

### 6.3 抓 vs 算结论（2026-11-24 实测，已钉死）

**核心事实：回撤 / 夏普「能直接抓」的，且已经在抓、在落库。之前「天天要自算」的判断是错的。**

| 平台 | 回撤/夏普 | 净值序列 |
|---|---|---|
| 好买 HOWBUY | ✅ 直接抓（`clcphbzst.json` 已抓） | ✅ `clcplshb.json` 实测可用，Port 没接 |
| 天天 TIANTIAN | ✅ **直接抓，已落库**（`getTGQuoteByFavor` 的 `MAXRETRA_LN`/`SHARPE_LN`，2026-10-29 适配器已修） | ❌ 无公开净值序列端点 |
| 且慢 QIEMAN | ✅ 有净值序列 + 已抓回撤/夏普 | ✅ MCP `GetPortfolioNavHistory` 已跑通（2384 行/只） |

**实测数据（`backend/invest.db`，2026-11-24 探针 + 库内核查）：**

- 天天基金 3 只组合回撤 / 夏普 **3/3 全部填充**，数值与实时抓取一致（如越海 `XCOVSEX` 回撤
  24.33%、夏普 0.07）；且慢 102 只回撤 100 填充、夏普 97 填充、波动率 97 填充。
- 唯一真空缺：天天 / 好买组合的**净值序列**（天天无公开端点；好买 `clcplshb.json` 实测可用但
  Port 没接）。但回撤 / 夏普已有官方值，**不需要净值序列来算**——净值序列只用于「组合走势图」，
  与「谁更强」的判据无关。

**推论（成本账彻底算清）：**

- **L2「补回撤/夏普」其实已经是「已办结」状态**——判据数据（回撤/夏普/波动率）三平台都能拿到、
  且慢 + 天天已在库，唯一空的是好买组合（Port 已接 `clcphbzst.json`，缺的是「把值写进库」而非
  「取不到值」）。
- **「算」这条路可以基本放弃**：`fund_risk_metrics.py` 引擎虽现成，但回撤/夏普有官方值就不必
  自算（口径无争议、最权威）。自算仅作为「且慢个别组合官方值缺失」的兜底。
- **净值序列不是本功能的地基**：它服务于走势图展示，与「谁更强」的判据（回撤/夏普/收益）正交。
  之前把「净值序列」抬到「没有它其他都是镜花水月」的高度，是**把两个正交问题混为一谈**。

- **目标池已守纪律**：`tracked_codes` 只取「自选 ∪ 持仓」，不做全库刷。
- **「存 vs 现拉」判据已写好**：`advisor_nav.refresh_series` 库里净值 >3 天且进程内 6 小时没试过
  才补拉——净值是低频更新 + 高复用，存下来边际成本趋近于零。

## 7 落地顺序

```
第一步：L3 跨组合对比（我的账户集 vs 投顾组合的重叠 + 风格 + 指标对照）——唯一真缺口，直接起
第二步：L1 聚合提醒（多组合同期调仓触发）
第三步：L4 解读（含「说的 vs 做的」分歧识别）
（L2 已办结：回撤/夏普/波动率三平台官方值已在库，无需自算）
```

L3 是整个功能能否成立的**地基**——先跑通「我的持仓 vs 投顾组合，能不能真算出『对方回撤更小、
夏普更高』」的对照。判据数据（回撤/夏普/收益）已齐，缺的只是「跨组合」这个比对方向。

## 7.1 L3 跨组合对比设计（2026-11-24 已对齐，进入实现）

### 决策（已拍板）

1. **核心口径 = 基金代码级重合**（非穿透到股票/风格）。实证：投顾持仓 `advisor_holdings`
   是**基金级**（`fund_code` 6 位 + `after_ratio`），我的持仓 `positions` 归一后也是基金码；
   本机库实测投顾成分 1068 只、我的基金持仓 157 只、**重合 58 只**——基金级重合可靠、直接。
2. **权益边界 = 按 `fund_type` 剔除偏债**。库里 `fund_types` 只有 5 个一级大类
   （混合型/股票型/指数型/债券型/货币型），**无二级「偏股/偏债」分类**；`equity_position`
   （权益仓位）覆盖率仅 167/26975（0.6%），不能作主判据。故：剔除「货币型」「债券型」
   一级分类 + 持仓 `type` 的 bond/money_fund；「混合型」暂不细分（平衡仓视为权益类兜底）。

### 数据流

1. 投顾组合基金级持仓（`advisor_holdings` 最新快照日），剔除货基/债基成分
   （用 `fund_utils._lookup_market_type_names` 跨域查 `fund_types.name`）；
2. 我的账户集权益持仓（`positions` 中 `type` ∈ fund/etf/stock，剔除 bond/money_fund），
   用 `normalize_fund_code` 归一 6 位码；
3. 基金代码级三集合：交集（共同持有）、投顾独有（它持我无）、我独有（我持它无），
   各带占比/市值；
4. 指标对照：组合 `max_drawdown`/`sharpe_ratio`/收益（复用 `advisor_profile`）vs
   我的账户集对应指标（用 `fund_risk_metrics` 现算或聚合）。

### 关键发现（实证）

投顾组合持仓快照里混入大量货基（如「南方天天利货币B」占 66.71%）——投顾普遍用货基做
现金管理/流动性缓冲。**不剔除货基，基金级重合对比会被货基污染**（交集里一堆货基无意义）。
这印证了「账户集要排除货基/债基」的口径判断。

### 落地形态

- 服务层 `app/services/advisor_comparison.py`（独立文件，参照 `advisor_profile.py`）；
- 端点 `GET /api/funds/advisors/<code>/compare/`（独立蓝图 `advisor_comparison_views.py`，
  funds/views.py 已顶到视图厚度基线上限，不能加行）；
- 降级契约：投顾组合不存在 → 404；取数失败 → `degraded=True`（不拿 0 冒充）。

## 9 附录 · 代码级事实（探查结论）

### 9.1 四层现状（非从零做，是接通已有半成品）

| 层 | 已有资产 | 缺口 |
|---|---|---|
| L1 监控 | 天天/且慢/好买三适配器已落地；`advisor_adjust_histories.reason` 已在抓在存（天天 `getAdjustWarehouse tag=1` 的 `reason`、且慢 GraphQL `comment`、好买 `ms1`） | 「多组合同期调仓 → 聚合提醒」链路 |
| L2 指标 | `fund_risk_metrics.py`（回撤/夏普/索提诺/卡玛/溃疡引擎）；风格箱 `fund_style_exposures` + `dominant_style` 已落地；**组合级回撤/夏普/波动率已落库**（天天 3/3、且慢 100/102） | 好买组合回撤/夏普可能未落库（待核）；天天/好买净值序列缺失（但与判据无关） |
| L3 对比 | `holding_overlap.py`（重叠）+ `holding_correlation.py`（相关性） | 现做「**我的组合内部**」两两重叠，非「我的 vs 外部投顾组合」 |
| L4 解读 | Agent 底座有 | 「调仓解读」编排；「说的 vs 做的」分歧识别（数据已齐，reason + pre/after_ratio 两列都有） |

### 9.1.1 「说的 vs 做的」数据质量实证（2026-11-24 库内核查）

调仓记录三列（`reason` / `pre_ratio` / `after_ratio` + `op_name`）填充率**极高**，
「分歧识别」的数据底座已齐备：

| source | 记录数 | 有理由 | 前后占比 | 操作名 |
|---|---|---|---|---|
| qieman（手动） | 38 | 38/38 | 38/38 | 38/38 |
| qieman_official | 16793 | 16422 | 16793 | 16793 |
| tiantian | 1286 | 1286/1286 | 1286/1286 | 1286/1286 |

**但「理由文本」质量参差，正是「说的 vs 做的」要解决的核心：**

- 天天基金理由极简，几乎是模板话术（如「资产配置结构优化。」一句话），文本价值低；
- 且慢官方理由相对有信息量（如「基于对明年的经济环境、政策空间、盈利环境和当前各领域的估值
  情况，结合投资信号综合评估…」），但仍偏宏观套话。

**结论**：调仓理由（B 级数据）不足以支撑解读，**基于实际动作（pre/after_ratio，A 级数据）的
独立研判才是价值所在**——这印证了产品定位「说的当 B 级、做的当 A 级、分歧时提醒」。
