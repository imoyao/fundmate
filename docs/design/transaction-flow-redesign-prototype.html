交易流水 · 桌面端重设计

同一份流水，两种看法：表格用来对账、找单笔、改数；流水线用来复盘资金节奏。两套视图共享同一套筛选、同一个账户轴、同一份文案——切换只换呈现，不换数据。 手机端只能纵向堆叠，桌面端有横向空间，所以这里不是把 App 放大，而是把「账户」和「方向」摆成两条稳定的参考轴。

颜色只回答一个问题：这笔钱往哪个方向走。状态、账户、备注一律退回墨色层级。

字体 · 2 个字族

Inter / MiSans 承担中文与标签（13–14px，行高 1.6）。
SF Mono / JetBrains Mono 只给数字：金额、价格、份额、日期、笔数。

金额一律 tabular-nums， 小数点纵向对齐——这是表格能被「扫」而不是被「读」的前提。

字阶只用三档：页标题 30/300、行内主信息 14/500、元信息 12/400。没有第四档。

版式 · 三条横带

页头（我是谁）→ 汇总条（这段时间发生了什么）→ 筛选 + 列表（具体哪一笔）。 列表卡内再分两层：卡头（视图与计数）+ 内容。

表格 11 列，总宽 1086px，卡在默认列预算 1132px 内，1366 屏（可视 1098）不横滚。 流水线用 7 列固定栅格，账户列独立成列——同一账户的流水上下对齐，扫一眼就是「这个账户最近在干什么」。

原则 · 三条自守

① 一屏只有一个视觉焦点：列表本身。汇总条压到一行，不用 5 张大数字卡。
② 状态默认不出声：「成功」是常态，常态不染色。
③ 已清仓不是「坏数据」：不打灰、不删除，只加一枚安静的胶囊。

逐项对照：旧 → 新

位置旧实现新设计理由
孤儿流水标记 「已删除」灰字 + 整格 opacity .5 + grayscale 名称右侧一枚 已清仓 胶囊（--bg-soft 底 / --text-tertiary-ink 字），不打灰；悬浮说明「持仓已清仓或被合并，流水与金额保留」 「已删除」是数据库视角，用户做的是「清仓」；整格置灰把一条真实流水说得像失效数据，可读性也一起丢了
账户级流水 存入 / 取出（账户现金）也打「已删除」——它们本来就没有持仓行 按类型判定：deposit / withdraw 视为账户资金流水，不打任何标记，代码位显示「资金流水」 假阳性。用户看到「账户现金 存入 ¥68.76 已删除」会以为钱没了
内部代码 资产名下方显示 # _CASH_ 下划线开头的内部代码一律不显示（__CASH__ 等），无障碍名由名称承担 内部标识泄漏到界面，既不可读也不可核对
账户 表格里没有账户列；流水线里是「账户：xxx」纯文本，不可点 表格独立成列（第二位），流水线独立成列；统一为可点胶囊 账户名 › → /asset/ledgers/:id。无 ledger_id 的显示虚线「未归属账户」，不伪装成链接 「这笔钱在哪个账户」是核对流水时最常问的第二句话；不可点就等于要用户自己再去账户页找
状态 每行一枚绿色 el-tag「成功」 成功＝12px 灰字、不出声；只有 失败（危险色）、可撤单（沙金）才着色，已撤单加一枚描边胶囊 「红绿灯」式满屏彩色标签会把注意力从金额上拽走；常态不该抢戏
类型着色 --color-rise / --color-fall 直接作文字 改用 --color-rise-ink（5.6:1）/ --color-fall-ink（5.7:1） 现值的白底对比度 3.86:1 / 2.0:1，正文档不达 AA。这是既有缺陷，顺手一并修
斑马纹 stripe + 两行产品单元 去斑马纹，用 --border-light 行分隔线 + 悬停 --bg-soft 条纹底是冷灰 --bg-muted，与暖色体系并置发脏；行高 48px 有两条信息线，条纹反而增加噪点
筛选 4 个下拉平铺 + 刷新按钮，类型是下拉 一级＝交易类型分段控制器（全部/买入/卖出/分红/存入/取出，≤6 平铺）；二级＝资产 / 状态 / 时间三个下拉 + 重置 类型是最常用的维度，藏进下拉每天多点两次；六个选项正好在分段控制器适用域内
时间分组 按日折叠，默认展开近 30 天 按月分组，月头 sticky 并带月内合计（笔数 / 买入 / 卖出 / 净额），默认展开最近两个月 桌面上「一天」往往只有一两笔，按日分组全是空折叠头；按月才有节奏感，也和手机端「交易记录」的心智一致
金额口径 表格无符号、流水线带正负且自动染色 表格＝成交额（无符号）；流水线＝资金流向（±，不染色），并标注「＋入账 / −出账」 流水金额不表示涨跌，染红绿是错误语义（共享组件自己也是这么写的，流水线这处属于漏网）
页面头部 h2 + 副标题 + 一张筛选卡（页头下又起一条工具条） 一层页头（标题 / 副标题 / 右侧操作槽），筛选与列表同处一张卡 design.md「一层页头」原则：页头之下不再另起工具栏
汇总 无 一行汇总条（买入 / 卖出 / 分红 / 手续费 / 净投入），跟随筛选范围 参考手机端的「交易总览」，但压成一条：这页的主角是列表，不是指标卡

自检 · 第二遍

从手机端拿了什么，没拿什么

手机端的做法这里为什么
按月 / 按日分节的纵向流水（图 1）拿：月分组 + 月内合计，落在流水线视图分节回答的是「这段时间的节奏」，与屏宽无关
顶部「交易汇总」四宫格大数字（图 2、图 3）改造：压成一行汇总条手机竖屏没横向空间，只能用大卡片；桌面把 5 个数字铺成一行 40px 高就够了，列表才是主角
每行右侧的「›」进入详情不拿：改为 hover 出「编辑」桌面没有「进入详情页」这一步的空间成本，抽屉/弹窗更直接；「›」在宽屏上会变成一排噪音
「清仓分析」卡（图 2）不拿那是分析历史持仓周期，属于另一个功能面，不是流水列表的一行
「已撤单」跟在金额后（图 2）改造：金额划线 + 状态列写「已撤单」桌面上状态有独立列，重复标注两遍是冗余

是不是换了张皮的通用后台？

  • 配色、字体、圆角、阴影全部来自 design.md，不是自选色板 —— 所以「独特性」不在色板上，在信息结构：账户轴（每一行都能回答「在哪」并一步跳过去）+ 月轴（时间有节奏）+ 方向色（颜色只表示加仓 / 减仓）。
  • 没有 01/02/03 编号（月份是真实序列，不是装饰性序号）、没有全大写小标签、没有渐变卡片、没有 emoji 当图标。
  • 砍掉的一件配饰：本来想给每个账户一个色点（像银行卡），但账户色会和涨跌色抢同一个注意力通道，而且 6 种颜色过不了对比度。统一成墨色胶囊 + hover 出箭头 —— 少一件，反而更清楚。

待决 · 需要你拍板

  • 汇总条要不要做？它需要新接口（1 个端点，逻辑与列表同筛选）。若这轮只想改视觉与文案，可先不做，页面结构不变。
  • 行高 48px：两行产品单元 + 胶囊的必要高度。要么按 48px 登记为例外，要么压回 44px（名称与代码挤在 2px 内边距里，观感偏紧）。
  • 「已清仓」是否够准？目前 position_id IS NULL 有两种成因：用户清仓、导入时旧持仓被合并（备注里会写「基金持仓迁移为…」）。文案统一成「已清仓」，细节交给备注与 tooltip；若要更精确，需要后端回一个 position_state 字段。
  • 「清仓分析」卡（手机端第二张图）属于另一个功能面——分析历史持仓的完整周期，不在这页范围。
  • 是否需要行展开详情（确认日 / 来源 / 备注全文 / 编辑）？原型先走 hover「编辑」，展开行是下一步。
