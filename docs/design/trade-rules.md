## 3. 校验逻辑

### 3.1 买入校验 (validate_buy)

**入参**: `current_hold` (现有持仓), `order_qty` (委托数量), `min_unit`, `step`
**前置条件**: `order_qty > 0` (正整数)

分两档判断：

1. **现有持仓 < min_unit** (含空仓)
   允许小额补仓，**不校验**委托数量是否满足 `min_unit` 和 `step`，仅要求 `order_qty > 0`。
2. **现有持仓 ≥ min_unit**
   委托数量必须满足 `order_qty ≥ min_unit` 且 `(order_qty - min_unit) % step == 0`。

> 说明：该规则既兼容了实盘“补足零散底仓”的需求，又避免人为制造新的零散持仓。

### 3.2 卖出校验 (validate_sell)

**入参**: `total_hold` (总持仓), `order_qty` (委托数量), `min_unit`, `step`
**前置条件**: `order_qty > 0` 且 `order_qty ≤ total_hold`

判断流程（按优先级）：

1. **全额清仓**
   若 `order_qty == total_hold`，直接放行（不受任何步长/零头限制）。
2. **持仓不足最小单位**
   若 `total_hold < min_unit`，仅允许 `order_qty == total_hold`（已在第 1 步覆盖），其他任何数量均拒绝。
3. **持仓 ≥ 最小单位**
   - 禁止单独卖出“不足一手的零散部分”。
   - 委托数量必须满足 `order_qty ≥ min_unit` 且 `(order_qty - min_unit) % step == 0`。
   - 示例：主板持仓 150 股，min=100，step=100 → 允许卖 100 或 150，禁止单独卖 50。

## 4. 兼容性处理

- 保留 `skip_lot_check` 参数（用于导入历史交易）。
- 当 `skip_lot_check=True` 时：跳过所有手数/步长/整手校验，仅保留基础校验（数量为正、卖出不超持仓）。

---

## 5. 错误提示

所有校验函数返回 `(is_valid: bool, message: str)`，直接返回中文提示，不额外封装枚举。典型文案示例：

- “买入数量必须大于 0”
- “当前持仓不足一手，只能一次性全部卖出”
- “卖出数量必须是 100 的整数倍”
- “沪市可转债卖出必须为 10 张的整数倍”
- “禁止单独卖出不足一手的零散持仓”

## 6. 暂不实现项

- **T+1 可用持仓限制**：本期不引入 `available_quantity` 字段，卖出均基于总持仓。标记为 P2 待评估。
- **场内基金细化规则**：货币基金不进入持仓校验，ETF/LOF 复用股票规则，暂不单独处理。
- **科创板市价委托步长**：当前系统不支持市价委托，仅支持限价委托，故 step=1 适用。
