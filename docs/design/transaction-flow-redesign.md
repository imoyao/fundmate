# 交易流水 · 桌面端重设计

**状态**：设计定稿 v1.2（2026-11-01 落实施，见 §十三）· 三条横带全部落地（汇总条含后端端点）
**原型**：`docs/design/transaction-flow-redesign-prototype.html`（可交互，单文件离线可开）
**范围**：`/asset/transactionList` 桌面端（表格视图 + 流水线视图）· 边界见文末「不做」

> **v1.1 与 v1.0 的差异（实测推翻了初稿的两处判断，实施时以本文为准）**
> 1. §三「已清仓」的判据**从 `position_id === null` 改为后端下发的 `position_state`**：
>    #2343 起清仓不再删行（`ownership_status='cleared'`），已清仓的流水 `position_id` 仍有值，
>    按 null 判会让胶囊几乎永不出现。
> 2. §十二-2 的行高：实测 `tr` 的 `height` 是**最小高度**语义，两行产品单元 + 胶囊会自然撑高，
>    无需把全局 44px 基线改成 48px（改了反而影响账本 Tab 与持仓抽屉）。

## 一、谁的什么问题

现在这页能看能筛，但有四处让「对账」这件事变慢：

| # | 现象 | 代码证据 | 为什么是问题 |
|---|---|---|---|
| 1 | 已清仓的流水打「已删除」，且整格 `opacity .5 + grayscale` | `components/TransactionTable/index.vue:126` 输出「已删除」，`:316` 定义整格置灰 | 「已删除」是数据库视角，用户做的是「清仓」。一条真实发生过的买入被涂成失效数据，金额与日期一起看不清 |
| 2 | 账户级流水（存入 / 取出）也被打「已删除」 | 同一判据 `position_id === null` 覆盖了 `deposit` / `withdraw`——它们本来就没有持仓行 | 假阳性。用户看到「账户现金 · 存入 ¥68.76 · 已删除」会以为钱没了 |
| 3 | 表格没有账户列；流水线里只是「账户：xxx」纯文本，不可点 | `TransactionTable/index.vue:210` 有 `showAccount` 开关但流水页没传；`TransactionTimelineView.vue:146` 是纯文本 | 「这笔钱在哪个账户」是核对流水时最常问的第二句话。知道而不给跳转，等于让用户自己去账户页翻 |
| 4 | 流水线按**日**折叠，默认展开近 30 天 | `transactionListModel.ts:72 groupByDate` / `:112 isDateInLast30Days` | 桌面上一天通常只有一两笔，按日分组就是一屏空折叠头；节奏感被切碎 |

外加一处既有缺陷：类型色用 `--color-rise` / `--color-fall` 直接作文字，白底对比度 **3.86:1 / 2.0:1**，正文档不达 AA。

## 二、设计计划

### 颜色 · 五个角色

| 角色 | 值 | 用途 |
|---|---|---|
| 纸 | `#fdfbf7` / `#f5f0eb` | 页面底 / hover 底（暖奶油档，沿用 `design.md`） |
| 进 | `--color-rise-ink` `#c0341f` | 买入、存入（加仓方向） |
| 出 | `--color-fall-ink` `#1f6b43` | 卖出、取出（减仓方向） |
| 墨 | `#2d2a24` / `#716a60` | 数字与一切非方向信息 |
| 边 | `--border-light` | 行分隔（取代斑马纹） |

**颜色只回答一个问题：这笔钱往哪个方向走。** 状态、账户、备注一律退回墨色层级——这是本设计最硬的一条自律，也是它不像「通用后台」的地方。

### 字体 · 两个字族

- **Inter / MiSans**：中文与标签，13–14px，行高 1.6。
- **SF Mono / JetBrains Mono**：只给数字——金额、价格、份额、日期、笔数。全部 `tabular-nums`，小数点纵向对齐。

字阶只用三档：页标题 30/300、行内主信息 14/500、元信息 12/400。**没有第四档。**

### 版式 · 三条横带

页头（我是谁）→ 汇总条（这段时间发生了什么）→ 筛选 + 列表（具体哪一笔）。列表卡内再分两层：卡头（视图 + 计数）+ 内容。

```
┌─ 页头（一层页头 · 操作槽在右）
│   交易流水                                         [导出 CSV]
│   买入、卖出、转入转出的完整记录，按交易日倒序排列
├─ 汇总条（跟随筛选，一行读完就够）
│   近一年 · 买入 ¥86,320.44 24笔 · 卖出 ¥42,100.00 11笔
│          · 分红 ¥312.50 3笔 · 手续费 ¥28.45 · 净投入 +¥44,220.44
├─ 筛选（一级 = 分段控制器，二级 = 三个下拉）
│   [全部][买入][卖出][分红][存入][取出]   资产▾  状态▾  时间▾   ↻
├─ 列表卡
│   卡头：[表格|流水线]        共 N 条 · 按交易日倒序 · 金额不含手续费
│   表头：资产(冻结) │ 账户 │ 日期 │ 类型 │ 价格 │ 数量 │ 金额 │ 手续费 │ 状态 │ 备注 │
│   行：  名称 [已清仓] │ 招商证券› │ 2026-10-13 │ 买入 │ 2.9223 │ 3,421.96 │ …
│          # 021180      ↑ 可点跳账户                ↑ 涨红(ink)      ↑ tabular-nums
└─ 流水线视图：月分组（sticky 月头 + 月内合计）
    日期 │ 类型 │ 资产 + 备注 │ 账户 │ 金额(±) │ 状态
```

**列宽预算**：表格 11 列的目标宽度合计 **1086px**（各列下限），表格 `width: 100%` 随容器拉伸；1366 屏可视 1098 → **不横滚**。流水线用 7 列固定栅格，账户独立成列——同一账户的流水上下对齐，扫一眼就是「这个账户最近在干什么」。

> **实测（2026-11-01，Chromium 打开 `file://` 原型）**：表格渲染宽度 1440 视口 **1106px**、1366 与 1280 视口 **1088px**；三个视口下 `documentElement.scrollWidth === clientWidth`，**均无横向滚动**。即「1086」是列宽预算不是渲染宽度——实施时判据用「无横向滚动」，不要拿 1086 当死值。

### 原则 · 三条自守

1. **一屏只有一个视觉焦点：列表本身。** 汇总条压到一行，不用 5 张大数字卡。
2. **状态默认不出声。**「成功」是常态，常态不染色。
3. **已清仓不是「坏数据」。** 不打灰、不删除，只加一枚安静的胶囊。

## 三、语义规则（本设计的核心）

每条都是「判据 → 渲染 → 为什么」。这几条一旦写错，页面不报错、只是慢慢说谎。

| 规则 | 判据 | 渲染 | 为什么 |
|---|---|---|---|
| 持仓状态三态 | **后端下发 `position_state`**（`held` / `cleared` / `account`），判据实现在 `services/txn_name_resolver.resolve_transaction_position_states` | 见下三行 | 判据要看 `ownership_status` 与「持仓行是否还在」两件事，前端只有 `position_id`，猜不出来；而且这套口径已经变过一次（#2343 清仓不删行），前端抄的那份必然滞后 |
| 已清仓 | `position_state === 'cleared'` | 名称右侧一枚**已清仓**胶囊（`--bg-soft` 底 / `--text-tertiary-ink` 字），**不打灰**；`title`：「持仓已清仓或被合并，流水与金额保留」 | 用户做的是清仓，不是删除。整格置灰把真实流水说得像失效数据，顺带毁掉可读性 |
| 账户级流水 | `position_state === 'account'`（后端按 `type ∈ {deposit, withdraw}` 判） | **不打任何标记**；名称旁一枚「资金流水」弱化字 | 存入 / 取出本来就没有持仓行，标「已删除」是纯假阳性 |
| 内部代码 | `symbol` 以 `_` 开头（`__CASH__` 等） | **整段不渲染代码位**（而不是印 `# --`）；无障碍名由资产名承担 | 内部标识泄漏到界面，既不可读也不可核对 |
| 账户 | `ledger_id` 有值 / 无值 | 统一为可点胶囊 **账户名 ›** → `/asset/ledgers/:id`；无 `ledger_id` 时是虚线「未归属账户」，**不伪装成链接**（无箭头、`title` 说明不可跳转） | 可点与否必须能从外观分辨，否则用户点了没反应 |
| 状态 | `status` | 成功 / 未知＝12px 灰字、不出声；只有**失败**（危险色）、**可撤单**（沙金）着色；**已撤单**加描边胶囊 | 满屏绿色「成功」标签会把注意力从金额上拽走 |
| 类型着色 | `type` | 一律 `-ink` 令牌 | 现值 3.86:1 / 2.0:1 不达 AA，顺手一并修 |
| 金额口径 | 视图 | 表格＝成交额（**无符号**）；流水线＝资金流向（**±，不染色**），标注「＋入账 / −出账」 | 流水金额不表示涨跌，染红绿是错误语义（共享组件自己在注释里也是这么写的，流水线那处属漏网） |
| 斑马纹 | — | 去掉，改 `--border-light` 行分隔 + hover `--bg-soft` | 条纹底是冷灰 `--bg-muted`，与暖色体系并置发脏；行内已有两条信息线，条纹只增噪点 |

**关于红与绿**：这里不是「涨跌」，是「敞口增减」——红＝增加敞口（买入 / 存入），绿＝减少敞口（卖出 / 取出）。之所以仍用红绿，是因为 A 股用户的肌肉记忆就是「红增绿减」；但两个色值都取 `-ink` 档且**只允许出现在类型列与方向列**，金额列一律墨色。一旦让金额也染红染绿，读者就会把「卖出得了一笔钱」读成「亏了」。

## 四、汇总条口径（**数字必须有公式**）

汇总条是这次唯一新增的「聚合数字」。仓库里已经有过「已实现盈亏两套口径并存、互相矛盾」的先例，所以这里先把公式钉死，再由后端按同一公式返回——前端不做二次求和。

| 指标 | 公式 | 单位 / 说明 |
|---|---|---|
| 买入 | `Σ amount WHERE type = 'buy'` | 成交额（**不含手续费**），带笔数 |
| 卖出 | `Σ amount WHERE type = 'sell'` | 同上 |
| 分红 | `Σ amount WHERE type = 'dividend'` | 同上 |
| 手续费 | `Σ fee`（全类型） | 单独一行，不进任何金额 |
| **净投入** | `买入 + 手续费 − 卖出 − 分红` | 「为了这套持仓，我净从口袋里放进去多少钱」。正数＝净投入，负数＝净取出，符号必须显示 |

**为什么不把手续费摊进买入**：摊进去以后「买入金额」就不再等于成交额，与表格的金额列对不上；用户拿汇总条去核表格会差一笔，而差在哪儿看不出来。手续费单独一行，四个数各自可核。

⚠️ **原型里的数字是示意，不等于本公式**：原型页汇总条显示「净投入 +¥23,381.14」，恰为 `50,541.76 − 27,160.62`，未计手续费与分红。实施时以本节公式为准，**不要照抄原型的数值**。

> **实施（v1.2）**：`GET /api/transactions/summary/` → `services.build_transaction_summary`。
> 一次 `GROUP BY txn_type` 取齐四个数，**分做整数运算**、只在出口换算元（浮点累加在几百行上
> 就会出现 0.01 漂移，而这是印在屏幕上的钱）。筛选与列表**共用**同一套 WHERE；前端零求和。
> 两条判据钉在测试里：公式（56）与「25 笔不分页」。存款/取款不计入净投入（资金搬运不是
> 为持仓投进去的钱），但它们的**手续费计入**——这一差异由 `test_fee_covers_all_types_but_net_only_uses_four` 守。

## 五、月分组

| 项 | 规则 |
|---|---|
| 粒度 | 按**月**，不按日。桌面上一日一两笔，按日分组全是空折叠头 |
| 月头 | sticky，带月内合计：笔数 / 买入 / 卖出 / 净额 |
| 默认展开 | 最近**两个月**（原为近 30 天） |
| 心智对齐 | 与手机端「交易记录」的分节一致——分节回答的是「这段时间的节奏」，与屏宽无关 |

## 八、无障碍与响应式基线

- **对比度**：方向色一律 `-ink` 令牌；本设计引入的胶囊用 `--text-tertiary-ink` on `--bg-soft`，不靠透明度区分状态。
- **键盘**：账户胶囊、编辑按钮、分段控制器全部可 Tab 可达且 `:focus-visible` 有可见环；行本身不可点（避免「点了没反应」）。
- **动效**：只保留响应用户动作的（浮层、hover 200ms）；`prefers-reduced-motion: reduce` 下过渡压到 0.01ms；无编排式入场。
- **语义**：状态不只靠颜色（文字 + 描边/字重）；已清仓用胶囊（文字）而非灰度。
- **不做 emoji 当图标**；图标一律 EP 图标或内联 SVG，`aria-hidden` 并配文字名。

## 十、验收判据

1. 表格视图无「已删除」字样；`position_state === 'cleared'` 的行显示「已清仓」胶囊，且该行 `opacity` 与 `filter` 均为默认值（`grep` 不到整格置灰的样式规则）。
2. `position_state === 'account'` 的行走 `account` 分支：无胶囊、名称旁为「资金流水」弱化字。
3. `symbol` 以 `_` 开头时不渲染代码位；该单元格无障碍名仍含资产名。
4. 两条视图都有账户列；有 `ledger_id` 时是 `a[href]` 指向 `/asset/ledgers/:id`，无 `ledger_id` 时为非链接元素且带「未归属账户」文本。
5. 状态列：`success` 无背景色标签（纯文字）；`failed` / `cancelled` 按规则着色或描边。
6. 流水线视图按月分组，月头 `position: sticky`，月内含笔数/买入/卖出/净额；默认展开最近两个月。
7. 流水线金额显示 ± 且**不含** `--color-rise-ink` / `--color-fall-ink` 作为文字色（涨跌色只属于方向列）。
8. 类型色对比度 ≥ 4.5:1（白底），`audit_text_contrast` 静态复核通过。
9. 无横向滚动：1366px 视口下 `document.documentElement.scrollWidth === clientWidth`；表格列头文字完整不折行（实测基线见 §二「列宽预算」下方的实测注）。
10. 键盘 Tab 序列覆盖：分段控制器 → 三个下拉 → 重置 → 视图切换 → 每行账户胶囊 → 每行编辑；`prefers-reduced-motion: reduce` 下无过渡。
11. 汇总条：后端按 §四 公式返回；**一组已知数据单测**断言 `净投入 === 买入 + 手续费 − 卖出 − 分红`（构造 `买入 100、卖出 40、分红 5、手续费 1` → 净投入 **56**）。前端不得自行求和。
12. **行展开详情按需取**：列表请求体里不含 `import_hash` / `plan_id` / `position`；展开某行才发 `GET /api/transactions/<id>/`，收起不发、已取过不重复发。三条判据由 `transactionDetailOnDemand.spec.ts` 钉住（源码判据 + 变异验证）。

### 汇总条落地（v1.2，2026-11-01）

- **口径**：严格按 §四 公式，后端一次 `GROUP BY txn_type` 聚合，**全程用分做整数运算**，只在出口换算元；前端零求和。
- **为什么不复用列表数据**：列表分页 20 条，对它求和得到的是「这一页的汇总」——看起来像总计、实际只覆盖 20 行。用例 `test_summary_counts_every_row_not_just_one_page`（25 笔 + `per_page=10`）就是钉这个。
- **跟随筛选**：`buildFilterParams` 是列表与汇总**共用**的映射；汇总不跟分页，翻页与触底加载不重取（守卫 `transactionSummaryWiring.spec.ts`）。
- **未取到时不渲染**：`v-if="summary"`，不留空容器；重取时保留旧数字 + 降透明度（`aria-busy`），不闪成空白。
- **范围必须显式**：「全部时间 / 近一年 / 2026-01-01 至 2026-06-30」，且 symbol 预筛要进文案——从产品详情页进来时汇总只覆盖那一个产品，不标出来会被读成全家庭。
- **净投入带符号**：正＝净投入、负＝净取出；两者是相反的事，都印成正数等于说谎。

### 未做（明确边界）

## 附：与手机端的关系（拿了什么，没拿什么）

| 手机端做法 | 这里 | 为什么 |
|---|---|---|
| 按月/按日分节的纵向流水 | **拿**：月分组 + 月内合计，落在流水线视图 | 分节回答的是节奏，与屏宽无关 |
| 顶部「交易汇总」四宫格大数字 | **改造**：压成一行汇总条 | 手机竖屏没横向空间只能用大卡片；桌面 40px 一行就够，列表才是主角 |
| 每行右侧「›」进详情 | **不拿**：hover 出「编辑」 | 桌面没有「进入详情页」的空间成本 |
| 「清仓分析」卡 | **不拿** | 另一个功能面 |
| 「已撤单」跟在金额后 | **改造**：金额划线 + 状态列写「已撤单」 | 桌面状态有独立列，标两遍是冗余 |

**一句话自检**：配色、字体、圆角、阴影全部来自 `design.md`，所以独特性不在色板——在信息结构：**账户轴**（每行都能答「在哪」并一步跳过去）+ **月轴**（时间有节奏）+ **方向色**（颜色只表示加仓/减仓）。出门前摘掉的那件配饰，是账户色点。
