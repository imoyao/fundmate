# 基金风险指标的「基准」与「同类分位」（#167）

**性质**：设计说明（口径依据 + 实现位置 + 已知缺口）

**GitHub 原卡**：https://github.com/imoyao/fundmate/issues/2118
**相关代码**：`backend/app/services/fund_benchmark.py` ·

## 1. 这一层解决什么问题

用户在 #167 的原话是：

> 「股票基金和混合基金还有债券基金，它们参考的产品肯定不是一样的呀。那这样的话，
> 用同一个标准去衡量它们的夏普率是不是会有问题呢？」

**这句话里有两件事，长得像但完全不同**：

| | rf（无风险利率） | **基准（benchmark）** |
|---|---|---|
| 它是什么 | **不投资**能拿到的收益（国债 / 存款） | 这只基金**该跟谁比** |
| 谁的规定 | **全市场一个** | **分类别** |
| 用在哪 | 夏普 / UPI 的分子 `(收益 − rf)` | 超额收益 / 信息比率 / 捕获率 |
| 取常值对不对 | ✅ **对**（同减不改排序） | ❌ 必须分类别 |

所以：**「rf 不能取常值」是反的；「不同产品该参照不同东西」是对的**——
后者说的是基准。本文档只讲基准与它的伴生问题（同类分位）。

## 2. 为什么不解析 `Fund.benchmark`

`funds.benchmark` 存的是**自然语言串**，实测形如：

```text
沪深300指数收益率×95%+银行活期存款利率(税后)×5%
中债综合全价(总值)指数收益率
```

直接解析它有三个问题：

1. 复合基准（股 + 债 + 活期）与权重混在一句话里，正则必然脆；
2. 填充率低、各家写法不统一；
3. **解析失败会静默退化**——一个退回「沪深300」的债基基准，比没有基准更有害：
   用户读出「超额 −12%」却不知道这个数毫无意义。

**故不解析，改按 `Fund.fund_type_id → fund_types.name` 映射**
（`fund_benchmark.resolve()`）。零解析、零新增抓取，且 `fund_type` 有确定性回填 job
（#1155），覆盖率会自己长起来。

## 3. 映射规则表（`_RULES`，**有序**）

顺序本身就是判据，三条容易写错的：

- **「偏债」必须先于「混合」**：`混合型-偏债` 同时含两个词；「混合」在前会让偏债混基
  落到偏股混基的基准上（比沪深300 贴，仍然错）。
- **「指数型」/「ETF」必须显式返回 `None`**：指数基金该比的是**它跟踪的那只指数**，
  而 `funds` 表没有「跟踪标的」字段（`fetch_etf_list` 实测 1605 只全无）⇒ 只能不猜。
  ⚠️ 这两条**不是**「反正后面也匹配不到」的摆设——去掉它们，下面的债券族规则会把
  `指数型-债券` 捡成「比同类债基」。这是变异探针实测挖出来的真 bug。
- **货基最先**：它走万份收益分支，本就不该进这张表；放最前是为了在调用方漏判时
  显式拿到 `None`，而不是被后面的规则捡走。

命不中任何规则 ⇒ `None`（`_FALLBACK`）。**不拿宽基顶替**：留着「暂无基准」，
用户至少知道「没比」；给一个错基准，他分不出「没比」与「比错了」。

## 4. 「选了基准但序列取不到」是第三种状态

```text
resolve() → None                     「本基金不适用基准」（货基 / 指数型 / QDII）
resolve() → available=False          「基准已选定，但日线暂缺」（如 885005.WI 源侧未收录）
resolve() → available=True           「基准可用」，带上下载序列算相对指标
```

前端对前两种显示不同的文案。**不合并成一种**——合并等于把「我们没收录」说成
「这类基金不需要基准」，那是两码事。

## 5. 同类分位（`fund_peer_rank.py`）

基准解决「跟谁比」，分位解决「跨类怎么读」：风险比**跨类别不可比**
（债基年化波动 2%、股基 25%，而夏普把波动当风险 ⇒ 债基系统性偏高），
但「在同类里排前 10%」对任何类别都是同一句话。

口径要点：

- **经验分位**（`低于当前值的同类样本数 / 同类样本数`），与 `market_service._calc_percentile`
  同算法（那个价格分位已用很久）；
- **分位越大越好**是统一读法：算分位前把「越小越好」的指标取负。
  ⚠️ 回撤的符号容易写错——库内 `max_drawdown` / `current_drawdown` 是**负数**
  （-30 比 -10 更深、更差），所以「-8 优于 -25」= 数值越大越好，**不取负**；
  而 `annual_volatility` 是正数、越小越好 ⇒ 取负。
- **同类样本 < 5 时不出分位**：2 只基金选出的「同类第一」是噪音，出它比不出更坏；
- 分母只含**当前口径版本**且 `basis == 'acc_nav'` 的行——口径可疑的行与被折算污染的
  净值不能当标尺。

## 6. 横向筛（`fund_risk_ranking.py`）

`fund_type_id` **必填**，不存在「不传就全市场」的默认：那种默认一定会被误用成跨类榜。

其余三条纪律：

| 纪律 | 为什么 |
|---|---|
| 只取 `caliber_version == CALIBER_VERSION` | 旧口径混排会让榜单看起来完全正常，却是两代口径混在一起算的 |
| `basis != 'acc_nav'` 默认剔除，**剔除条数回显** | 被折算污染的净值可能算出全类第一的夏普，而那个数是假的；回显剔除数才能区分「榜上只有 3 只」与「同类只有 3 只有数据」 |
| 值 NULL 的行不进榜 | NULL 在 ORDER BY 里会排到一端，看起来像「排最后一名」，实际是「没算出来」 |

## 7. 中证专属码的日线源（`.CSI`）

`index_daily` 现有三路（`index_daily_job.py`）：

| 后缀 | 源 | 口径 | 备注 |
|---|---|---|---|
| `.WI` | 韭圈儿 | anchored / normalized | 万得系基金指数 |
| `.SH` / `.SZ` | 腾讯直连 | `raw` | 交易所指数真实收盘 |
| **`.CSI`** | **中证指数官网** | `raw` | 2026-10-14 新增（#167 基准补齐） |

`.CSI` 路当前两个目标：`932000.CSI`（中证2000，773 条）与 **`H11001.CSI`（中证全债，
5287 条，2005 起）**——后者是**债券族基准**，见 §8。

第三路是**必需的**：**腾讯源没有中证专属码**——2026-10-14 实测 `sh932000` / `sz932000`
均返回 0 行，而同期的 `sh000852`（中证1000）正常 ⇒ 不是限流，是源侧不存在。

中证官网一次请求即返回全序列（`932000` 成立以来 773 条，2023-08-01 起），
故该路**不分增量/全量**：做增量优化的收益是零，upsert 本就幂等。

## 8. 已知缺口

| 缺口 | 影响 | 状态 |
|---|---|---|
| ~~`885005.WI` / `885008.WI` 源侧未收录~~ | ~~债券族基准取不到序列~~ | **已解决（2026-10-14，#167 收尾）**：债基映射改指 **`H11001.CSI`（中证全债指数）**，走 `.CSI` 路取真实收盘。原 `885005.WI` 的「映射成立但无序列」形态从映射里摘掉（2026-10-14 二次复核，韭圈儿仍返回 0 条） |
| `funds` 无「跟踪标的」字段 | 指数型 / ETF 无法映射基准 | 不猜；缺口登记在此 |
| 基准相对指标**不落库** | 每次详情页现算（一次去交集，成本可忽略） | 刻意：映射与基准序列都会变，物化它会把「改了映射但快照没重算」变成静默错值 |

> **为什么换 H11001.CSI 而不是继续等 `885005.WI`**：原映射挂着一个**永远取不到序列**的
> 代码，前端只能显示「基准已选定但暂无数据」——映射看着完整，用户实际拿不到参照。
> 中证全债是**真实的债券市场全价指数**，比「同类基金加权」的 885005 更直接回答
> 「债基跑赢债市了吗」，且数据用已建好的 `.CSI` 路一次请求即得。
>
> ⚠️ `index_daily` 需跑一次同步把 `H11001.CSI` 落库（`pdm run sync --job index_daily`），
> 否则前端仍会走「暂无数据」分支——**改映射 ≠ 有数据**。
