### 需求文档：记账功能增强 — 简记、全面盘点与数据去重

**版本**：v2.0
**日期**：2026-05-12
**关联系统**：ShowBuy 投资记账
**依赖**：`SPEC.md v1.1` 中定义的 `transactions` 数据模型与 API 契约

---

### 1. 功能概述与定位

本次需求将记账功能拆分为两条互补路径，并内置完善的去重防呆机制，以满足不同场景下的用户效率与数据准确性需求。

| 功能         | 定位                     | 使用场景                           | 路由      |
| :----------- | :----------------------- | :--------------------------------- | :-------- |
| **简记**     | 高频、快速、轻量         | 日常随手记一笔买入或卖出           | 首页弹窗  |
| **全面盘点** | 低频、批量、完整、可校验、可对账 | 定期对账、首次迁移数据、复杂操作   | `/import` |

**核心原则**：
-   两条路径共享底层 `transactions` 表，保持数据一致性。
-   “简记”追求“30秒效率”，“全面盘点”追求“数据完整与准确”。
-   **任何导入操作都必须经过“去重检查”与“用户确认”两道关卡。**

---

### 2. 功能详述

#### 2.1 简记（首页弹窗优化）

**2.1.1 目标**
将用户最高频的“买入/卖出”操作，控制在最短路径内完成，避免页面跳转带来的注意力中断。

**2.1.2 交互入口**
-   **位置**：首页仪表盘右下角**悬浮操作按钮** 或顶部导航栏显眼位置的“+”图标。
-   **行为**：点击后弹出居中模态对话框。

**2.1.3 弹窗内容**
-   **类型切换**：顶部两个大标签，默认“买入”，可切换为“卖出”。
-   **表单字段（极简模式）**：
    -   **搜索选择器**：输入基金/股票名称或代码，带即时搜索建议。支持模糊匹配。
    -   **日期**：默认当天，可修改。
    -   **金额**：输入数字框。为方便用户，预留“份额”辅助换算的开关（可展开）。
    -   **费率**：预置通用默认值，可手动修改。
    -   **备注**：选填文本框，占位符文案“补充交易理由（选填）”。
    -   **保存按钮**：主按钮，点击后关闭弹窗，并刷新首页持仓。
-   **高级字段**：将非必填项（如“下午3点前”、“交易账户”、“对方账户”等）折叠在“更多选项”展开区域，保持默认界面清爽。

**2.1.4 范围决策（明确排除）**
-   **不包括**：分红、转股、拆合股、定投等复杂操作。
-   **原因**：这些操作参数多，需要校验和预览，不适合仅有一屏的弹窗。应在“全面盘点”中完成。

**2.1.5 引导**
-   弹窗底部设置低视觉权重的文字链接：“批量导入、分红转股、定投？去「全面盘点」>”。
-   **目的**：在不干扰核心操作的前提下，让用户知晓更强大功能的存在。

---

#### 2.2 全面盘点（独立页面 `/import`）

**2.2.1 目标**
为用户提供一个清晰、安全、向导式的批量数据处理中心，能覆盖所有复杂的记账操作、外部数据导入，以及关键的对账与去重功能。

**2.2.2 页面整体设计**
采用**水平步骤条**，将流程固化为4个阶段。步骤条位于页面顶部，可点击回到已完成步骤。

-   **第1步**：选择导入模式
-   **第2步**：上传文件
-   **第3步**：预览、去重与修正
-   **第4步**：导入完成

**2.2.3 各步骤详述**

**第1步：选择导入模式**
-   **布局**：以“卡片矩阵”形式呈现，每张卡片代表一种模式。大图标 + 标题 + 一句适用场景说明。
-   **需提供的选项**：
    1.  **CSV/Excel 文件**：“使用我们提供的模板，或映射您自己的文件字段。”
    2.  **券商交割单**：“直接上传从券商官网导出的原始交割单文件，系统自动解析。”
    3.  **截图/照片**：“上传交易记录截图，系统尝试智能识别。”
    4.  **手动批量录入**：“没有文件？在网页表格中逐行快速录入。”
    5.  **从持仓反推**：“通过当前持仓，快速生成一笔初始买入记录。”
    6.  **API/JSON**：“面向高阶用户的编程接口（未来开放）。”
-   **对账模式开关**：在卡片区上方，提供一个醒目的开关按钮：“🔍 导入并对账”。
    -   **关闭（默认）**：纯粹的导入流程，只新增数据库中不存在的交易。
    -   **开启**：进入对账模式，将文件数据与库中现有数据做全量比对，展示差异（详见第3步）。
-   **行为**：用户点击任一卡片，自动进入第2步。

**第2步：上传文件**
-   **动态内容**：根据第1步所选方式，显示对应的上传组件。
    -   **文件导入**：拖拽/点击上传区，支持 `.csv`, `.xls`, `.xlsx`。
        -   上传区下方提供**标准模板下载链接**。
        -   提供**预置模板选择器**（如：华泰证券模板、富途模板、通用模板、基金定投模板）。
    -   **截图导入**：拖拽/点击上传区，支持 `.png`, `.jpg`。
        -   展示上传预览图，并提供“添加更多截图”按钮。
    -   **手动批量**：直接跳转至第3步，给出一个空白的可编辑在线表格。
-   **行为**：文件上传成功后，系统后台开始解析。解析完成后，**自动跳转至第3步**。

**第3步：预览、去重与修正**
这是整个页面的核心，根据第1步是否开启“对账模式”，显示不同视图。

**A. 标准导入模式视图**
-   **核心组件**：可编辑数据表格。
-   **去重机制（三层防护的第一、二层）**：
    -   **第一层：UI智能标记**
        -   **匹配规则**：`symbol` + `date` + `type` + `quantity` + `price` 完全一致时，判定为**疑似重复**。
        -   **界面表现**：重复行用**黄色警告背景**高亮，行首显示标签 `⚠️ 疑似重复`。
        -   **默认行为**：重复行的复选框**默认取消勾选**，即不会导入。
        -   **Tooltip提示**：悬停在标签上，显示“该笔交易与 2026-04-15 已录入的买入记录高度相似，已自动跳过。”
        -   **批量操作**：工具栏提供按钮“一键取消全部重复行”。
    -   **第二层：后端唯一性校验**
        -   **策略A：报错策略（严格，默认）**
            -   若检测到重复，该笔记录写入失败，返回错误信息，在“导入完成”页列出所有失败原因。
        -   **策略B：跳过策略（静默）**
            -   若检测到重复，直接忽略该笔记录，在导入完成摘要中提示“已自动跳过 X 笔重复交易。”
        -   **用户选择**：在第3步工具栏，提供单选框“导入时自动跳过重复项”，让用户自主选择策略。
-   **其他功能**：
    -   **字段高亮**：系统自动检测并高亮标记有问题的字段（如费率缺失、代码未匹配、金额与份额不匹配等）。
    -   **行操作**：每行前有复选框，用户可取消勾选不想导入的行。
    -   **表格内编辑**：支持直接双击单元格修改数值、文本、日期。
    -   **批量操作**：工具栏提供“批量设置费率”、“智能匹配未知代码”等快捷修复功能。
    -   **高级操作支持**：侧边栏或右键菜单，提供“标记为分红”、“标记为转股”、“标记为拆分”等操作入口。
-   **提示文案**：表格顶部显示温和的系统提示——“系统已自动解析并标记了疑似重复数据。建议检查高亮项，确认无误后再导入。”

**B. 对账模式视图**
-   **核心组件**：差异对比表格，新增三列状态。
-   **状态列定义**：
    -   `✅ 新交易`：该笔交易在库中不存在，将被新增。默认勾选。
    -   `🔄 有差异`：日期、代码、方向一致，但金额或份额不一致。
        -   **界面表现**：该行展开后，并排显示“库中值”和“导入文件值”，差异字段用红色边框高亮。
        -   **用户决策**：提供单选框“以文件为准（覆盖）”或“以库中为准（忽略）”，默认选择“忽略”。
    -   `✅ 完全一致`：两边数据一模一样。默认不勾选，仅作核对确认。
-   **全球唯一标识符（GUID）支持（第三层防护）**：
    -   若导入文件中的交易记录包含 `transaction_id` 字段，系统优先以此字段进行精确匹配，无视其他字段。
    -   这是最彻底的解决方案，适用于用户反复导入同一份券商源文件（自带交易流水号）的场景。

**第4步：导入完成**
-   **结果展示**：一个大号的对勾图标，文案“成功导入 X 笔交易”。
-   **明细**：
    -   如采用策略A，列出所有失败行和原因。
    -   如采用策略B，显示自动跳过的重复交易数量。
    -   在对账模式下，显示“新增 X 笔，覆盖 Y 笔，确认一致 Z 笔。”
-   **智能建议**：根据导入内容给出下一步操作链接。
    -   _示例1_：“您导入了股票交割单。是否现在去**更新最新持仓市价**？”
    -   _示例2_：“检测到新基金建仓。是否去**设置定投计划**？”

---

#### 3. 情感化设计与边界情况

-   **空状态处理**
    -   **简记弹窗**：若用户无持仓，在搜索框下显示“还没有持仓，先去「全面盘点」创建第一笔吧~”。
    -   **盘点页面**：首次进入`/import`时，展示一个欢迎横幅“欢迎使用全面盘点”，用图文引导用户选择一种导入方式开始。
-   **容错与安全**
    -   **导入预览**是最后防线，用户必须手动点击“确认导入”。
    -   **导入前自动备份**：系统应在确认导入前，自动备份本地数据库（`snapshot_YYYYMMDD_HHMMSS.db`），并提示用户“已在本地创建了导入前备份，如数据有误可恢复。”
    -   **定投**：从简记入口排除，但在盘点页的第3步，支持用户将一批周期性买入记录“识别为定投计划”，自动创建定投模板。
