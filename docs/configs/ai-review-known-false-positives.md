# AI Review 历史误报案例库

> **本文件刻意不注入 prompt。** 它是维护者归档、复盘与「该加什么规则」的证据台账；
> 把它塞进 prompt 既烧 token 又会锚定模型（2026-09-11 之前它确实在 prompt 里，实测收效甚微，故迁出）。
>
> **追加规则前先来这里登记案例**，流程见 `docs/configs/ai-review-prompt.md` 文末「附」。
> 判断次序：**能降级为配置的，不进 prompt**（审查范围、配额、忽略路径、agent 开关）→ 剩下的才抽象成一般规则。
>
> ⚠️ **口径更新（2026-09-11）**：下表「现在由什么拦住」一列中凡写有「prompt §0 验证义务 / 先看文件 / 必须 `rg` 出证据」
> 者，其原始含义是「模型先读仓库再发言」。但 `agent.enabled` 实测失败已关闭（`.ai-review-deep.yaml`，
> 证据链见 `docs/spec/ai-review.md` §7），**该能力不存在**。`prompt §0` 已同步改写为
> 「**不得对看不见的仓库做任何断言**」。
> 即：拦截方向不变（都是「不许猜」），但从「要求核实」改为「禁止越界断言」——**不再依赖读仓库能力**。

## 三、一个反直觉但重要的教训

PR #1401 的 4 处**真**缺陷（决策编号漏标导致三处交叉引用悬空、两个文档对同一事实口径矛盾、引用措辞指错行、同一句混用两种引用风格）**AI 一条都没报**，全部由人工自查发现。

也就是说：这套 bot 当时既在**产出大量误报**，又在**漏掉真缺陷**——两头不讨好。原因不是「模型不够强」，而是**接口给错了**：

1. `review.mode = FULL_FILE_DIFF` → 送去的是整个文件，模型对没改过的行也评论、也把删除行当现况；
2. `agent.enabled = false` → 模型读不到仓库，只能凭补丁文本猜，「未定义 / 未使用」类断言必然大面积出错；
3. 无配额、inline 失败降级为普通评论 → 单 PR 可产出几十条；
4. 应对方式一直是「往 prompt 里追加禁止事项」→ 16 天从 8.7KB 涨到 29KB，且**已被禁止过的类别继续复发**。

→ 结论：降噪要改**接口与结构**，不是把禁止清单写得更长。2026-09-11 的改造即按此执行（见 `.ai-review-deep.yaml` 头部注释与 `docs/spec/tech-debt.md`）。

## 四、结构改完之后剩下的瓶颈：模型档位（2026-09-11 实证）

结构调整把**数量**压下去了，但**质量**没有同步改善。PR #1416 提供了一个干净的反证：

- 该 PR 只新增一个 92 行的 vite 插件，逻辑简单、类型检查与端到端冒烟全通过；
- AI 产出 **5 条 inline + 1 条 summary**，5 条 inline **全部是同一类**：称「代码注释中使用了中文，违反了中文优先的约定」；
- 而 `docs/configs/ai-review-prompt.md` 第 129 行**早已明确写着**：「注释/docstring 普遍用中文，是既定约定；不要以『应保持英文风格』为由提意见」。

即：模型不是「没看到规则」，而是**看到了规则、抓住了「中文优先」四个字、然后反向套用**。同一轮日志显示当次 `CHOSEN: glm-4-flash (selected_ok=true)` ——**智谱免费档**，付费的火山方舟 DeepSeek 因额度用尽全程 429 未参与。

**可操作的结论**：

1. 在当前免费档模型下，**继续加 prompt 措辞无效**——规则已写明仍被违反；
2. 质的改善**只能靠换回付费档模型**（恢复 `ARK_API_KEY_CODEREVIEW` 额度，或在 `scripts/llm_health_probe.py` 的候选清单里换一家）；
3. 额度未恢复前，deep-review 的产出**不应作为合并依据**（它是非必需检查，不阻塞合并，这是有意为之）。

判断依据可直接复核：`.github/workflows/ai-review.yml` 的探测步骤会打印 `CHOSEN: <model>` 与各候选的 `429 限流/额度用尽` 状态。

> **2026-09-17 候选池变更**：智谱独立线路（`glm-4.7-flash` / `glm-4-flash` / `glm-4v-flash`，
> 即上文所说的「免费档」）**已从 `scripts/llm_health_probe.py` 删除**——实测常 429 且产出价值低，
> 纯浪费 Actions 分钟；GLM 家族改由方舟托管的 `glm-5-3-flash-260828` 承接。候选池同时按
> 「越新越强越前」换为豆包 Seed 2.1 Pro / DeepSeek V4.1 / GLM 5.3 / 豆包 Turbo
> （被「安全体验模式」限额暂停的 DeepSeek `-ga-` 两档**保留在池内**，探测标 429 后自动跳过；
> 见 `docs/spec/ai-review.md` §8）。故上文「质的改善只能靠换回付费档模型」的成因**已部分消除**：
> 默认首选即最新最强付费档；但候选仍全部来自同一把方舟 key，**单账号额度/限额风险依然存在**
