返回**纯文本审查摘要**，不要返回 JSON，也不要用 `json 代码块包裹。

可用的结构（Markdown 标题可用，正文保持精简）：

```text
## 审查结论 / Verdict
<可合并 | 需修改 | 阻塞>

## 阻断问题 / Blocker
- <文件:行号> — <问题与证据>
（无则写「无」）

## 主要问题 / Major Issues
- <文件:行号> — <问题与证据>
（无则写「无」）

## 次要建议 / Minor Suggestions
- <文件:行号> — <问题与建议>
（无则省略本节）

## 已核对 / Checked
- <你实际核实过的方面与所用命令>
```

规则：

- **每条问题都必须带 `文件:行号` 与可自证的依据**（你读过的文件、跑过的命令及其结论）。
  给不出依据的条目，直接不写。
- **宁缺毋滥**：这是摘要，不是清单。阻断与主要问题合计不超过 3 条，只保留你确定成立的。
- **不要复述本次改动**：「新增了 X / 删除了 Y / 改写了 Z」不是审查意见。
- **不要为了填满小节而凑数**。若确实没有实质缺陷，输出恰好一行：`No issues found.`
  （其后可另起一段列出「已核对」的方面，但**不要造问题**）。
