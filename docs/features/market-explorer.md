# 探市 · 大类资产观察 设计

**状态**: 设计稿（待评审，未实现）
**日期**: 2026-09-11
**依据**: ① 府库《做了一个星期，观察大类资产真不容易》（20 资产组合 + 三个数据坑）；② 「全A等权 500 日线温度计」截图；③ **本仓代码与数据源实测**——本文第 2 节全部为 2026-09-11 真接口实测结果，非推断

**相关**: 温度页**视觉/交互**方案见 [`temperature-redesign.md`](./temperature-redesign.md)（本文只补其数据侧）；数据分层口径见 [`../spec/data-strategy.md`](../spec/data-strategy.md)；刷新现状台账见 [`../spec/data-refresh-inventory.md`](../spec/data-refresh-inventory.md)

## 0. 一句话

- **探市页** = 20 个大类资产的「当日涨跌 + 相对位置」一览，解决「我现在该看哪儿」；
- **温度计** = 把「市场贵不贵」压成一个 0~10 ℃ 的数，解决「现在能不能买」。

两者共用**同一套底座**：指数日线 → 均线偏离 / 历史分位。**不引入新依赖。**

## 3. 口径统一（文章 1 的三个坑 + 对策）

文章作者一周内踩的三个坑，**我们必须提前写死规则**，否则同样会「数据天天出错」：

### 3.1 坑一：不同市场收盘时间不同 → 观测日不一致

**对策**：每个资产落库携带**两个时间**，前端按「数据截止」展示而非假装同一日。

- `trade_date` —— 该资产的**所属交易日**（A股/港股/美股各按本地交易所日历）
- `data_asof` —— 该值**实际取到的时刻**（北京时间）

界面右上角统一显示「**各市场数据截止：A股 15:00 / 港股 16:00 / 美股 05:00（北京）**」，
**永不显示一个笼统的「今日」**。这是文章里「同一天的数据没法同时获取」的正解。

### 3.2 坑二：24 小时交易品种的「收盘价」需人为定义

黄金 / 白银 / 原油 / 比特币几乎 24 小时交易，不同人取不同时点会得出**涨跌相反**的结论
（文章原文：「国内是下跌 2% 左右，海外是上涨 3% 左右」）。

**对策（硬规则，写进 spec）**：

1. 24h 品种的「当日收盘」**统一定义为北京时间 08:00 的快照**（可配置，配置项入 `.env`）；
2. 该口径**必须出现在界面的字段 tooltip 上**，不允许只写「收盘」；
3. 同一资产**只用一个源**，禁止 A 处用国内、B 处用海外——文章里的错乱正是多源混用导致。

### 3.3 坑三：估值口径无法跨资产复用

文章结论：**只有 A 股指数能给出可靠估值**，海外各国差异大、商品/加密根本没有盈利现金流可估。

**对策（与我们 L3 分层完全一致）**：

| 资产类别 | 「相对位置」指标 | 依据 |
|---------|----------------|------|
| A 股指数 | **估值分位**（PE / 股息率的历史分位） | 已有 `index_valuations` 表与岗位；自算链路见 `SelfCalcFetcher` |
| 港股 / 海外股指 | **价格分位**（现价在 N 年区间的百分位），**不做估值** | 无口径统一的数据源 |
| 债券 | **收益率分位** + 期限利差 | `bond_zh_us_rate` 自带 10Y-2Y 利差列 |
| 商品 / 加密 | **价格分位**，并标注「不产生现金流，分位≠贵贱」 | 与文章作者判断一致 |

> **口径参考（来自文章原文）**：作者的 A 股估值在试过多种算法后，最终采用「**中位数等权**」——
> 因为它比均值更能描述国内市场的真实状态；而海外各国差异大、单一算法不通用，商品与加密
> 更没有盈利 / 现金流可估。
>
> 我们的对策：**优先用中证官方口径**（`index_valuations` 的 PE / 股息率，可追溯、免自算争议），
> 把「中位数等权」作为**官方口径覆盖不足时的备选**（`SelfCalcFetcher` 已有自算链路）。
> 两条链路的口径**必须在界面上区分来源并标注**，禁止混算或互相覆盖。

## 4. 数据分层与落盘（避免重犯「全量堆砌」）

严格按 `data-strategy.md` L1~L4 判定：

| 数据 | 层 | 落盘？ | 量级估算 | 依据 |
|------|----|-------|---------|------|
| 20 资产**日频快照**（当日涨跌 + 分位） | L3 缓存 | **落**（唯一新增） | 20 行/天 ⇒ **7,300 行/年** | 要算「异动」与回看历史，必须有序列；量级可忽略 |
| 指数 / 债券 / 商品**日线** | L3 缓存 | 落，**复用 `index_daily`**（现有 10 个万得系指数，单指数 2,104 ~ 6,466 行、最长 ≈26 年） | 每资产 +1 行/天 | 均线、分位都从此表算 |
| 全市场个股日线（做市场宽度用） | — | **暂不落** | 5,000 只 × 250 天 = **125 万行/年** | 这是唯一会「堆量」的部分，**按 L3 降级处理**（见 §5.3） |
| 实时行情 | — | **不落** | — | 前端直连，见 `realtime-data-sources.md` |

> 关键判断：**探市页的数据量根本不是问题**（一年 7,300 行）。
> 真正会失控的是「市场宽度」（需全部个股日线），因此它是**唯一被明确降级**的部分。

## 5. 温度计算法

### 5.1 截图给定的口径

从截图文字可确定的规则：

- **底座**：全A等权指数的 **500 日线**，输出「深温」值（示例 `-1.685`）
- **输出**：温度 **4 ℃**（示例），量纲 0~10
- **分区**：绿区 `(-10, -5]` / 黄区 `(-5, 0]` / 红区 `(0, 10]`——注意分区是在**偏离量**轴上，不是温度轴上
- **分布**：10 个档位的标的数量直方图（原文示例 `26 7 31 5 2 0 5 3 2` —— 仅 9 档可见，第 10 档原文未给出）
- **市场宽度**：`0.08%` 处于 200 日均线以上、`8.67%` 处于 500 日均线以上
- **发布节奏**：每日 **20:00**

### 5.2 我们的实现路径

```
全A等权指数日线（index_daily）
      ↓
偏离量 dev = (close - MA500) / MA500        # 文章示例 -1.685 量级
      ↓
截面 z-score / 历史分位归一
      ↓
温度 = clip(映射(分位) , 0, 10)              # 0~10 ℃
      ↓
落入 绿/黄/红 区  →  前端三色 token（复 temperature-redesign.md §5.1）
```

**「全A等权」怎么来（需拍板）**：

| 方案 | 数据 | 代价 |
|------|------|------|
| A. 用现成指数近似 | `sh000002`（A股指数，**8,724 行 ≈ 35 年**）或 `sz399317`（国证A指，5,248 行） | 零成本，**但不是等权**，与截图的「等权」口径不一致 |
| B. 自算等权 | 需全部 A 股日线 ⇒ 125 万行/年 | 重，且正是 §4 要避免的堆量 |
| C. 用韭圈儿已有的万得系指数 | `index_daily` 里已有 `881001.WI`（万得全A，6,465 行） | 零成本，非等权 |

**建议 A/C**：先用 `881001.WI` + `sh000002` 各算一条，与截图数值对照，确认口径接近后再定。
**不为了「等权」二字去拉全市场个股。**

### 5.3 市场宽度（`% 处于 200 / 500 日均线以上`）——唯一的重活

截图里 `8.67%` 这类数字需要**全部个股**的日线。三条路：

1. **降级**：只做**指数级**宽度（如「28 个申万一级行业中，几个在 200 日线上方」）——行业指数数量少、`index_daily` 可承载；
2. **借用 baostock**（已在依赖里）：批量拉全 A 日线，但需评估落盘量（125 万行/年）；
3. **不做**：该指标缺失时显示 `—`（符合 L3 可降级）。

**建议先 1，把 2/3 作为后续选项。** 这也是全篇最该由你拍板的取舍。

### 5.4 A 股焦点区：估值条 + 强度条

原文把两个指标嵌在 A 股区域底部、每日更新（此前只在周六「市场体检」发布）：

| 指标 | 视觉 | 口径 |
|------|------|------|
| **估值** | 一条横条，**绿 → 红** | **全指近 10 年的 PE 百分位**；靠左 = 便宜，靠右 = 贵 |
| **强度** | 一条横条，**灰 → 紫** | 市场动能：偏灰 = 情绪低迷，偏紫 = 交易活跃、趋势较强 |

- 常态下两条都停在中间，说明「一切正常」；
- 只有跑到**两端**（极度低估 / 极度超涨）才值得多想一步。

**我们需要注意两点**：

1. **估值条的绿→红与温度三色同源**（低=绿、高=红），应复用同一套 token，不要再造一套；
2. **强度条的灰→紫是第三套配色**，与涨跌、温度都不同。项目 tokens 里已有可对应项
   （`--color-primary` = `#7a7fa8` 灰紫蓝、`--tag-thistle`、`--tag-periwinkle`），
   但 `design.md` 正文未收录这三者——落地时**以 `frontend/src/style/colors.css` 为准**，
   并顺手补文档。

### 5.5 ⚡ 异动标记：双线规则（原文给出的完整逻辑）

这是全篇**唯一一条能直接抄下来的判定规则**——原文用「量血压」类比讲得很清楚：

```
线 1（相对 / 自适应）：与「自身过去一年」的波动比
        —— 过去一年这个资产通常波动多大？今天偏离了多少？
线 2（绝对 / 兜底）：   单日涨跌幅超过某个绝对阈值

任一触发 → 亮 ⚡
```

原文的例子（可直接作为我们实现的验收样例）：

| 资产 | 当日涨跌 | 平时日波动 | 是否亮 ⚡ | 原因 |
|------|---------|-----------|----------|------|
| 原油 | +3.5% | ≈2% | **是** | 超出自身上限，且绝对幅度大 |
| 日经225 | ≈+2% | 高于原油 | 否 | 对**它自己**来说不算罕见 |

> 关键点：**阈值是按资产自适应的，不是一个全市场统一的百分比**。
> 这与 `data-strategy.md` 的 L3 口径一致——只要「过去一年的该资产日收益序列」，
> 就能算（我们的 `index_daily` 已有足够历史）。

**实现提示**：线 1 用滚动波动率（如过去 250 个交易日日收益标准差）的倍数判定，
线 2 用固定绝对阈值兜底（对应原文「不管平时血压多高，量到 200 都不正常」）。
**两个参数都必须可配置**，并在事件底部附一句新闻事实解释（原文的「异动解读」）。

### 5.6 跨类对比：「谁和谁不一样」

原文反复强调的一句设计原则：

> 「最值得关注的不是谁涨谁跌，而是**谁和谁不一样**。」
> 「不看全局，单个资产的涨跌很难判断它到底意味着什么。」

由此得出三条**必须由界面承载**的对比，而不是把 20 个数字平铺给用户：

| 对比 | 含义 |
|------|------|
| **红多还是绿多** | 全球资金昨天在进攻还是防守（原文「看颜色大势」，不用读数字） |
| **有没有 ⚡** | 哪里发生了不寻常的事（§5.5） |
| **跨类关系** | 股涨债跌？股跌金涨？**股债一起跌**？——关系比单个数字信息量大 |

> 第 3 条是探市页真正的产品价值所在，也是「记账软件」与「行情软件」的分界：
> 我们不只是给数字，而是给**关系**。界面必须显式承载它（见 §6.1 的「跨类对照条」）。

## 6. 界面设计

### 6.1 探市页

布局要点：

1. **顶部一行「市场状态条」**：各市场数据截止时间（§3.1），不做成装饰；
2. **20 个资产卡片网格**（6 列自适应），每张卡片三段：名称 + 涨跌幅（**涨红跌绿**，中国习惯）+ 相对位置条；
3. **相对位置条**是核心：一条横向刻度，把「当前值在历史区间 / 分位」画成一个游标，**绿/黄/红三色分区**与温度计共用 token；
4. **异动标记**：|涨跌幅| 超阈值（如 2%）的卡片加角标，这样「一眼看到今天哪里不对」；
5. **口径提示**：24h 品种卡片上必须有口径 tooltip（§3.2）。

### 6.2 温度计页

在已有 `temperature-redesign.md` 的视觉方案上，补三块：

1. **大号温度数字**（`4 ℃`）+ 绿/黄/红三色背景，字号最大，作为页面唯一锚点；
2. **三区刻度尺**：`-10 … -5 … 0 … 10`，游标标出当前偏离量，区带用绿/黄/红；
3. **温度分布直方图**：10 档位的标的数量条；**需注明分母**（是「全市场个股」还是「指数/行业」——取决于 §5.3 的取舍）；
4. **市场宽度两个数字**（200 日 / 500 日线上方占比）+ 「发布 20:00」时间戳。

### 6.3 两种消费形态：页面 + 邮件简报

文章最终交付的不是可交互页面，而是**每天早上推的一张图**（文末即「每日简报」）。
我们支持两种形态，**共用同一份数据**：

| 形态 | 面向 | 投递方式 | 对口径的要求 |
|------|------|---------|-------------|
| **页面**（探市 / 温度计） | 主动查看 | Web | tooltip 里写清口径即可（§3.1 / §3.2） |
| **每日简报** | 被动接收 | **邮件（订阅制）** | **必须把口径写进正文**——邮件里没有 tooltip |

> 简报形态对口径的要求**比页面更严**。文章里「每天都要解释数据为什么和别处不一样」的根因，
> 正是简报正文没有承载口径。简报正文固定带一行：
> 「A 股截止 15:00 / 港股 16:00 / 美股 05:00（北京）；商品与加密按北京 08:00 快照、海外算法」。

#### 6.3.1 现状：仓库里没有任何发信能力

全仓检索确认：`pyproject.toml` 与 `backend/app/` **零邮件依赖**
（`email` 的命中全部是 Supabase 登录鉴权，不是外发邮件）。因此这一步是**从零选型**，不是复用。

| 方案 | 免费额度 | 取舍 |
|------|---------|------|
| 腾讯云 / 阿里云邮件推送 | 有免费额度 | 国内到达率好，需实名与域名 |
| Resend / Brevo | 免费层较宽 | 海外服务，国内到达率需实测 |
| 个人邮箱 SMTP（QQ / 163 等） | 免费 | 最快跑通，但**易被判垃圾、有日限额**，只适合自测 |
| 暂不发信，先出 HTML | — | 最保守：先做好渲染，投递后置 |

**建议路径**：先用「个人 SMTP / 控制台输出 HTML」把**渲染**跑通（即下面的开发者口子），
投递通道留到订阅功能真正要做时再定。

#### 6.3.2 订阅者来源：复用 `users.email`，不新建用户表

`users` 表已有 `email`（由 Supabase 托管）与 `is_active`。订阅只需**新增一个订阅状态**，
不需要用户表、不需要重复收集邮箱。

> **跨域红线**：`users` 属 **user 域**（Supabase Postgres），而行情 / 简报数据属 **market 域**（Turso / SQLite）。
> 项目硬规则是「**跨域零外键**」——订阅状态若要落库，**必须落在 user 域**（与 users 同库），
> 或在 market 域只存邮箱快照 + 显式时间戳，**禁止外键指向 `users.id`**。

#### 6.3.3 邮件渲染约束（邮件 ≠ Web，形态取舍的关键）

邮件客户端的能力远低于浏览器，直接决定「简报长什么样」：

| 约束 | 后果 |
|------|------|
| 无 JavaScript | 任何交互、动态计算都做不了——**数据必须服务端渲染完** |
| 外部 CSS 支持差 | 样式必须**内联**，布局退回**表格**或受限 flex |
| 图片默认可能被屏蔽 | 「一张图」形态会**直接白屏**——文章作者的图在邮件里不可靠 |
| 深色模式不可控 | 客户端可能强制反色，**暖奶油白底 / 深色文字未必成立** |
| 客户端差异 | 同一封邮件在不同客户端渲染差异大 |

**结论（建议）**：简报以 **HTML 邮件为主**（内联样式 + 表格布局 + 系统字体栈），
把「一张图」作为**可选附件**而非唯一载体。这样图片被屏蔽时，信息仍然完整可读。
—— 这与文章的「一张图」形态**刻意不同**，理由就是邮件会比 Web 更早失效。

#### 6.3.4 开发者作为第一个订阅者（本期先留的口子）

不先做订阅管理，先做**一个可重复执行的 CLI 入口**（`app/tools/` 已有 `scheduler.py` 等先例）：

```
pdm run brief --to <你的邮箱>            # 渲染并发出当日简报
pdm run brief --dry-run --out brief.html # 只渲染到本地文件，不发信（零依赖、零风险）
```

实现次序建议：

1. **先只做 `--dry-run --out`**：渲染 HTML 到本地，人工在浏览器 + 邮件客户端（把 HTML 当附件发给自己）各看一遍；
2. 确认渲染过关后，再加 `--to`：接 SMTP 把同一份 HTML 发出去；
3. 只有 1~2 都稳定，才做「订阅开关 + 退订」。

**这样你自己就是第一个订阅者，且第 1 步不依赖任何邮件服务选型。**

#### 6.3.5 退订与合规

- **必须可退订**：一旦对外发信，退订入口与退订生效是硬要求；
- **免责声明**：沿用 `temperature-redesign.md` §5.3 的措辞纪律——
  简报中**不得出现荐股 / 跟单 / 预测未来涨跌**的表述；温度低 ≠ 买入信号；
- **口径声明**：见本节开头的固定口径行。

### 6.4 与项目设计语言的强制对齐（落地前置约束）

本文第 6 节的两张界面稿是**结构性草案**，用通用色绘制。**真正落地时必须全站统一**，
以以下四者为权威（优先级从高到低）：

| 权威来源 | 管什么 |
|---------|--------|
| `frontend/src/style/colors.css` + `design-tokens.css` | **实际 token 值**（唯一真相源，250 行） |
| `frontend/design.md` | 亮色设计语言（色阶语义、字阶、间距、形状、组件） |
| `frontend/design.dark.md` | 暗色适配（含 HSL 动态计算规则） |
| `docs/design/`（`brand-v1.7.md` / `components.md` / `font-design.md`） | 品牌、组件、字体细则 |

#### 6.4.1 视觉元素 → token 映射

| 界面元素 | 项目 token | 备注 |
|---------|-----------|------|
| 页面底 / 卡片底 | `--bg-page` `#FDFBF7` / `--bg-card` `#FFFFFF` | 暖奶油白体系，**不是纯冷白** |
| 涨 / 跌 | `--color-rise` `#E34F38` / `--color-fall` `#7BC49A` | **禁止直接用 `--brand-*`**（编码红线） |
| 颜色深浅 = 幅度 | 由 `--color-rise`/`--color-fall` 按幅度取色阶 | 对应原文「颜色越深幅度越大」 |
| 温度三色（探市位条 / 温度计） | `--temp-low` / `--temp-mid` / `--temp-high` | 见 6.4.2 缺口 ① |
| 强度条（灰→紫） | `--color-primary` `#7a7fa8` ／ `--tag-thistle` ／ `--tag-periwinkle` | 见 6.4.2 缺口 ② |
| 20 资产分组标识 | `--asset-stock` / `--asset-bond` / `--asset-etf` / `--asset-crypto` / `--asset-saving` | **已有资产类别色，直接复用** |
| 主要 / 次要 / 辅助文字 | `--text-primary` `#2D2A24` ／ `--text-secondary` `#6B655C` ／ `--text-tertiary` `#8C8478` | 暖灰体系 |
| 边框 / 卡片内分割 | `--border-default` `#E5DDD4` ／ `--border-subtle` | |
| 卡片圆角 / 内边距 | `--radius-md` 12px ／ `--space-standard` 24px | 大卡片 `--radius-lg` 16px + `--space-loose` 32px |
| 数据密集区 | `--space-compact` **16px**、行高锁 **40~44px** | 强制紧凑原则 |
| 数字 | Inter（正文）／ **SF Mono / JetBrains Mono + `tabular-nums`** | 金额与涨跌幅**必须等宽对齐** |

**两条硬约束**（`design.md` 明文）：

1. **正负符号与数字同色**：`+` 同涨色、`-` 同跌色，禁止只改数字色而符号保持默认；
2. **业务代码禁止直接调用 `--brand-*`**：涨跌一律走 `--color-rise` / `--color-fall`，
   以保证暗色模式全站自动同步。

#### 6.4.2 三个必须先补的缺口（否则落地即返工）

**① `--temp-*` 温度三色当前并不存在。**
`temperature-redesign.md` §5.1 规定了 `--temp-low` / `--temp-mid` / `--temp-high`
并注明「写入 `colors.css`」，但**实测 `colors.css` 里没有这三个变量**——
也就是说那份文档是「计划」，尚未落地。而它开头写的正是
「为彻底修复 **undefined 变量 bug**」。**探市页与温度计都要用温度三色，
必须先落 token，再写页面**，否则就是第三次踩同一个坑。

**② 「强度条 灰→紫」在 `design.md` 正文无记录。**
token 层有可对应项（`--color-primary` 灰紫蓝 / `--tag-thistle` / `--tag-periwinkle`），
但设计语言正文只覆盖品牌色、功能色、中性色三族。落地时应**以 `colors.css` 为准**，
并顺手把这族颜色补进 `design.md`，避免下一个人再找不到。

**③ 字阶下限是 13px，草案稿用了 11~12px。**
`design.md` 的字阶系统最小档是 `--text-label` 13px / 500，
**没有 11px / 12px 档**。因此草案稿里的辅助文字（如「价格分位 41%」）落地时
必须升到 `--text-label` 13px，或改用 `--text-small` 14px，
**不得**为了塞下信息而自造小字号。

#### 6.4.3 落地检查清单

- [ ] 温度三色 token 已写入 `colors.css`（缺口 ①）
- [ ] 强度条配色已确认并补进 `design.md`（缺口 ②）
- [ ] 全部字号 ≥ `--text-label` 13px（缺口 ③）
- [ ] 涨跌颜色全部经 `--color-rise` / `--color-fall`，无 `--brand-*` 直引
- [ ] 正负号与数字同色
- [ ] 所有金额 / 涨跌幅列加 `tabular-nums`
- [ ] 暗色模式（`design.dark.md`）下逐屏走查
- [ ] 探市页与温度计页面底部均带图例 + 免责声明（`temperature-redesign.md` §5.3）
