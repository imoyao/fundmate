## 三项改动

**① API 命名统一**：`logoutApi` → `logout`（`api/auth.ts:28`）。全仓只此一处，
调用方仅 `store/modules/user.ts`（import + 1 处调用）。store 的 action 叫
`logOut`，与新的 `logout` 不同名，无冲突。

**② 类型集中**：`WatchlistItem` / `HomeSummaryItem` / `WatchlistGroup` /
`HoldingGap` / `WatchlistTag` 五个**跨模块复用实体**从 `api/watchlist.ts` 迁入
`api/types.d.ts`（+146 行），该文件自此只留请求函数与请求/响应契约类型
（`WatchlistPageResponse` / `*Input` / `*MutationResult` 仍留原处——它们是接口
契约的一部分，与请求函数同住合理）。

搬运用脚本剪切而非人工复制：`WatchlistItem` 有 95 行，人工搬运必然漏行；脚本按
原文件行尾风格写回（CRLF 工作区若被写成 LF 会造成整文件 diff）。

`api/watchlist.ts` 侧保留 `export type { ... } from "@/api/types"`，使既有 **31 个**
`from "@/api/watchlist"` 的引用方**零改动**即可继续工作——改 31 个文件的 import
拆分是纯机械改动，风险收益比不划算（若要彻底拆分应作为独立低风险改动）。

> 落地时踩了一个坑并已修正：`export type { X } from "..."` 只做对外 re-export、
> **不在本地引入绑定**，本文件内用到这些名字时 `tsc` 报 TS2304
> `Cannot find name`。故顶部另有 `import type { ... } from "@/api/types"` 供
> 本文件函数签名使用，两行并存（注释里已写明原因，防止后人「cleanup」掉其中一行）。

**③ components 目录组件**：`WatchlistWidget.vue`（256 行）用 `git mv` 迁入
`WatchlistWidget/index.vue`（保留文件历史）。`components/` 下自此**全部 44 个
组件均为目录形态，平铺 0**（迁移前实测：44 个目录 + 1 个平铺）。

引用方 `views/welcome/index.vue` 的 import 改为 `@/components/WatchlistWidget/index.vue`
—— 与其余 41 个 `.vue` 目录组件的既有写法一致（`ReDialog` 能省略 `/index.vue`
是因为它额外有 `index.ts`；我先写成不带扩展名的形式，typecheck 报 TS2307，已按
既有惯例改回）。
