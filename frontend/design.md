# 多多贝 设计语言

**版本**: v2.3.4
**状态**: 正式版
**主题**: 亮色（暗色模式规划中）
**设计原则**: 温暖 · 精致 · 可信赖 · 涨势 · 专业 · 健壮


## Overview

多多贝 是一套专为个人全资产记账设计的视觉语言，基于现有代码实现提炼而成。不同于传统金融工具的冰冷与严肃，多多贝 追求 **"温暖的极简主义"** ——在保持专业、可靠、冷静的金融工具气质的同时，通过暖色基底、圆润形态和细腻质感，让"管钱"这件事变得从容、安心、有温度。

设计上融合了 Vercel Geist 的系统性与专业度，同时保留了 多多贝 独有的温暖情感与国内金融语境。


## Design Principles

1. **温暖 (Warm)**：暖奶油色背景 + 暖红珊瑚品牌色，中和金融产品的冰冷感
2. **精致 (Refined)**：大量留白 + 柔和阴影 + 大圆角，传递优雅质感
3. **可信赖 (Trustworthy)**：明亮的品牌色 + 极致的清晰友好，降低认知负担
4. **涨势 (Uptrend)**：品牌色 = 涨色 = 暖红，正向情绪强化
5. **专业 (Professional)**：高对比度 + 清晰信息层级 + WCAG AA 合规
6. **健壮 (Robust)**：设计系统需经得起极端场景检验——低对比度环境、宽屏显示器、暗色模式切换、字体降级。所有设计决策以"可落地、可维护、可扩展"为最终标准

### 功能色（金融涨跌 + 系统语义分离）

| 语义 | Token | 色值 | 用途 |
|------|-------|------|------|
| **涨（红）** | `--color-rise` | `#E34F38` | 盈利、上涨、正收益（与品牌色一致） |
| **跌（绿）** | `--color-fall` | `#7BC49A` | 亏损、下跌、负收益（柔和灰绿） |
| **危险（系统）** | `--color-danger-system` | `#D4364A` | 删除、错误、破坏性操作（独立于品牌红） |

> **设计决策**：品牌红（`#E34F38`）代表"涨 = 好事"，独立危险色（`#D4364A`）代表"删除 = 需谨慎"。两者在视觉上有明显区分，避免用户将"删除"与"好事"关联。
>
> **编码红线**：业务代码中**禁止直接调用 `--brand-*` 系列变量**。所有涨跌颜色必须通过 `--color-rise` / `--color-fall` 间接引用，确保暗色模式切换时全站自动同步。

## Spacing

基于 4px 基数，与现有 Tailwind 类名对齐。

### 间距体系

| Token | 值 | Tailwind | 用途 |
|-------|-----|----------|------|
| `--space-1` | 4px | `p-1` / `gap-1` | 图标与文字间距 |
| `--space-2` | 8px | `p-2` / `gap-2` | 紧凑内边距 |
| `--space-3` | 12px | `p-3` / `gap-3` | 小内边距 |
| **`--space-compact`** | **16px** | `p-4` / `gap-4` | **表格/列表/密集数据区** |
| `--space-5` | 20px | `p-5` / `gap-5` | 段落间距 |
| **`--space-standard`** | **24px** | `p-6` / `gap-6` | **卡片默认内边距** |
| **`--space-loose`** | **32px** | `p-8` / `gap-8` | **大卡片/区块间距** |
| `--space-12` | 48px | — | 页面边距（桌面） |
| `--space-16` | 64px | — | 页面边距（宽屏） |

### 使用原则

- **卡片默认**：`--space-standard`（24px）
- **表格/列表/筛选栏**：`--space-compact`（16px）
- **仪表盘/概览卡片**：`--space-loose`（32px）
- **垂直节奏**：正文行高保持宽松（如 16px/24px），提升长列表阅读舒适度
- **紧凑模式下的行高**：列表项高度保持 40px，不缩小，确保金融数据点击热区充足

> **[新增] 数据表格强制紧凑原则**：在"资产总览"、"交易流水"、"自选"等**数据密集型场景**中，必须优先使用 `--space-compact`（16px）作为基准行高。表格行高度强制锁定在 **40px ~ 44px** 之间，严禁使用 `--space-standard`（24px）或 `--space-loose`（32px）作为表格行填充，以确保横向视觉扫视的信息密度。数字列必须强制启用 `tabular-nums` 确保小数点纵向绝对对齐。

## Elevation & Depth

所有阴影带有暖调（棕底），与奶油色背景协调。

| 层级 | Token | 阴影值 | 适用场景 |
|------|-------|--------|----------|
| 微凸起 | `--shadow-raised` | `0 2px 16px rgba(180, 150, 130, 0.06)` | 卡片、列表项 |
| 悬浮 | `--shadow-float` | `0 8px 32px rgba(180, 150, 130, 0.08)` | 下拉菜单、Popover |
| 模态 | `--shadow-modal` | `0 16px 48px rgba(180, 150, 130, 0.12)` | 抽屉、对话框 |

### 暗色模式预留

| Token | 亮色模式 | 暗色模式（规划） |
|-------|----------|------------------|
| `--shadow-raised` | 暖调阴影 | `inset 0 1px 0 rgba(255, 255, 255, 0.04)` |
| `--card-border` | `--border-light` | `1px solid rgba(255, 255, 255, 0.06)` |
| `--glow-brand` | `none` | `0 0 20px rgba(227, 79, 56, 0.2)` |

> **设计决策**：暗色模式下，层次感通过"边框提亮 + 内阴影"实现，而非依赖传统投影（在深色背景上容易呈现为脏污）。

### 暗色模式实现提示

> 品牌色的饱和度降低和涨跌色的提亮，建议通过 CSS 自定义属性（HSL 色值）动态计算，而非硬编码独立色值。具体实现方案将在 `/frontend/design.dark.md` 中详细定义。

### 毛玻璃（Glass）

用于**悬浮浮窗类**元素（记账托盘 QuickFab、回到顶部 el-backtop），营造"半透明底层 + 微高光边框"的轻量悬浮感。**禁止大面积铺底**，仅限全局浮窗。

| Token | 亮色值 | 说明 |
|-------|--------|------|
| `--glass-bg` | `rgba(255, 255, 255, 0.72)` | 玻璃基底 |
| `--glass-bg-hover` | `rgba(255, 255, 255, 0.88)` | 悬停提亮 |
| `--glass-border` | `rgba(255, 255, 255, 0.65)` | 边缘高光 |

> 实现要点（`src/style/index.scss` 的 `.quick-entry-glass`）：
> `background-color: var(--glass-bg)` + `border: 1px solid var(--glass-border)` + `box-shadow: var(--shadow-float)` + `backdrop-filter: blur(12px) saturate(160%)`。
> Token 定义在 `src/style/colors.css`（亮色）与 `src/style/dark.scss`（暗色），**改动 token 值必须双端同步并回归对比度**。
> 使用处：`src/components/QuickEntry/QuickFab.vue`、`src/layout/index.vue`、`src/layout/components/lay-content/index.vue`。

## Focus & Accessibility

所有可交互元素在 `:focus-visible` 状态下必须显示 Focus 环。

```css
--focus-ring: 0 0 0 2px var(--bg-card), 0 0 0 4px var(--brand-700);
```

- 内层环（2px）：与卡片背景色一致，制造干净间隙
- 外层环（4px）：品牌色，指示焦点位置

> 禁止移除 `outline` 而不提供替代视觉指示。所有交互元素需附带 `aria` 标签。

> **自动化测试约束**：所有 CSS 变量（颜色）变更必须通过 axe-core 或 Lighthouse 进行对比度回归测试，确保 WCAG AA 合规。禁止在无自动化验证的情况下修改 `--text-*` 或颜色相关变量。

### Button

| 变体 | 背景 | 文字 | 圆角 | 高度 | 用途 |
|------|------|------|------|------|------|
| 主按钮 | `--brand-700` | 白色 | `--radius-sm` | 40px | 主要操作（保存、确认） |
| 次按钮 | 透明 / `--bg-card` | `--text-primary` | `--radius-sm` | 40px | 次要操作（取消、重置） |
| 文本按钮 | 透明 | `--text-secondary` | `--radius-sm` | 40px | 轻量操作 |
| **涨按钮** | `--color-rise` | 白色 | `--radius-sm` | 40px | 买入 / 盈利操作 |

| **软涨按钮** | `--brand-100` | `--brand-700` | `--brand-400` | 40px | 已选中/候补操作 |
| **软跌按钮** | `#F0F9F2` | `#38A354` | `#D4E8DB` | 40px | 已选中/候补操作 |

> **危险按钮交互补偿**：为弥补 `--color-danger-system: #D4364A` 视觉警示力不足的问题，采用"幽灵按钮 + 悬停填充"模式。

| 状态 | 背景 | 边框 | 文字 |
|------|------|------|------|
| Default | 透明 | `--color-danger-system` 1px | `--color-danger-system` |
| Hover | `--color-danger-system` | 无 | 白色 |
| Active | `--color-danger-system`（+ 半透明叠加层） | 无 | 白色 |

> **软按钮使用原则**：当一个页面需要同时展示多个操作时，主操作使用实心按钮，辅助操作使用软按钮，避免"红绿灯"式的视觉噪音。

> **软按钮反馈**：由于软按钮背景通透，点击时不进行位移（无 `translateY`），而是通过背景色加深（如 `--brand-100` → `--brand-200`）或边框消失来反馈，保持轻量感。

#### 按钮物理反馈

> 主按钮（Primary）在 `:active` 状态下增加 `transform: translateY(1px)`，配合阴影消失，模拟"按下被吸进去"的物理反馈。

```css
.btn-primary:active {
  transform: translateY(1px);
  box-shadow: none;
}
```

> **全站 `el-table` 视觉基线统一维护在 `src/style/el-table.css`**（2026-08 起强制）。
> 此前各页面各自 `:deep(.el-table)` 覆盖主题导致风格分化，现收敛为单一维护点，
> 文件头注释即规则。新增页面表格直接用 `<el-table>` 即可自动继承基线，
> **禁止在页面内 `:deep(.el-table)` 覆盖视觉基线**。

| 属性 | 值 | 说明 |
|------|-----|------|
| 边框 | `--border-light` | 由 `--el-table-border-color` 注入 |
| 表头底色 | `--bg-muted` | 淡灰蓝（本就用于表格条纹） |
| 行 hover | `--bg-soft` | 柔和表面 |
| 表头文字 | `--text-tertiary` | 弱化表头 |
| 正文文字 | `--text-primary` | — |

**页面内可保留**：行内行为样式（如操作列按钮悬停浮现），不涉及视觉基线。

**横向滚动**：表格横向滚动支持浏览器原生 `Shift + 滚轮`（无需任何代码，Element Plus 表格默认支持），**禁止引入拖拽滚动库**（金融表格复制数字场景易误触）。行高统一 44px（`el-table.css` 基线，见上），页面禁止用 `size` / `:row-style` 单独覆盖。

#### 行内图标规范
表格行内状态图标（置顶/关注等）默认 `--text-tertiary`，行 hover 提亮 `--text-secondary`，语义靠 icon 形状区分（禁用多彩硬编码）；hover 浮现按钮统一 opacity 0→1 机制（150ms ease，与 Motion 表一致）。

#### [新增] 行内操作交互规范
依据"克制与冷静"的原则，表格列表中**禁止**每一行永久显示操作按钮（如"删除"、"编辑"）。
- **默认状态**：操作按钮保持 `opacity: 0` 或 `visibility: hidden`。
- **Hover 状态**：仅当鼠标 `Hover` 或触控"长按"触及到**特定行**时，操作按钮通过 `200ms ease-out` 缓动淡入浮现，并提供 `--shadow-raised` 或 `--bg-soft` 的轻量底纹反馈。
- **目的**：最大化降低行内视觉噪音，让用户聚焦于数据，而非操作。

#### [新增] 冻结列与横向滚动规范
表头与左侧锚点列的"视口留驻"是金融表格的专业基石。
1. **固定列（冻结）**：强制要求"基金/股票名称 + 代码"作为首列，宽度固定约 180-220px，**必须由 `el-table` 的 `fixed` 属性进行左侧冻结**，任用户如何横向滑动，始终锚定在屏幕最左侧。
2. **横向滚动**：除固定的名称列外，所有数值列（最新价、涨跌幅、持仓市值等）必须在表格宽度不足时，启用流畅的横向滚动。
3. **滚动条 UI**：全局表格滚动条必须自定义统一风格，厚度 `6px-8px`，颜色使用 `--border-default`（`#E5DDD4`），悬停时稍亮。**必须支持 `Shift + 鼠标滚轮`**（浏览器原生、Element Plus 默认支持，禁用第三方拖拽滚动库）；滚动条 thumb 原生可点按拖拽，配合 `user-select: none` 防止误选中数字。

#### [新增] 空状态与加载态（品牌隐喻共鸣）
为呼应品牌文档 `brand-v1.7.md` 的品牌故事，需在工具端赋予情感。
- **空状态（暂无持仓）**：严禁使用干瘪的文字提示（如"暂无数据"）。必须使用 **珊瑚红 `#E34F38` 单色细线的鹦鹉螺插画**（来自品牌海洋生态插画映射，见 `brand-v1.7.md` §9–§10），配合品牌收尾定调文案："**潮有涨落，壳有深浅。算得清，才无患。**"以此引导用户"添加自选"，完成从品牌营销页到工具端的使用闭环。
- **加载状态**：使用珊瑚红 `#E34F38` 的鹦鹉螺单螺旋辅助图形，配合 6-8 秒 `scale(1) → scale(1.03)` 品牌呼吸动效。

> **资产缺失提示**：上述鹦鹉螺单线插画与单螺旋辅助图形当前在 `brand-v1.7.md` §9–§10 标注为"待开工"，落地前需先在 `logos/` 或图标目录补齐对应 SVG 资产，避免空状态/加载态引用悬空。

### [新增] Filter & Selection（筛选与过滤）

> **核心原则**：投资列表数据通常需要多维交叉筛选，为降低认知负荷，筛选逻辑统一**强制降维到两级**。

1. **两级筛选架构**：
   - **一级筛选（主维度）**：如"资产类型（全部/场内/场外）"或"资产类别（全部/股票/基金）"。使用 **胶囊分段控制器** 平铺在顶部栏（圆角 `--radius-pill`，字体 `--text-label`，选中态实心 `--brand-700`）。
   - **二级筛选（状态/子维度）**：如"持有状态（全部/持仓/观察中/已清仓）"或"自定义分组"。**严禁将此维度放在左侧边栏**。必须将其转化为 **`水平滑动胶囊栏 (Horizontal Scroll Capsules)`**，紧贴在一级筛选栏下方。超出容器宽度时支持触控/鼠标滚轮横向滑动，严禁强制换行挤压表格空间。

2. **去冗余原则**：明确各筛选维度的交集逻辑，**禁止在列表上方同时出现"全部/股票/基金"与"场内/场外"等语义重叠的筛选层**，统一整合进两级筛选架构中。

## Voice & Content

> 文案是设计的一部分，极致清晰和友好是财务工具的核心。

- **标题/按钮/标签**：动词 + 名词：`新建持仓`、`删除账户`、`导入交割单`，禁用 `确定`、`OK`
- **正文/说明**：完整句子：`该操作将删除所有关联交易记录`
- **错误提示**：描述问题 + 给出下一步：`导入失败，文件格式不匹配。请检查 CSV 列头是否包含"交易日期"`
- **成功提示**：直接陈述结果：`持仓已删除`、`导入完成（12 条记录）`
- **进行中**：动词 + 省略号：`导入中…`、`计算中…`
- **空状态**：指向第一个行动：`暂无持仓，点击"新建持仓"开始记录`
- **数字**：阿拉伯数字 + 货币符号（`12 条记录`、`¥3,245.67`）
- **语气**：温暖、直白、不卑不亢。不说「请」，不说「非常」，不说「卓越」
- **涨势语言**：多用「收益」「增长」「积累」，少用「亏损」「风险」

### 数字格式规范

| 规则 | 标准 | 示例 |
|------|------|------|
| 千分位分隔符 | 使用逗号 | `¥12,345.67` |
| 小数点位数 | 金额保留 2 位 | `¥3,245.67` |
| 份额/数量 | 保留 2 位 | `1,234.56 份` |
| 百分比 | 保留 2 位，带 `%` | `+12.34%` |
| 负数 | 使用减号 `-` | `-¥1,234.56` |
| 零值 | 统一格式 | `¥0.00` 或 `0.00%` |
| **超大数值（≥1 亿）** | 默认显示完整数字，可选"缩写模式" | `¥123,456,789.00` → `¥1.23亿` |
| **负数会计模式** | 默认使用减号 `-`，未来可扩展括号模式 | `-¥1,234.56` → `(¥1,234.56)` |

> **实现约束**：缩写模式为全局开关（用户偏好设置），默认关闭，显示完整数字。

### 日期时间格式规范

| 场景 | 格式 | 示例 |
|------|------|------|
| 纯日期 | `YYYY-MM-DD`（短杠） | `2026-08-15` |
| 日期 + 时间 | `YYYY-MM-DD HH:mm`（短杠 + 时分，**不带秒**） | `2026-08-15 12:30` |
| 仅时间 | `HH:mm` | `12:30` |

> **实现约束**：
>
> - 全站日期时间展示统一走 `src/utils/date.ts` 的 `formatDate` / `formatDateTime` / `formatTime` 三个纯函数（等宽数字，本地时区），**禁止**各页面自行 `toLocaleString` / 手拼字符串 / `slice` 截断。
> - 后端 ISO 字符串（带 `T`）展示前必须格式化，禁止原样渲染。
> - 金融场景秒无意义，日期+时间统一不带秒；仅行情类「实时更新」场景可用秒级精度。
> - 「更新时间」类展示位由组件（如 `RealtimeStatusIndicator` / `PageHeaderBar`）内部统一格式化，调用方传入原始时间字符串即可。

## Dark Mode（规划中）

暗色模式将遵循以下方向：

| 维度 | 亮色模式 | 暗色模式（规划） |
|------|----------|------------------|
| 页面背景 | `#FDFBF7`（暖奶油白） | `#1A1816`（深灰） |
| 卡片背景 | `#FFFFFF`（纯白） | `#242120`（稍亮灰） |
| 卡片边框 | `--border-light` | `1px solid rgba(255, 255, 255, 0.06)` |
| 卡片阴影 | `--shadow-raised` | `inset 0 1px 0 rgba(255, 255, 255, 0.04)` |
| 品牌色 | `#E34F38`（暖红珊瑚） | 饱和度降低 20% |
| 涨色（`--color-rise`） | `#E34F38` | `#F06B57`（稍亮） |
| 跌色（`--color-fall`） | `#7BC49A` | `#5DAF85`（稍亮） |
| 主文字 | `#2D2A24`（暖黑） | `rgba(237, 234, 229, 0.92)`（暖灰白，避免光晕） |
| 品牌发光 | `none` | `0 0 20px rgba(227, 79, 56, 0.2)` |

> **核心原则**：
>
> - 非纯黑背景，使用深灰层级
> - 品牌色饱和度降低，避免在暗色背景上"震动"
> - 阴影消失，发光 + 边框提亮 + 内阴影替代
> - 所有涨跌颜色通过 `--color-rise` / `--color-fall` 变量自动切换

> **暗色模式实现提示**：品牌色的饱和度降低和涨跌色的提亮，建议通过 CSS 自定义属性（HSL 色值）动态计算，而非硬编码独立色值。具体实现方案将在 `/frontend/design.dark.md` 中详细定义。


## Do's & Don'ts

**Do:**

- 用暖奶油色背景（`--bg-page: #FDFBF7`）
- 用大圆角（12–16px）和胶囊形状
- 用大量留白让数据呼吸
- 用暖红珊瑚作为品牌色（涨 = 好事）
- 用独立危险色（`#D4364A`）表示删除/错误
- 核心位置（总资产）用 Inter + 字重 600 建立视觉锚点
- 所有金额使用等宽字体 + `tabular-nums`
- 正负符号与数字保持同色（涨红跌绿）
- 图表颜色通过 `getComputedStyle` 动态读取
- 所有可交互元素显示 `:focus-visible` 环
- 保持 WCAG AA 对比度（正文 ≥ 4.5:1）
- 主按钮 `:active` 增加 `translateY(1px)` 物理反馈
- 软按钮点击时**不位移**，仅背景加深或边框消失
- 卡片内分割线使用 `--border-subtle` 降低视觉权重
- **所有 CSS 变量（颜色）变更必须通过 axe-core 或 Lighthouse 进行对比度回归测试**

**Don't:**

- 不使用 Georgia（衬线体）
- 不用冷白色或灰白色作为主背景
- 不用小圆角（<6px）作为卡片圆角
- 不用绿色传递正面情绪（国内语境绿 = 跌）
- 不将危险色（删除）与品牌色（涨）混用
- 不在暗色模式下简单反转亮度
- 不用颜色作为唯一信息载体（涨跌配 `+`/`-` 符号）
- 不直接调用 `--brand-*` 变量，通过 `--color-rise` / `--color-fall` 间接引用
- 不将 `--text-tertiary` 大面积直接置于 `--bg-page` 上

## 数字等宽对齐落地规范（2026-08-15）

> 账户管理页（`views/asset/ledgers/index.vue`）已落地，全站新页面遵循。

- **页面根容器**：业务页根元素统一声明 `font-family: var(--font-ui)` + `font-variant-numeric: tabular-nums`，**禁止硬编码字体栈**（如 `"PingFang SC", "Microsoft YaHei"`），字体继承自动覆盖全页数字。
- **金额/统计数字**：`.metric-value`、指标区、关联负债行等数字容器显式补 `font-variant-numeric: tabular-nums`（与根容器双保险），消除数字宽度抖动与锯齿感。
- **MoneyDisplay 组件**：内部已自带 `tabular-nums` 与等宽数字字体，外层容器无需重复处理，仅需保证不覆盖其字体/字距。

## 提示性 Banner 品牌色规范（2026-08-15）

> 账户管理页「未归置持仓提示」banner 已由危险色改为品牌色，全站提示性 banner 遵循。

- **语义分工**：提示性信息（存在未归置数据、待处理建议）用**品牌色**——`--brand-100` 底 + `--brand-700` 图标/文字；**危险色只留给破坏性操作**（删除、清理、错误）。
- **Token**：背景 `var(--brand-100)`、图标与文字 `var(--brand-700)`，禁止硬编码 hex。
- **例外**：真正的风险警示（如负债率偏高）仍用系统危险色（`--color-danger` + `--color-danger-20`），与提示性 banner 区分开，避免「提示」与「危险」语义混淆。
